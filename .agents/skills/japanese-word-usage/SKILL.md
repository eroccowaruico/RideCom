# 読む人に意味が伝わる日本語を選ぶ

1. [文書と画面文言の検査](../../../docs/policies/文書作成規約.md#日本語の技術文書を検査する)を実行する。登録済みの用法に当たったら、対象の文と前後の見出しを読む。画面ではタイトル、ボタン、読み上げの文を一緒に確認する。
2. 新しく書いた日本語もすべて読む。変更箇所は `python3 scripts/review_wording.py --all-passages` で探せる。コミット後は `--base` に作業開始時のコミットを指定する。辞書にない略し方や直訳でも、読者が対象・動作・結果を補わないと読めない表現は調べる。画面で組み立てる文は値を入れて読み直す。

   動詞は主語と目的語を補って読む。英語から訳したかどうかにかかわらず、同じ言葉が別の操作にも読める箇所を探す。画面のボタンなら押す人の目的を、手順なら実際の操作を、検証記録なら観測できた結果を表す言葉を選ぶ。前後の文や実装で区別できなければ、推測で書き換えず、元の要求や記録を確かめる。
3. 疑わしい語は、その場で表す意味を日常の言葉で説明する。同じ語を使う昔の例と、同じ意味を別の語で書いた例をインターネット上の公開資料から探す。検索に使うのは用語や一般に公表された機能名だけにする。社内資料の文章・識別子・宛先を検索に渡さない。
4. [過去の用例と割合の調べ方](../../../docs/policies/日本語の用例.md)に従う。旧期間は2024年7月31日までとする。採用する言い換えには、できれば2023年末までに同じ読者向けに使われた例を選ぶ。公開日が分かる公的資料や製品の当時のマニュアルを使う。現在の検索順位・推定ヒット数や、このプロジェクト内の出現数から昔の利用率を推定しない。
5. 読者・分野・意味・数える単位をそろえ、前後それぞれの分子と分母を記録する。過去にも同じ意味で同じ割合だった場合は、その場面での元の表現を許容する。古い例が1件だけなら、その用法があったことまで分かる。比較できない場合は未比較と記録し、省略が残る箇所を昔から使われる具体的な表現に直す。原文、正式名称、法令上の用語は参照先や意味を確かめて保つ。
6. 新たに見つけた使い方は、判断理由と資料を上の用例集へ追記する。[共通の用語検査](../../../tools/doc-lint/japanese-usage.mjs)に文脈を区別できる条件を追加する。機械で区別できない用法は、変更箇所を読むときに確認する項目として用例集に残す。違反する文と、同じ語でも適切な文を[検査のテスト](../../../tools/doc-lint/japanese-usage.test.mjs)へ加える。語だけを他の語に一括で置き換えない。
7. 書き直した文を元の要求・操作・測定記録と比べる。誰が送ったか、どこまで届いたか、誰が確認したかを区別する。条件、例外、時点、確かさを保ったうえで同じ検査をやり直す。意味が決まらない場合は[再実装できるかを確認する手順](../rebuild-from-spec/SKILL.md)に従う。
