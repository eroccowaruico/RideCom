# 品質と次の作業の独立評価

各コミットの区切りで、主担当は今回の変更と次に予定する1件を、今回の実装・作業選択に関与していない別のエージェントへ評価依頼する。同じチャット内で読み取り専用の評価を委任する。評価担当は編集・再委任しない。セキュリティ監査の受入は別途行う。

**主担当が渡すもの**　対象の差分を識別する情報、優先用途と依頼者指定の順位、今回の受入結果、次に進める主要機能と品質改善の候補、各候補の利用への効果と所要時間。品質に直接関係しない変更でも、変更範囲と次の候補を示す。共有する情報には常設セキュリティ監査の出力条件を適用する。

**評価担当が確かめること**

1. [準一元的品質](../../../docs/policies/開発方針.md#準一元的品質と検証パターンを増やす時期)では、代表経路、報告済み不具合、変更が影響する既存挙動のどれを守る試験かを確認する。未報告のエッジケースを主要機能より先に増やす案には、具体的な阻害や回帰の根拠を求める。根拠がなければ主要機能を選び、ケース追加を再開する条件を示す。
2. [一元的品質](../../../docs/policies/開発方針.md#品質の種類と通常作業を切り替える基準)では、今回の用途に必要な判定帯、同条件での前後の差、他の品質への影響を確かめる。数値をもう少し良くする案と、今試せる別の主要用途を比較する。追加調整や再測定で変わる判断を説明できなければ、次の指定項目へ進めるよう差し戻す。
3. 最優先の用途が確認できない場合の依頼者への確認、定期作業の完遂、受入に必須の回帰試験を守っているかを照合する。定期作業中の次の1件はその回の残る受入条件から選ぶ。独立した製品作業を並行して始めない。

**判定と再開**　評価担当は「進行可・再選択・根拠不足」のいずれか、根拠、次の1件（依頼完了なら終了）を返す。主担当は対象と判定を既存の作業記録またはコミット本文に短く残す。再選択なら案を直し、根拠不足なら判断に必要な証拠だけを補って再評価を受ける。判定者が利用できない場合を含め、進行可が出るまで次の作業への着手を保留する。監査済みの完了差分は通常どおり小さくコミットして共有できる。評価の記録だけの追加コミットは作らない。
