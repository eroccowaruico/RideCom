# 常設セキュリティ監査

[開発方針の常設監査](../../../docs/policies/開発方針.md#常設のセキュリティ監査)を着手・再開時に適用する。最初のファイル閲覧・ツール実行より前に、今回扱う情報、保存先・出力先と必要な検証を決める。変更単位のコミット・外部送信前に次の監査を実行する。調査だけの作業でも、得た情報を共有する前に対象の出口を確認する。

## ローカルで証拠を作る

- 対象の入口から、アプリ・Worker・CI・監査自身の保存、ログ、エラー、成果物、外部送信まで、変更が届く出口をたどる。実データ、環境変数一覧、Keychain、資格ストア、本番のログやダンプをモデルに読ませることは禁止する。ファイル名・絶対パス・URL・コマンド引数・例外文にも個人情報や秘密が入り得る。開発用のチャット、端末出力、テスト失敗、Git・通知・引継ぎも出力先に含める。
- 許可されたローカル環境で、信頼済みの検査コードと架空の値を使う。正常時・失敗時の出力をローカルの判定器へ直接渡し、固定語の結果だけを取り出す。値の一部・マスク・ハッシュ、差分、原文、ファイル名、自由記述を監査モデルに渡すことは禁止する。対象の変更が検査器やテストを差し替える場合は信頼済みの別 worktree の検査器を使い、新版は資格なしの隔離環境で先に検証する。
- コミット対象をステージした後、対象 worktree のルートを現在地として `python3 -I -S <信頼済みスキルのディレクトリ>/scripts/check_staged.py` を実行する。[検査器](scripts/check_staged.py)は index の追加・変更後の blob と変更パスをローカルで検査する。終了 0 の `checked` は既知パターンの検出なし、`empty` は差分なし。終了 1 の `review` は候補あり、終了 2 の `unavailable`、異常出力、タイムアウトは検査不能とする。候補は `private-key`、`credential`、`personal-data`、`sensitive-file`、`opaque` の固定語だけ。バイナリ・リンク・2 MiB を超える blob 等は `opaque` とし、秘密鍵等の保管用ファイルは内容を開かずに分類する。
- 標準 index を監査した同じ内容でコミットする。別 index・パス指定コミット・自動ステージで内容が変わる場合は、その対象を検証してから共有する。未ステージの作業、過去のコミット、アーカイブ・ログ等の別の送信物は個別の対象とする。送信対象に含まれる各コミット・成果物に対応する証拠を用意する。Git のメッセージ・作者・コミッターも共有されるため、送信前にローカルで公開範囲に合う内容・役割名義であることを照合する。検査器は未知の資格形式、人名、住所、位置情報などの完全な検出器ではない。これらは入力と出口の対応、実データの排除、架空の識別値を使う出力試験で確認する。候補を修正できる場合はローカルで修正・再検査する。既知の誤検出や不透明な形式はその対象に限って独立した形式検査・出口試験で解消し、一括除外しない。

## 人の定例作業が必要になる経路を監査する

[資格の定期更新と安全性](../architecture-refinement/SKILL.md#定期更新と安全性の確認)と[ログ記録規約](../../../docs/policies/ログ記録規約.md#記録禁止)を使う。人が秘密を閲覧・転記・配布する工程を探し、初回設定から通常利用、期限越え、失効、障害復旧までを確認する。

| 判定項目 | 必要な証拠 |
|---|---|
| `egress` | 架空の個人情報・資格・鍵材料を使い、成功・失敗時とも許可した出力項目だけが届く。診断や成果物にも生の識別子・音声・招待情報が残らない |
| `access` | 発行・保存・利用の主体を分離し、最小権限と環境分離を維持する。権限外の利用を拒否する |
| `renewal` | 発行元の資格までたどり、初期設定後に人が何もせず期限を越えても利用が継続する。提供元管理または必要時の短命資格発行をローカルの時計・代替 provider で確かめる |
| `revocation` | 期限切れ・失効・取消後に旧資格を拒否する。更新失敗時は安全に停止し、限定的な再試行・復旧後も権限を保つ |
| `operations` | 通常の検査・更新・復旧を無人で繰り返せる。失敗検知と通知に秘密が入らず、再実行で権限・資格・副作用が増えない |

## 最新 Astra へ判定を依頼する

主担当が実行環境のモデル一覧から Astra 系列の最新版を選ぶ。実行環境が同系列の latest エイリアスを提供すればそれを使い、それ以外は利用可能な正式モデル ID の版を比較して最新を明示指定する。監査ごとに新規の独立した担当を起動する。Codex の `spawn_agent` では `fork_turns="none"` と選択した `model` を指定し、ツール使用・ファイル閲覧・再委任をさせず、下記の固定語と判定規則だけを渡す。作業履歴や利用者の依頼原文を継承させない。Astra の最新版・独立した入力境界・実行結果のいずれかを確認できない場合は `incomplete` とする。

| 引き渡す項目 | 許可する値 |
|---|---|
| 対象 | `staged-change` / `observation`（読み取りや Git 以外の成果物） |
| 検査状態 | `checked` / `empty` / `review` / `unavailable` / `not-applicable`（Git の変更を扱わない作業） |
| 検出分類 | 検査器が定義する固定語の集合 |
| 検出候補の別検証 | `pass` / `fail` / `unknown` / `na` |
| 上表の各判定項目 | `pass` / `fail` / `unknown` / `na` |

適用の有無は変更前に対象のデータフローから決める。該当項目で証拠が欠ければ `unknown` とする。`na` は対象への経路がない場合に限る。監査自身の変更では `egress` と `operations` を必ず検証する。

Astra は判定と該当項目の固定語だけを返す。失敗または未解消の検出候補は `hold`、検査不能・必要な証拠の不足は `incomplete`、適用項目と全候補の検証が揃えば `clear` とする。`staged-change` で `empty` / `not-applicable` の場合も `incomplete`。主担当は指定モデルの実行結果、検査状態、適用項目と根拠を照合する。想定外の応答は転記せず `incomplete`。変更・ステージし直し・成果物の再生成後は該当する検証と判定をやり直す。

記録は実行モデルの正式 ID、対象の種別、判定項目・成否、残る対応に限る。`hold` / `incomplete` では該当するコミット・送信・配布を保留し、権限内の修正・再検証を自動で進める。人に依頼するのは所有者だけができる初回同意、失効・本番切替などの権限判断、既存手段で解消できない例外に限る。秘密値を人に尋ねたり貼り付けさせたりすることは禁止する。
