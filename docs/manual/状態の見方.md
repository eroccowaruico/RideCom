# 通話・音声・接続状態の見方

## 目的

本書は、RideCom App の画面上でユーザーが確認できる状態と、その読み方だけを定義する。

本書では画面に表示される状態のみを扱う。

## 対象画面

| 画面 | 確認すること |
|---|---|
| Call | 通話先、接続状態、音声入出力、参加者状態 |
| Users / Groups | 保存先、招待・受諾通知の状態、詳細表示での管理 |
| Diagnostics | 通話、package runtime report、送受信、codec、再生、認証、経路の要約状態 |
| Settings | 入出力デバイス、音声設定、Audio Check の状態 |

画面項目の詳細な配置、ラベル、表示条件は `docs/spec/App/UI/画面項目定義.md` から参照する画面別文書を正とする。

## 音声経路による違い

DiagnosticsのOverviewで送受信の状態を確認し、LocalとInternetの内訳はNetworkで見る。PCM meter・effect chain・peer音量・TX/RX pipelineは両経路のpacket audioを対象とする。Internet Serviceのチェックは設定と認証を確認する。

## Call 画面で確認する状態

| 表示 | 読み方 |
|---|---|
| グループ名 | 現在表示している通話対象グループ |
| 接続状態 | 未接続、接続準備中、接続済み、通話可能、再接続中、失敗を確認する |
| 経路表示 | Local / Internet / Offline など、現在使っている、または試行している経路 |
| Connect / Disconnect | 接続開始できる状態か、既に接続中で切断操作になる状態かを確認する |
| Invite | 標準表示で招待URLを共有できる状態かを確認する。詳細表示の招待はUsers / Groupsの対象詳細から確認する |
| 入力状態 | 自分のマイクが Unmuted か Muted かを確認する |
| 入力メーター | 自分の声がアプリへ入っているかを確認する |
| 出力状態 | 受信音声のマスター音量と出力ミュートを確認する |
| 他音声ダック状態 | 設定 ON と実際の発動中を区別して確認する |
| 参加者カード | 相手ごとの接続、認証、入力レベル、出力音量を確認する |
| エラー表示 | マイク権限、音声起動、入出力デバイス変更などの失敗理由を確認する |

## Usersで確認する招待状態

一覧は保存した人を1行ずつ表示する。名前だけを保存した相手は「未登録」で、タップすると共有できる詳細が開く。コピーや共有取消では未登録のまま。相手の受諾を確認すると同じ人が登録済みになり、行から通話を開始できる。返信の未着は同じ相手の詳細内に残し、別の人物行にしない。AdvancedはSavedUserと送受信の記録の値を同じ詳細で確認する。

## Diagnostics 画面で確認する状態

詳細表示のDiagnosticsでは、OverviewのTX・RXの判定から、確認が必要な段と理由を読む。Pipelineの矢印は処理順、色と記号は段ごとの状態を示す。

| 表示 | 読み方 |
|---|---|
| Live TX Pipeline | Session → Input → VAD → TX Bus → Codec → RTC。VADを開くと判定に使った音、RTCを開くと経路別の最後の送信受付を確認できる |
| Live RX Pipeline | RTC RX → Decode → Peer Buses → Mix Down → RX Master → Master FX → Output。受信、復号、実出力を段ごとに確認する |
| TX Bus | 送信側に適用される音声効果と各効果の状態を確認する |
| RXのParticipants | 相手ごとの送信側の設定、受信経路、受信codec、自分側の音量・音声効果・Jitter bufferを確認する。Mix Downでは出力へ進む枝が合流する |
| Network | Local・Internetの計測値と、最後に確認した相手ごとの経路を読む |
| Call | 接続状態、media 状態、選択 group を確認する |
| Invite | 招待済み、招待可能、招待情報なしを確認する |
| Remote Runtime Status | `RTCRuntimeStatusTransport` で受け取った通信相手の接続、route、media、codec、package report を必要に応じて確認する |

RXでは、`Last receipt`がAppでの音声受信、`Last PCM`が復号、`Last audible PCM`がnative出力で有声PCMを観測した時刻を示す。各段は2秒を超えて次の観測がないとWaitingになり、最後の経過秒は残る。`Render not measured`では再生予約までを確認できる。相手の受信や出力は、相手側のRXで確認する。

## Settings 画面で確認する状態

| 表示 | 読み方 |
|---|---|
| Communication | RTC へ渡す有効 route のユーザー希望を確認する。active / available route は Diagnostics を正とする |
| Audio Session | Mode、Use Speaker、Echo Cancellation、Duck Other Audio の組み合わせを確認する |
| 入力デバイス | どの入力を使う設定になっているかを確認する |
| 出力デバイス | どの出力を使う設定になっているかを確認する |
| Voice Isolation Effect | SoundIsolation effect の有効/無効を確認する |
| Transmit Codec | 送信 codec 希望と bitrate を確認する |
| Voice Activity | 発話判定の感度 preset を確認する |
| Audio Check | マイク録音とスピーカー再生の確認状態を確認する |
| Reset | App の画面設定を初期値へ戻す操作を確認する |

設定値を定める資料は `docs/spec/App/Configuration/設定値一覧.md` とする。

## Audio Check で確認する状態

| 状態 | 読み方 |
|---|---|
| recording | マイク入力を取得している |
| playing | 録音した音声を再生している |
| completed | 入力と出力の確認が完了した |
| failed | 権限、入力なし、再生失敗などにより確認できなかった |

Audio Check は通話中の品質評価ではなく、端末の入力と出力が使えるかを画面上で確認する機能とする。

## 状態確認時の考え方

| 状況 | 確認する画面 |
|---|---|
| 相手につながらない | Call の接続状態、Diagnostics の Connection / Authentication |
| 自分の声が届かない | Call の入力状態と入力メーター、Diagnostics の Live TX Pipeline |
| 相手の声が聞こえない | Callの参加者入力と出力状態、DiagnosticsのOverview → RXとNetwork |
| 音が小さい | Call のマスター出力音量、参加者ごとの出力音量 |
| マイクが使えない | Call のエラー表示、Settings の入力デバイス、Diagnostics の Live TX Pipeline、Audio Check |
| 招待できない | 新しい相手はUsersのInvitationsと案内で確認する。登録済みの相手・グループは標準表示のCallか、詳細表示のUsers / Groupsで対象の詳細を開く。DiagnosticsのInvite Summaryでも確認できる |

本書では、画面で何を確認するかだけを扱う。

## Networkの読み方

DiagnosticsのNetworkで通信の実測値を確認できる。RTTは自分のICE接続までの往復時間で、相手の声が届くまでの遅延ではない。send queueは送信待ちbyte数。Event dropsは端末内で期限や上限を超えたイベントの数で、回線のpacket lossとは異なる。

Loss（%）とJitter（ms）は別々の項目。値が取得できなければ `Not measured` と表示する。レポートが15秒を超えると `Updated` に `Stale` が付く。Direct group path / Relayedは最後に認証済みのデータを受信した経路を示す。
