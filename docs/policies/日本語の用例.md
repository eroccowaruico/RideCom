# 日本語の用例

技術文書の言葉を選ぶときは、読者が何を見て、何を判断するのかを確かめる。公開時期が分かる日本語資料を2024年8月1日の前後に分ける。古い資料に用例が1つあれば、その意味で当時使われていたことが分かる。どの程度使われていたかを判断するには、同じ意味を別の言葉で表した例も数える必要がある。

## 同じ意味の候補から表記を選ぶ

2024年7月31日までに、同じ場面を同じ読者に説明した資料を比べる。先に意味・候補・資料の選び方・数える単位を決める。同じ資料の転載や改訂で引き継いだ文章は一度だけ数える。ほかの表記や併記も記録し、調べた対象全体の半数を超えた表記をその用途に採用する。最近の資料での増減は別に記録する。

同数、過半数なし、比較に使える資料が乏しい場合は「判断保留」とし、何が足りないかを書く。正式名称、原文の引用、コードの識別子は元の資料で照合する。一般向け画面で色を示す場面と、開発者が手法の名前を説明する場面は別に数える。

同じ書式・文章の再掲や少数の用例から、分野全体の使用率を推定しない。表記の採否には、分母・分子・時期と、調べた範囲で判断できないことも添える。採用した表記と典拠は[日本語の用例調査](../development/history/日本語の用例調査.md)に残す。

## 読者が見分ける内容

表示色を伝えるときは「赤」「緑」、試験の報告では「失敗」「成功」を使う。

- 対象と時期や番号が分かるか。アプリの提供先を表す場合、たとえば「iPhone用アプリ」と書ける。
- 色の表示を検査する場合は「成功すると緑色で表示する」と書く。検証の報告では「通話のテストに成功した」のように対象と結果を示す。
- テストの失敗を報告する場合、期待した動作と観察した結果を記す。
- 通知や音声を扱うときは、観察できた段階に応じて「サーバーが通知を受け付けた」「端末が音声を受信した」と書き分ける。
- 何をどこで更新し、どこに複製するのかが分かるか。開発者に読む文書を指定する場面では、文書名と調べられる内容を示す。
- 誰に判断する権限があり、どの手続に基づくか。作業の順序を決める場合は、決めた人と理由を書く。

## 技術的な操作を表す動詞

同じ英語の動詞でも、テストなら「実行する」、アプリなら「起動する」、既に起動したプレーヤーなら「再生を始める」と書き分ける。手順では開始する操作を、結果の報告では開始・終了・合否のうち実際に確かめた事実を書く。道を走る人や車の動作は、そのまま表せる。

| 読者が見分けたいこと | 書き分ける内容 |
|---|---|
| 処理をいつ、何回行うか | 初回の実行、失敗後の再実行、決まった間隔での繰り返し |
| どの処理をどこに依頼するか | 関数を呼び出す、サーバーに要求を送る、相手の応答を受け取る |
| 誰に失敗が伝わるか | エラーを記録する、呼び出し元に伝える、画面に理由を表示する |

未登録の表現でも、別の担当者が同じ操作を選べるかを確かめる。複数の操作に読めるときは、観測記録や元の指示で意味を確かめてから、同じ使い方が文書や画面のほかの箇所にも残っていないかを調べる。
