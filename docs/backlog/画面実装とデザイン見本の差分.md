# 画面実装とデザイン見本の差分

## 指示と背景

2026-11-06の利用者指示「細かい違いもバックログに親子関係を維持して追加」「他の画面も実装とHTMLの差を総点検」「しっかり差分を洗い出さないとHTML通りの実装にならない。監督するのもデザイナーの責務」により、実装の画面とHTML見本の差を画面ごとに洗い出した。

**主分類** デザイン。**関連分類** 機能・改善。全体の順位は[バックログの着手順](README.md#着手順)。残る画面差分は機能への依存、仕様・見本との不一致、デザイン判断の単位で扱う。

本書の構造は「画面（親）→ 画面の部分（子）→ 個々の差（表の行）」とする。1つの差は1行にし、同じ差を別の場所に重ねて書かない。複数の画面にまたがる差は[全画面に共通](#全画面に共通)に置き、各画面からは参照だけにする。機能の詳細と完了条件は該当課題を参照し、ここでは画面に現れる差を扱う。

### 進め方

影響する画面と状態を特定し、同じ状態でMarkdownの定義、HTML見本、Appの画面仕様、実装を照合する。デザインの判断が必要な場合は定義と見本を先に揃える。実装の単位ごとに、対象端末と文字サイズ・外観の条件で確認し、完了した差を外して[検証履歴](../validation/history/画面デザインと録音操作の整理.md)へ結果を残す。実装済みで検証を待つ項目は[画面デザインの実環境受入](../validation/未確認事項.md#画面デザインの実環境受入)で追う。[初回の照合と撮影条件](../validation/history/画面とデザイン見本の照合.md)

## 機能への依存とデザイン判断

- [招待と削除の同期](未実装課題.md#招待と削除の同期)の実装と一緒に、[ユーザーの削除](#一覧の構成)、[グループの削除・退出](#グループの一覧)、[メンバーを外す確認](#メンバー)を揃える。
- [通知の残り](未実装課題.md#通知の残り)の実装と一緒に、[未接続のメンバーの呼び出し](#メンバー)を揃える。
- 単独で直せる差は[Advanced通話の表記](#call)。[設定のグループ間隔](#主画面)はデザイン判断待ち。
- Diagnosticsは、処理の段と流れ、分岐・合流、停止位置とその理由を画面で追えることを優先する。無線通話での状態と実処理の照合は[画面デザインの実環境受入](../validation/未確認事項.md#画面デザインの実環境受入)で行う。

旧着手順と確認済みの記録は[整理前の履歴](../development/history/バックログの優先順位と進捗の記録.md#画面差分の整理前の記録)に保持する。
