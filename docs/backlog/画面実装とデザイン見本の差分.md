## 全画面に共通

### Standardとダイアログの平易な文言と継続検査

既存の画面・文書ですでに意味を失った表現の全体修正と、異なるモデルによる最低3回のレビューは[意味の全体修復](未実装課題.md#画面と文書全体の意味が痩せた表現を修復する)で管理する。本課題は継続して混入を防ぐ検査の入口と運用を担い、修復結果を再利用する。

**要求の根拠:** [利用者向けの平易な日本語と英語](../requirements/製品要求.md#利用者向けの平易な日本語と英語)、[文言の継続検査](../policies/開発方針.md#利用者向け文言の意味と平易さを継続検査する)。

**主分類:** デザイン。2026-11-21の利用者指摘。「試行」等の専門語やAIが省略・圧縮した、意味やニュアンスが伝わらない語を利用者向けUIへ持ち込まない仕組みを作る。変更したカタログ・画面コード・設計見本から候補を拾う検査と、[意味を読み直す手順](../policies/文書作成規約.md#次の読者が同じ意味に読めるか確かめる)を追加した。既存の全画面の棚卸し、個々の文言修正と表示確認が残る。

### Standardのコントロールとピクトグラムによる操作性の照合

2026-11-19の[製品要求](../requirements/製品要求.md#standardの操作性の受入)に基づくデザイン点検。説明文より明確なコントロール・SF Symbols等のピクトグラムで操作が伝わり、グローブでも狙いどおりに誤操作なく使えるか、Standardの各画面を照合する。必要なラベル・状態・VoiceOverを残し、記号だけの分かりにくさへ置き換えない。音量スライダーの幅、追加・招待の入口、削除・切断など既存課題と一体で差分を判断し、修正が必要な箇所は機能・デザイン課題へ引き継ぐ。

Build 1630の縦画面で、接続待ちからミュート・切断、音量の操作、個人・グループ招待の保存と共有を[実画面と見本で照合した](../validation/history/画面デザインと録音操作の整理.md#standardの待機と個人グループ招待を実画面に揃える)。次は横画面と大きな文字で主要操作へ届くかを確認する。共通スワイプの設定・削除の表示条件と、削除前の確認は[Simulator検証の記録](../validation/history/画面デザインと録音操作の整理.md#一覧の削除可否を保存の状態と揃える)を参照する。グローブ、VoiceOver、Macの右クリックは[画面デザインの実環境受入](../validation/未確認事項.md#画面デザインの実環境受入)で確認する。

### 現在の雰囲気を保った明暗モードのコントラスト調整

2026-11-18の利用者要望。ダークモードは画面項目と背景のコントラストが近く見づらいため、大きく変えずに見分けやすくする。ノーマル（ライト）モードも、項目と背景にほんの少しだけコントラスト差を付けたい。両方とも現在の配色・質感・雰囲気を損なわない程度の控えめな調整にする。

行・カード・入力欄・操作項目などの面と背景の境界を実画面で確認し、明度差、標準の区切り、必要最小限の境界表現等から適切な手段を比較する。強い枠線や影の一律追加、大幅な色変更・再デザインを前提にしない。ダークは見づらさの解消を優先し、ライトはさらに控えめな差にとどめる。文字・アイコンの読みやすさ、選択・無効・危険操作など既存の状態表現も保つ。

デザイナーには同じ画面の変更前後を明暗両方で示し、Standard・Advanced、一覧・設定・通話の代表的な画面で視認性と現在の雰囲気の両立を判断してもらう。OS標準の素材と[デザインシステム](../design/デザインシステム.md)との整合、文字サイズ・アクセシビリティ設定での見え方も確認する。具体的な配色値と適用範囲は実画面の比較で決め、デザイン定義・HTML見本・画面仕様・実装を揃える。

## Advanced

### 診断のオーバービューを廃止してTXから開く

**最重要。** Advancedの診断からオーバービュー画面とタブを取り除く。診断を開くと最初にTXタブを表示する。

着手時にオーバービューの表示項目を一覧にする。他のタブで見られない情報は、対象に合う既存のタブへ移す。完了時はオーバービューがなく、TXから開き、移した項目をすべて移動先で確認できることを確かめる。[TXとRXの診断を見直す課題](未実装課題.md#advancedで送受信を診断できるように戻す)と表示項目を照合する。

### 診断の処理順と入れ子をデザインシステムに定義する

2026-11-26の依頼。[デザインシステム](../design/デザインシステム.md)に、AdvancedのTX・RXで共通に使う表示枠と配置の規則を定義する。[製品要求の音声処理順と階層](../requirements/製品要求.md#音質選択と音声設定の体験)を基準とし、[送受信診断の修正](未実装課題.md#advancedで送受信を診断できるように戻す)と照合する。

| 対象 | 完了条件 |
|---|---|
| 表示枠と親子関係 | 各処理段を同じ形式のオブジェクトとして示す。子の枠は親の枠の内側に置く。TX Busの中と、RXの受信ユーザーごとの中も同じ形で示す。処理段を省かず、実際の順序、分岐先、合流先が追えること。TXでは声の分離がVADより前にあることも照合する |
| iPhoneの配置 | iPhoneでは向きや画面幅に関係なく、すべての処理段を上から下へ縦に積む。親の中での処理順も縦に示す |
| 大きな横画面の配置 | iPadOSやmacOSの十分に広い横画面では、処理順・分岐・合流と親子関係を追える場合に横並びを選べる。iPadOSでは縦積みと横並びの見本を比較し、使える幅と流れの見え方からデザインで採否を決める。文字、番号、矢印に頼らず、枠の形・位置・間隔・入れ子といったオブジェクトの表現だけで順序が分かること。横並びに必要な幅を取れない場合や、流れを追えない場合は縦に積む |
| 製品要求との照合 | 現行の製品要求ではTXとRXを上から下に並べる。横並びを採用する場合は、今回の依頼で許された条件に沿って製品要求の適用範囲をそろえてから反映する。どちらの配置でも全段と親子関係、各段の状態表示を保つ |
| 見本の確認 | TXと複数の相手がいるRXの見本を用意する。iPhoneの縦横、iPadの広い横画面と分割表示、Macの広い画面と狭い画面で照合する。横並びは順序を示す文字や矢印を加えずに、同じ順序と分岐・合流が読み取れることを確かめる |

### Advanced設定の呼び出し通知の必要性と説明

2026-11-20の利用者報告。「呼び出しの通知」の意味が分からないため、項目の必要性から検討し、残す場合は名称・表示内容・必要な説明で分かりやすくする。今回はバックログへの記録のみで、実装変更・実画面受入は未実施。

現行は[Settings仕様](../spec/App/UI/Settings.md)の`AdvancedCallNotificationStatusSection`で、通知許可・受信状態・処理中・取消待ち等を読取り表示し、表示時に更新する。OSの通知設定や通話先への呼出し操作そのものではない。利用者が設定を変更する項目か、診断状態を確認する項目かが読み取れるかを、実画面・現行処理と照合する。

| 判断すること | 受入条件 |
|---|---|
| 必要性・配置 | 各表示が何の確認・トラブルシュートに必要かを特定する。必要ならSettingsに残すかDiagnosticsへ置くかを判断し、不要・重複の項目は整理する。必要な診断情報を理由なく失わない |
| 名称と状態の意味 | 通知の送信／受信、OS許可とサービス側の登録、処理中と失敗・取消待ち等を混同しない表示にする。Advancedとして実装との対応を保ち、値だけを並べて目的が分からない状態を解消する |
| 説明と次の行動 | 必要に応じ、ほかの設定と整合する説明を付ける。何を表し、どの操作に関係し、問題時にどこを確認するかを示す。操作できない状態表示をON／OFF設定に見せない |

通知の操作設定はOSに任せ、Standardへ通知Sectionやアプリ内の相手別許可スイッチを増やさない既存要求を維持する。保持・移動・削除の判断と理由を記録し、採用した構成を見本・現行仕様・実画面で照合する。表示変更が機能の変更を要する場合は、必要な差分を機能課題へ引き継ぐ。

### 両設定画面のログイン表示とアカウント操作の配置

2026-11-20の利用者要求。Standard・Advancedのどちらの設定画面も、表示できる時点でログイン済みなので、重複する「ログイン済み」表示は不要として外す。ログアウトとアカウント削除は、両方の設定画面の最下部へ移す。上部に常時置く理由はなく、通常の設定操作から先に見つかるよう並べる。今回はバックログへの記録のみで、画面変更・受入は未実施。

削除・ログアウトの配置だけを変更し、認証要件やアカウントの確認・処理中／失敗の表示、削除の確認・復旧手順を失わない。利用者を識別するための本人名など、単なる「ログイン済み」とは別の必要な情報を一律削除しない。リセット等のほかの設定より後にアカウント操作をまとめ、通常操作と破壊的操作の境界を分かりやすくする。

StandardとAdvancedの実画面で受け入れを判断する。上部に不要なログイン状態が表示されず、最下部からログアウトとアカウント削除を操作できることを確認する。文字サイズや画面幅を変えた場合と、VoiceOverを使う場合も到達できることを確かめる。既存の確認・取消・失敗時の回復と、実行対象のアカウントの一致を保つ。表示の責務はモード別に持ち、共通の認証・削除処理は複製しない。実装と同じ変更で画面仕様・見本・マニュアルを更新する。
