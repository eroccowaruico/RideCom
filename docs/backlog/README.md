# バックログ

これから作るもの・直すもの・判断するものの入口。今着手できる作業は[着手順](#着手順)、依存先や再開条件がある課題は[判断や再開を待つもの](#判断や再開を待つもの)を参照する。受入の条件と結果は検証文書を参照する。

## 管理のしかた

| 文書 | 置くもの | 置かないもの |
|---|---|---|
| 本書 | 全課題の順位・状態・次の一手を1行ずつ | 課題の詳細（リンク先に置く） |
| [未実装課題](未実装課題.md) | 採用済みで残っている作業。1見出しが1課題で、残る作業・完了条件・決定済みの条件を持つ | 実装済みの経緯、未採用の案 |
| [改善候補](改善候補.md) | 未採用の案と判断待ちの事項。採用・再開の条件を持つ | 採用して着手する作業 |
| [画面実装とデザイン見本の差分](画面実装とデザイン見本の差分.md) | 残るデザイン判断と実画面の差。画面 → 部分 → 個々の差の階層 | 機能の契約（未実装課題に置く） |
| [利用権とデータ保持の設計](利用権とデータ保持の設計.md)、[機能拡張の実装前整理](機能拡張の実装前整理.md) | 実装前に決めた条件と調査結果の設計記録。課題から参照する | 作業の一覧・順位（本書と未実装課題に置く） |

| 場面 | 行うこと |
|---|---|
| 課題の単位 | 1課題は、利用者が目的を達成できる一連の操作、または1つの不具合とする。部品・API・テスト件数の増加だけを課題の完了としない |
| 課題を足す | 改善・機能は未実装課題へ、デザインは画面差分へ見出しを足す。見出しごとに着手順か判断・再開待ちのどちらかへ1行足す。採用から検討する案は改善候補へ置く |
| 課題が進んだ | 終わった作業を課題から外し、残る作業だけを残す。実態は[仕様](../spec/)へ、確認の結果は[検証の履歴](../validation/history/)へ、実機・実サービスの確認待ちは[未確認事項](../validation/未確認事項.md)へ置く。「済」を付けて残さない |
| 課題が終わった | 見出しと本書の行を外す。順位が変わるなら着手順を並べ直す |
| 順位を変える | 利用者が明示した順、コア体験の阻害・デグレ、重大な不確実性、依存関係と利用者価値で比べ、本書の表だけを直す |

分類（改善・デザイン・機能）と規約の正本は[文書作成規約](../policies/文書作成規約.md#バックログの分類と全体優先順位)、デザイナーへの引継ぎ条件は[開発方針](../policies/開発方針.md#機能実装とデザイン判断の引継ぎ)。2026-11-17の整理で外した完了済みの経緯は[旧未実装課題の完了済み経緯](../development/history/旧未実装課題の完了済み経緯.md)に原文を保持する。

文書検査で、未実装課題（第2レベルの見出し）と画面差分（第3レベルの見出し）が一覧から1回ずつ参照されることを確認する。両表の分類・状態・次の行動も検査する。

## 次に行う受入

招待は、利用者が指定した順で[新しい相手へのグループ招待](../validation/未確認事項.md#新規相手招待の実環境受入)、次に[登録済みの相手へのグループ自動配送](../validation/未確認事項.md#登録済み相手へのグループ自動配送の実環境受入)を実環境で受け入れる。[実環境の設定と受入順](../development/Cloudflare試用手順.md#利用者が行うapplecloudflareの設定と受入順)

実機を使える区切りでは、[ロック後の通話](../validation/未確認事項.md#ロック後の相手待ちからの通話成立)の発話と、同じ試験中の[Diagnosticsの処理順・分岐・状態](../validation/未確認事項.md#画面デザインの実環境受入)を照合する。

## 着手順

上から着手可能な最小の作業を選ぶ。招待の残りを優先し、同じ重要度では次の区切りで確認できる効果と所要時間を比べる。[ビルド番号に応じた見直し](../policies/開発方針.md#ビルド番号で決まる定期作業)を適用する。過去の判断・検証の推移は[バックログの履歴](../development/history/バックログの優先順位と進捗の記録.md)を参照する。

| 課題 | 主分類 | 状態・依存 | 次の一手と優先理由 |
|---|---|---|---|
| [招待と削除の同期](未実装課題.md#招待と削除の同期) | 機能 | 既知端末と個人招待で確認した追加端末への配送は実装済み。未知端末の確認と受領後の除外が残る | 手動の個人招待を交換する前に、追加端末の署名と既存の相手・配送許可を結び付けられる経路を確かめる |
| [音声の途切れと遅延](未実装課題.md#音声の途切れと遅延) | 改善 | 既定AACの欠落0と125msの同時達成が残る。遅着からの再基準化は保存PCMで再現済み | 送信の遅れが大きい入力側を、native収録・録音バッファ・workerの取出しに分ける |
| [APもセルラーもない場所からの近距離通話を実証する](未実装課題.md#apもセルラーもない場所からの近距離通話を実証する) | 改善 | 保存済み状態からの製品App回帰が不足。実無線は回帰用意後に受入 | 圏外の山中でも開始できるよう、Internet無効・応答なしの両方で保存済み状態から起動し、双方向音声を確認する |
| [受信側の声の分離をONにすると音声が途切れる](未実装課題.md#build-1222で受信側の声の分離をonにすると音声が途切れる) | 改善 | 継続的な減衰は修復。切替時の無音・再生時刻のずれが残る | 相手別と全体の切替を、同じ通話で出力波形と聞こえ方まで比較する |
| [Standardの主要操作とピクトグラム](画面実装とデザイン見本の差分.md#standardのコントロールとピクトグラムによる操作性の照合) | デザイン | 製品要求あり。音量の幅と保持は修正済み、共通操作の総点検が残る | グローブを着けても通話・招待・削除を誤操作しにくいか、実画面と見本を照合する |
| [Advanced通話の表記](画面実装とデザイン見本の差分.md#advanced通話の表記) | デザイン | 日本語環境の実画面で混在を確認 | 入力・出力・個別通話の表記を揃え、英日とStandard切替を確認する |
| [通知の残り](未実装課題.md#通知の残り) | 機能 | 通常APNsでの通知拡張と選択呼び出しが残る。背景の実APNs試験は鍵・署名が必要 | 未接続の登録済みメンバーが正しいグループを開けるよう、宛先認可から通知タップまでの経路を検証する |
| [個別通話の鍵を全経路で一致させる](未実装課題.md#個別通話の鍵を全経路で一致させる) | 機能 | 個人登録を兼ねる招待に対応。通常グループのみ・鍵競合・複数端末が残る | 相手との通話を始められるよう、通常グループの秘密から独立して個別通話の鍵を揃える |
| [購入と利用権の公開準備](未実装課題.md#購入と利用権の公開準備) | 機能 | 商品設定と価格待ち。週券のStoreKit試験に残りあり | 公開判断のために週券fixtureを片付け、家族共有を加味して再見積もりする |
| [アカウント削除のサービス範囲と別端末への反映](未実装課題.md#アカウント削除のサービス範囲と別端末への反映) | 機能 | 端末内とserverに削除処理あり。公開サービスの範囲は未決 | 同じ保存領域で既に稼働中の別sessionが削除を受け取る経路を先に絞る。別サービスへの拡張は公開範囲の判断後 |
| [ウインドウの大きさの変化で崩れる配置](未実装課題.md#ウインドウの大きさの変化で崩れる配置) | 改善 | Macの一覧幅と最小サイズを修復。iPadと残りの画面が未確認 | サイズ変更で操作を失わないよう、iPadの画面幅切替から再現する |
| [Watchをリモコン既定・通話オプションにする](未実装課題.md#watchはリモコンを既定にし通話を開発者向けオプションにする) | 機能 | 2026-11-20要求。未着手。Watch音声実験の中断は維持 | StandardのWatch設定を開発者向けへ移し、既定は最低限のリモコンのみ。音声通話は明示ON時だけに限定し、設定配置・表示のデザイン判断と実機受入を閉じる |
| [macOS版のアプリ名とアイコンが他OSと一致しない](未実装課題.md#macos版のアプリ名とアイコンが他osと一致しない) | 改善 | 正式名とアイコンの不一致の報告あり。調査待ち | 通常起動と配布生成物でbundle設定・asset・旧版の表示を切り分ける |
| [明暗モードのコントラスト](画面実装とデザイン見本の差分.md#現在の雰囲気を保った明暗モードのコントラスト調整) | デザイン | ダークの境界が見づらいとの要望。配色・適用範囲は未決 | 一覧と設定の明暗の実画面を比較し、既存の質感を保てる差を決める |
| [UIファイルの分離の残り](未実装課題.md#uiファイルの分離の残り) | 改善 | 機能や表示の責務が混在する候補を記録済み | UIの保守を妨げる結合を確認し、共通操作の所有先と両モードの表示責務を揃える |
| [低帯域の推奨を決める](未実装課題.md#低帯域の推奨を決める) | 改善 | 手動候補あり。実通話の比較前 | 悪い通信環境でも会話できる推奨値を決めるため、同じ条件でbitrateだけを変え、聞き取りと通信量を測る |
| [公開時の費用監視と停止運用](未実装課題.md#公開時の費用監視と停止運用) | 機能 | 頻度制限あり。公開時期に依存 | 費用超過に対応できるよう、転送量計測・請求通知・停止手順を実配置で確認する |
