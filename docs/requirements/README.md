## 用途別のストーリーマップ

横は目的に向かう活動の順。各行は、操作する人から結果を受ける人までをたどる。人物と場面ごとの立場は[操作の流れの人物表](../design/操作の流れ.md#人物と場面での立場)を使う。開発・トラブルシュートは担当者が下せる判断までを結果とする。

| 用途・担い手・背景 | 準備する | 使う・変更する | 結果を知る・復帰する |
|---|---|---|---|
| ナオとハルカ。走行中は手がふさがるので、出発前につなぎ、画面を閉じても短い相槌を交わしたい | [出発前にグループで接続する](../design/操作の流れ.md#出発前にグループで接続する) | [走行中に会話する](../design/操作の流れ.md#走行中に会話する)。Standardの[通話画面](../spec/App/UI/Call.md)で開始し、ロック後も会話する | 双方に声が届く。[双方背景と無音状態の受入](製品要求.md#双方背景と無音状態を組み合わせた受入)で後参加・無音後の復帰をたどる |
| ナオが1対1の場所でハルカを待つ。ハルカは停車後に通知を見る | ナオが個人登録済みのハルカを選ぶ。アプリは有効な通知先へ呼び出しを送る | ハルカは「接続」か通知本体を押す。接続待ちや音声停止を含む現在の通話があれば、その通話を開く。「無視」では通知を閉じる | 未接続で呼び出しが有効なら、ハルカはナオの待つ場所へ入る。「無視」や通知を見なかった場合、ナオは同じ場所で待つ。[呼び出しを受ける](../design/操作の流れ.md#呼び出しを受ける) |
| ナオがマキを個人で招待する。送る前に呼び名を保存したい | ナオが未登録の相手と呼び名を保存する | [「招待を共有」で招待を準備し、共有先を選ぶ](../design/操作の流れ.md#新しい相手を招待する)。共有画面を閉じた場合も、ナオは同じ人の詳細からやり直せる | マキは届いた招待を開いて登録する。返信を確認したナオは同じ行からマキを選べる。[招待と登録](../design/招待と登録の設計.md) |
| 会話中のナオが、登録済みのマキと初参加のソラをグループへ招待する | ナオは利用権を持つ。メンバーの選択画面でマキを選び、ソラの名前を入力する | [招待をまとめて保存](../design/操作の流れ.md#会話中に仲間を招待する)する。マキには端末鍵の条件が揃えば自動送信する。ソラの招待はその場でも後からでも共有できる | マキの受取は「受け取り済み」で分かる。ソラは届いた招待を開いて登録し、ナオは返信で登録と参加枠の更新を確認する。今の会話は続く |
| 設計案。ナオとハルカが会話中。参加していないケンタを呼びたい | ケンタが参加できるグループを開く | [ナオがケンタだけを呼ぶ](../design/操作の流れ.md#会話中のグループへ仲間を呼ぶ) | ケンタは通知から入るか、放っておける。ハルカとの通話は続く。他の未参加者は通知を受け取らない。[実装と受入の課題](../backlog/未実装課題.md#グループの中で登録済みの相手を呼び出す) |
| ハルカが個人の登録をやめる。ナオはオフライン | ハルカが相手の設定か一覧から削除を選んで確認する | [削除を保存する](../design/操作の流れ.md#一覧から削除する) | ナオが再びつながり、削除が届いた場合に一覧からハルカが消える。既存の通常グループでの関係と個人登録の解除は別に扱う。[相手に削除された](../design/操作の流れ.md#相手に削除された) |
| 利用権を持つナオが、会話中のグループからマキを外したい | グループ設定でマキの行を開く | [マキの名前を確認して外す](../design/招待と登録の設計.md#削除の種類)。確認中に利用権が切れた場合は設定とメンバーを保つ | ナオのグループ設定からマキが消え、この端末でマキの音声が止まる。残った人との会話と個人登録は続く。マキの端末への反映は[削除同期の課題](../backlog/画面実装とデザイン見本の差分.md#メンバーを外す確認)で追う |
| 製品利用。山中で合流した2人がその場で話し始めたい。アクセスポイントはなく、セルラーも圏外 | 保存済みの相手・グループを選ぶ | [圏外で近くの仲間と始める](../design/操作の流れ.md#圏外で近くの仲間と始める)。近距離経路で互いの発話が届くところまでが最小の体験 | 移動中の経路断・復帰は次の体験として扱う。[通信仕様](../spec/App/通信仕様.md)と[圏外開始の残課題](../backlog/未実装課題.md#apもセルラーもない場所からの近距離通話を実証する)で実装・確認範囲を区別する |
| 開発。送信形式の変更で相手の声まで止めたくない | 送信設定の所有元と[受信資源の寿命](../spec/App/音声処理仕様.md#入力時間と受信資源の寿命)を確認する | [送信形式変更の判定](../spec/App/音声処理仕様.md#送信形式変更の判定)で成功・拒否と受信側の影響を読む | 受信音が続き、失敗時は直前の設定を保つ。画面を開かずに境界を確認でき、画面からの操作は[Settings](../spec/App/UI/Settings.md)へたどれる |
| トラブルシュート。接続表示があっても相手が聞こえず、どこまで音声が届いたかを知りたい | [困ったとき](../manual/困ったとき.md)で出力ミュート・音量・出力先を確かめる | Advancedの[Diagnostics](../spec/App/UI/Diagnostics.md#画面構成)でOverviewの音声停止、矢印と状態を確認する。RXでは受信・復号と相手の行を順に読み、出力の最後の観測を確かめる | [機器消失で音声が止まった](../spec/App/UI/Diagnostics.md#通話の音声が一時停止したとき)場合は出力先を確認し、Callで音声を再開する。原因を特定できなければ[不具合を調べるために残す情報](../manual/困ったとき.md#不具合を調べるために残す情報)を開発側へ渡す |

**会話の品質目標（SLO）**。通常端末・良好な通信・標準の音声分離で、相手の入力から自端末の出力までを対象にする。ローカルの双方向試験では、共通時計を使える環境で、発話が一致した同じ収録区間について方向ごとに `実測遅延 + 計測余裕10 ms ≤ 125 ms` を判定する。UIの接続表示は通信状態、診断表示は処理段の観測を示す。遅延の達成状況は音声測定で確認する。[製品の品質目標とWatchの適用範囲](製品要求.md#共通の品質方針)・[測定区間と実出力の判定](../development/音声E2Eテスト.md#通る経路と判定)・[残る改善](../backlog/未実装課題.md#音声の途切れと遅延)・[未確認の環境](../validation/未確認事項.md)

ほかの製品用途は下表から、要求を実現する内部契約・保存・ログ・画面は[仕様の分類と所有者](../spec/アーキテクチャ.md#仕様の分類と所有者)からたどる。

## 要求とユースケースの対応

[製品要求](製品要求.md#利用者に提供すること)の利用用途ごとに、誰が（立場・相手との関係）、いつ何をしたいか（シーン・目的）、何が使えるか（端末・接続・権限・前景／背景など）、本人と相手にどんな結果が届くかを定める。下表は各ケースの基準となる資料への入口である。詳細は対応する機能仕様に、Standardの操作は[操作の流れ](../design/操作の流れ.md#ユーザーストーリー)に置く。画面を開かずに成立するケースも含む。

| 立場とシーン | 結果が変わる環境・確認する結果 | ケースを管理する基準となる資料 |
|---|---|---|
| 本人が初めて使う・端末やアカウントを替える、仲間の呼び名を編集する | 初回・ログイン済み圏外・同一ユーザーの複数端末。本人の表示名、自分だけの呼び名、アカウントごとのデータとWebRTC接続台数を保つ | [製品要求](製品要求.md#利用者に提供すること)・[一覧と通話](../spec/App/UI/Call.md) |
| 招待者・受取人が登録し、個人またはグループで会話を始める | 個人登録の有無、招待・返信・再共有、待受中・会話中、通知の到達有無。選んだ相手への効果と他メンバーの会話継続を確かめる | [招待と登録](../design/招待と登録の設計.md)・[通知仕様](../spec/App/通知仕様.md) |
| 参加者が別のグループを閲覧し、通話先を替える | 一覧で別の相手を選ぶ操作、招待を受諾して参加先を表示する操作、終話後に別の相手へ接続する操作で結果が変わる。進行中の通話と相手への効果を確かめる | [会話中に別の宛先を扱う](../design/操作の流れ.md#会話中に別の宛先を扱う) |
| 近くの仲間と遠隔の仲間が合流・移動・離脱する | アクセスポイントがなくセルラーも圏外の場所での開始、近距離優先、Internetのみ、混在、経路断と復帰。届く相手との双方向音声、重複送信の抑制、明示終了後の停止を確かめる | [通信仕様](../spec/App/通信仕様.md)・[経路別の状態遷移](../spec/App/UI/画面・状態遷移.md#機器と混在経路の遷移) |
| 走行中の話者・聞き手が画面を閉じて会話を続ける | 開始直後の双方ロック、マイクOFF、無音、経路断・復帰、自動切断期限。それぞれで維持・復帰・終了のどれが必要かを両端で観測する | [双方背景と無音状態の受入](製品要求.md#双方背景と無音状態を組み合わせた受入) |
| 音楽を聴く参加者が音量を調整し、自分の送信音を確認する | 機器・経路・設定を替えてもミュートや音量の意味を維持する。実送信処理後の録音再生、機器消失時の停止と明示復帰、相手の聞こえ方を区別する | [音声処理仕様](../spec/App/音声処理仕様.md)・[設定画面](../spec/App/UI/Settings.md) |
| 停車した利用者が、通話の状態を見て必要な操作を選ぶ | Live Activityは状態を表示し、タップで通話を開く。設定した宛先への接続はWidgetまたは宛先Control、同じ通話のミュート・切断はWidget。iPhoneのロック時の認証、実車でのWidget操作は実機で確かめる | [操作ごとの担当](../spec/App/システム表示と通話操作.md#操作の所有者)・[OS経由の受入](../validation/未確認事項.md#widgetcontrollive-activityのos受入) |
| Watchを着けた利用者が、停車中にiPhoneを手に取らず操作する（開発・検証用） | 指定先、登録済みの相手、iPhoneのロック、Watchの押下・解除・暗転を照合する。通常のiOS ReleaseではWatch Appを同梱しない | [Watch操作](../spec/App/Watch操作.md) |
| 購入者がグループを開始し、参加者が会話を再開する | 利用権・再開猶予・利用枠・配布環境に応じた開始、継続、停止理由を確認する | [通話利用権](../spec/App/通話利用権仕様.md)・[配布環境](../spec/App/配布環境の利用権仕様.md) |

機能・デザインの変更前に、影響する要求から全ケースへ、変更する画面・共通操作・プラグインから影響するケースへ、両方向にたどる。操作の可否、相手への効果、失敗時の復帰、または受入基準が変わる条件は別ケースにし、同じ結果を代表ケースで検証するときは同等と判断した条件を仕様に残す。新しい用途や対応漏れは、該当する仕様書とこの入口を同じ変更で更新する。

各ケースの期待結果には[共通の品質方針](製品要求.md#共通の品質方針)の該当条件を適用する。変更後は対象ケースごとにテスト・必要なE2E・実行環境・観測結果を[検証記録](../validation/README.md)で対応付ける。未確認のケースは条件と再開方法を残し、成立を確認した範囲だけを受入済みとする。

## 招待・削除・購入・音質の要求の所在

確定条件を定める文書は[招待・登録と個別通話](製品要求.md#招待登録と個別通話の一貫性)、[削除・退出・除外の同期](製品要求.md#削除退出除外の同期)、[購入・復元・共有と公開条件](製品要求.md#購入復元共有と公開条件)、[音質選択と音声設定](製品要求.md#音質選択と音声設定の体験)、[通知と画面](製品要求.md#通知と画面の一貫性)。対応する残作業は[未実装課題](../backlog/未実装課題.md)の要求リンクから照合する。要求への追記は実装・受入完了を意味しない。iCloud自動保存は確定要求。長押しや、更新を必須にする方式などは、採用するか決まっていない。
