# 要求の入口

| 知りたいこと | 正本 | 内容 |
|---|---|---|
| アプリは何のために何を満たすか | [製品要求](製品要求.md) | 利用者の価値・背景・品質方針 |
| 省電力機構の考え方を参照したい | [製品要求の参考付録](製品要求.md#付録省電力機構の考え方) | バースト送信を前提に、VAD・CNG・DTXと通信制御を参考として整理。各技術の導入決定とは分ける |
| 共通基盤に何を統一して求めるか | [パッケージ要求](パッケージ要求.md) | 責務と判断基準 |
| どう作る必要があるか | [開発方針](../policies/開発方針.md) | 製品とは別の工程・設計・品質の制約 |
| 配布時のバージョン管理に何を求めるか | [開発方針の公開バージョンとビルド番号](../policies/開発方針.md#公開バージョンとビルド番号) | Debug・Release・Archive共通連番、公開バージョン維持、project設定と成果物の番号一致 |
| どう書き、整理するか | [文書作成規約](../policies/文書作成規約.md) | 分類、更新責任、命名、計画 |
| ログの共通方針 | [ログ記録規約](../policies/ログ記録規約.md) | 記録する情報と機密保護の境界 |

実装の棚卸し・API詳細は仕様、達成状況は検証へ記録する。[仕様](../spec/アーキテクチャ.md)は現行実態、[課題](../backlog/README.md)は実装する作業と候補、[検証](../validation/README.md)は確認待ちと証跡を管理する。初期構想と対応経緯は[履歴](../validation/history/初期構想と対応経緯.md)に保存する。

## 要求とユースケースの対応

[製品要求](製品要求.md#利用者に提供すること)の利用用途ごとに、誰が（立場・相手との関係）、いつ何をしたいか（シーン・目的）、何が使えるか（端末・接続・権限・前景／背景など）、本人と相手にどんな結果が届くかを定める。下表は各ケースの正本への入口である。詳細は対応する機能仕様に、Standardの操作は[操作の流れ](../design/操作の流れ.md#ユーザーストーリー)に置く。画面を開かずに成立するケースも含む。

| 立場とシーン | 結果が変わる環境・確認する結果 | ケースを管理する正本 |
|---|---|---|
| 本人が初めて使う・端末やアカウントを替える、仲間の呼び名を編集する | 初回・ログイン済み圏外・同一ユーザーの複数端末。本人の表示名、自分だけの呼び名、アカウントごとのデータとWebRTC接続台数を保つ | [製品要求](製品要求.md#利用者に提供すること)・[一覧と通話](../spec/App/UI/Call.md) |
| 招待者・受取人が登録し、個人またはグループで会話を始める | 個人登録の有無、招待・返信・再共有、待受中・会話中、通知の到達有無。選んだ相手への効果と他メンバーの会話継続を確かめる | [招待と登録](../design/招待と登録の設計.md)・[通知仕様](../spec/App/通知仕様.md) |
| 参加者が別のグループを閲覧し、通話先を替える | 未接続・接続中で選択の効果が異なる。閲覧、切断、新しい通話の開始を区別する | [操作の流れ](../design/操作の流れ.md#ユーザーストーリー) |
| 近くの仲間と遠隔の仲間が合流・移動・離脱する | APもセルラーもない場所での開始、近距離優先、Internetのみ、混在、経路断と復帰。届く相手との双方向音声、重複送信の抑制、明示終了後の停止を確かめる | [通信仕様](../spec/App/通信仕様.md)・[経路別の状態遷移](../spec/App/UI/画面・状態遷移.md#機器と混在経路の遷移) |
| 走行中の話者・聞き手が画面を閉じて会話を続ける | 開始直後の双方ロック、マイクOFF、無音、経路断・復帰、自動切断期限。それぞれで維持・復帰・終了のどれが必要かを両端で観測する | [双方背景と無音状態の受入](製品要求.md#双方背景と無音状態を組み合わせた受入) |
| 音楽を聴く参加者が音量を調整し、自分の送信音を確認する | 機器・経路・設定を替えてもミュートや音量の意味を維持する。実送信処理後の録音再生、機器消失時の停止と明示復帰、相手の聞こえ方を区別する | [音声処理仕様](../spec/App/音声処理仕様.md)・[設定画面](../spec/App/UI/Settings.md) |
| Watch装着者やWidget利用者がiPhoneを手に取らず相手を選んで操作する | 指定先・登録済み相手、iPhoneのロック、Watchの押下・解除・暗転。開始・終了・ミュートの効果とWatch送受話の各条件を確かめる | [Watch操作](../spec/App/Watch操作.md)・[システム表示と通話操作](../spec/App/システム表示と通話操作.md) |
| 購入者がグループを開始し、参加者が会話を再開する | 利用権・再開猶予・利用枠・配布環境に応じた開始、継続、停止理由を確認する | [通話利用権](../spec/App/通話利用権仕様.md)・[配布環境](../spec/App/配布環境の利用権仕様.md) |

機能・デザインの変更前に、影響する要求から全ケースへ、変更する画面・共通操作・プラグインから影響するケースへ、両方向にたどる。操作の可否、相手への効果、失敗時の復帰、または受入基準が変わる条件は別ケースにし、同じ結果を代表ケースで検証するときは同等と判断した条件を仕様に残す。新しい用途や対応漏れは、該当する正本とこの入口を同じ変更で更新する。

各ケースの期待結果には[共通の品質方針](製品要求.md#共通の品質方針)の該当条件を適用する。変更後は対象ケースごとにテスト・必要なE2E・実行環境・観測結果を[検証記録](../validation/README.md)で対応付ける。未確認のケースは条件と再開方法を残し、成立を確認した範囲だけを受入済みとする。
