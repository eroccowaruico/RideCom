# 画面とデザイン見本の照合

## 指示と経緯

2026-11-06の利用者指摘「実装のDiagnosticsとHTMLとだいぶ印象が違う。他の画面も含めて精査不足」を受け、実際に描画した画面とHTML見本を並べて照合した。同日の先行点検（[デザイン案の未反映](../../backlog/画面実装とデザイン見本の差分.md)）はコードと文言の読み取りだけで行い、Diagnosticsを「デザインどおり」と判断していた。これは見た目を確認しない誤った判断であり、本書の照合で訂正する。

## 総点検（2回目）

同日の利用者指示「他の画面も実装とHTMLの差を総点検」「細かい違いも親子関係を維持してバックログへ」により、範囲を広げて撮り直した。

| 項目 | 内容 |
|---|---|
| 実行 | 一時UI試験`ZZAuditAllUITests`（commitしない）を別worktreeで実行。iPhone 17 Pro（iOS 27.2）で5試験60枚（サインイン・名前の入力、Standardの一覧・招待・通話のシート・メニュー・確認・横画面、設定の全体・通信経路・開発者向けの高度な設定・アカウント削除、AX5、Advanced）、iPad Pro 11インチ（M5）で1試験11枚（縦・横の一覧・設定・Diagnostics）。全試験成功 |
| 既存の画像 | Apple Watch 3枚（2026-11-03）、Widget・Live Activityの描画試験64枚（2026-11-03） |
| 証跡 | `.validation/design-audit-20261106/screens2/`、`surfaces/`、一覧画像`sheet2_0〜3.png`・`sheet_surf.png`、試験のソース |
| 撮れなかったもの | 試験用の招待URLの受け入れが「この招待を確認できませんでした」で失敗し、保存ユーザーがいる状態（ユーザーの行、1対1の通話、メンバーの行、切替の確認）が撮れなかった。iPadの通話の列、Control、Watchの会話中以外の状態、ダーク表示も未撮影 |

新たに分かった主な差: iPadの一覧が全幅・設定が中央の帯（縦）と左寄せ（横）、AX5で招待中の行が1〜2文字ずつ折り返して読めない、招待のシートが名前を先に入れない旧来の構成、日本語の表示に英語（Speaker、Auto、Internet、Audio Session等）が混ざる、「送信する声を明瞭にする」など用語集で使わない語、Widgetのミュート中にミュートと切断が同じ赤の塗りに見える。差分はすべて[画面実装とデザイン見本の差分](../../backlog/画面実装とデザイン見本の差分.md)に画面ごとの階層で記録した。

## 扱い

実装の差は[画面実装とデザイン見本の差分](../../backlog/画面実装とデザイン見本の差分.md)へ記録した。実装からデザインへ取り込んだ点（人とグループのアバターをどちらも青い円にし、記号で区別する）は[デザインシステム](../../design/デザインシステム.md#共通コンポーネント設計案)へ反映した。iPadの通話の列、Macの実ウインドウ、ダーク表示、会話中の画面、保存ユーザーがいる状態の照合は未実施であり（iPadの一覧・設定・DiagnosticsとAX5は総点検で照合した）、[未確認事項](../未確認事項.md#画面デザインの実環境受入)の範囲として残す。


## 個人通話のメンバー表示の修正

2026-11-17の利用者報告を受け、Standardの個人通話からメンバーSectionを外した。Markdownの「1対1も自分と相手の2行を置く」とHTMLの同じ2行も訂正し、[配置の定義](../../design/一般向け/画面構成とレイアウト.md#会話中の配置)・[HTML見本](../../design/一般向け/デザイン見本.html#call)・[現行仕様](../../spec/App/UI/Call.md#ユーザー指定の個別通話)・マニュアルを揃えた。通常グループの2人を個人通話と推測せず、`IntercomGroup.kind`で分ける。Advancedの表示は維持する。

| 確認 | 結果・証跡 |
|---|---|
| 基準 | `d0f464e`のAppへUI回帰を先に追加。`design-direct-red-20261117`でメンバー見出しの非表示assertが失敗し、不具合を再現 |
| 個人通話 | `StandardInterfaceUITests.testDirectCallHidesMembersAcrossReopeningAndLayoutSwitch`。招待URLの署名検証・受諾・保存した相手の選択から実UIを操作。相手名と通話操作を保ち、開き直しとStandard→Advanced→Standardの後も一覧・招待が出ない。同じ相手を加えた通常の2人グループには一覧が出る。`design-direct-green2-20261117/ui.xcresult`、1件成功、失敗・skip・runtime warningなし |
| 既存の通話操作 | `DesignSystemCallUITests.testCallControlsAndCancelledDisconnectKeepCall`は`design-direct-green-20261117/ui.xcresult`で成功。修正済みAppでミュート・消音・切断取消を確認。同runの個人通話試験は下スワイプがシートを閉じるテスト操作で失敗し、操作を訂正して上のrunで再確認 |
| 画面 | 最終runの`attachments/manifest.json`の`Standard direct call without members`と`Two-person ordinary group retains members`を目視照合。iPhone 17 Pro、iOS 27.2、英語・light・標準文字サイズ。HTMLのdiv/figure構造と個人通話見本の行除去も検査 |

範囲は接続待ちの実UIとモード切替。合成した相手は接続しないため、実音声・会話中・音声停止・実機受入を示す試験ではない。状態に依存しない種別条件でSectionを出し分ける。HTMLのブラウザ描画はローカルファイルURLの表示制限により未確認であり、構造と定義を照合した。


## グループ行の共通スワイプ削除

2026-11-17、利用者のスワイプ削除の報告と、共通化済みなのに仕様が違うとの指摘を受けて修正した。`destinationRowActions`自体は共通だったが、Standardだけ`canDelete: false`で削除を隠し、Advancedは権限条件なしで削除を出していた。両方を`canEditSavedGroups && groupRepository.ownsGroup(group.id)`へ揃え、共通の確認から既存の`deleteGroup`へ接続した。`allowsFullSwipe: false`と既存の削除取消・切断の安全条件を維持する。

| 確認 | 結果・証跡 |
|---|---|
| 修正前 | `design-swipe-red-20261117`でStandardのオーナー行にDeleteがない失敗、`design-swipe-permission-red-20261117`でAdvancedの非オーナー行にDeleteがある失敗を再現 |
| 修正後 | `design-swipe-green-20261117/ui.xcresult`。`DesignSystemCallUITests.testGroupSettingsOpenFromTheCallMenuAndTheListRow`と`StandardInterfaceUITests.testJoinedGroupHasNoSwipeDeleteInEitherLayout`の2件成功。失敗・skip・runtime warningなし |
| 操作 | 通話・一覧からの設定、名前の保存、設定での削除取消を回帰。実際のスワイプから削除確認を出し、取消で一覧・通話を保持、確定で一覧から消えて接続が終わることを確認。招待から入ったグループの行ではStandard・Advancedとも設定だけを表示 |
| 定義との照合 | デザインシステム、操作の流れ、招待と登録、一般向けと詳細画面のMarkdown・該当HTML見本、現行Call仕様とマニュアルを同時更新。HTMLのdiv/figure構造、文書参照、String Catalog、差分を検査 |

環境は専用iPhone 17 Pro Simulator、iOS 27.2、英語・light・標準文字サイズ。合成した署名付き招待を使い、実サービスは利用しない。実機のジェスチャ・Macの右クリック、他端末への削除同期の受入を示すものではない。HTMLのブラウザ描画はローカルファイルURLの表示制限により未確認。


## 同一部品の共通化ルールの照合

2026-11-17、スワイプの共通化に関する利用者の指摘を受け、[開発方針の絶対ルール](../../policies/開発方針.md#standardとadvancedの設計の絶対ルール)とデザイン文書を再照合した。正本は2026-11-15から表示・語・配置・操作が完全に同一の部品の共通化を許していたが、デザインシステムの部品節とHTMLの冒頭・StandardとAdvancedの比較には「部品を流用しない」「共通なのは色・安全・アクセシビリティの下限だけ」という古い説明が残っていた。

MarkdownとHTMLを同じ条件へ揃え、操作の流れと詳細画面の一律の禁止表現も訂正した。異なる部品の分離、Commonの中でモード分岐を持たせず違いが生じたら分ける条件は維持する。共通スワイプ・削除確認を具体例としてCallの現行仕様へ参照させた。文書のみの変更で、文書参照・該当HTMLのdiv/figure構造・差分を検査し、実装の追加変更やアプリの機能検証とは区別する。


## グループ設定の削除と退出の共通化
