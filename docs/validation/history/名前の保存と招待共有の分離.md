# 名前の保存と招待共有の分離

## 指示と設計

2026-11-17。招待中に名前の確定・共有・終了の意味が分からず、OS共有を取り消せることも設計から漏れていたという利用者指摘に対応する。[状態遷移と一連の操作](../../design/招待と登録の設計.md#招待の作成)を先に定義し、HTMLの入力・保存済み詳細も更新した。共有取消・コピーを配達や登録成功と扱わず、画面を勝手に閉じない。

## 名前だけ保存する基盤

App工程。`SavedUser`の固定IDを先に明示保存できるschema 10を追加した。未登録の人はリモート識別情報を持たず、通話・グループ追加・通知許可の対象から除外する。招待の送受信の記録は`personID`で人へ紐づける。初回受諾は元のIDと呼び名を引き継ぎ、既存本人は既存IDと呼び名を保って重複を除く。表示名による統合はしない。期限切れ・削除・再送ACKでも名前だけの人を勝手に登録しない。

## 同じ相手の詳細で保存・共有・完了する

保存前は書き込まず、明示保存で同じシートを確定した名前の詳細へ切り替える。共有しなくても完了でき、共有取消・コピー・前面復帰・相手の受諾でも親の詳細を勝手に閉じない。相手の受諾で同じ人の行を更新する。AdvancedはSavedUserと送受信の記録を同じ人の詳細に内包する。受け手の拒否は無書込・相手への通知なしで、同じ有効リンクから後で登録できる。

登録前の人を通話・グループ追加・通知許可に使わず、通常通話・ミュートを維持する。通話中は返信を再試行できないため、待機理由を表示して実行できないボタンを出さない。前面復帰で同じログイン世代の停止対象だけを1回再開し、各試行は従来の最大60秒。background scanや通知基盤は追加しない。共有文に呼び名が含まれる説明もMarkdown・HTML・画面へ揃えた。

## 失敗の扱いと確認の限界

初回UIでは、削除確認ボタンの二重AX要素、長い一覧の途中からの集計、日本語の行操作を英語で検索したこと、スクロール後の非表示ヘッダーを同時に検索したことを修正した。旧仕様の「ACKで詳細を閉じる」というテスト期待も、同じ人の詳細を保持する新仕様へ更新した。失敗したrun全体を成功とは扱わず、主要な6操作と共通処理は`contact-person-ui-verified-20261117`で全件再実行した。

`contact-person-active-reply-red-20261117`はXCTestのURL起動でAppが再起動するため通話中の再現にならなかった。`contact-person-active-reply-red2-20261117`では、登録→通話開始→同じ相手の設定の順で実際の待機状態を作り、誤った「Reply not delivered」を再現した。その修正後は通話・ミュートを維持し「Waiting for the current call to end.」を表示する。

Mac実通信の証拠は標準のApplications配下の専用コピーから実行したものだけを使う。DerivedDataのhostに再試行を重ねない。Macの通常hostの60定義成功と、最終コピーの123定義成功を混同しない。

実通信の2者は同じ検証host内の独立したViewModel・保存領域・native transportであり、2実機のUI往復や実AirDropの証明ではない。物理端末、外部の共有先アプリへの実到着、VoiceOver実操作、Mac共有画面の実操作、HTMLのbrowser表示は未確認。HTMLの表示が拒否された経路を別経路で回避していない。実OSの電源断・commit直後の障害を含む保存故障のUI操作も、モデルの故障注入・再読込と区別する。

通知は通常のAPNsとUserNotificationsを前提にし、CallKit・VoIP Push・Apple PushToTalkは追加していない。オフラインでの手動返信共有、2実機の各段階の照合、成立後の仮名から本人名への変更確認は[招待の残課題](../未確認事項.md#新規相手招待の実環境受入)として維持する。ローカルの修正・検証完了と、招待全体の実機受入を分ける。
