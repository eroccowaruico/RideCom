# 招待返信の手動共有

2026-11-18。利用者の「招待を優先し、小さく修正・検証・コミットし、Markdown・HTML・仕様・実装を揃える」指示を継続する。基準は`600a518`、担当は現在のチャット、作業領域は通常cloneのmain。未実装だった[オフライン返信](../../backlog/未実装課題.md#インターネット未接続だと招待への応答まで進めない)を対象とし、通知は通常APNs／UserNotificationsを維持する。

## 先に検証する経路

Internet資格・サーバー・通常通話・ローカル無線を使わず、保存済みの署名付き返信を共有URLへexportし、元の作者が同じ招待へ登録する。作者の到着確認も共有URLで受け手へ返し、同じ受諾の配達待ちを解消できるかを先に検証する。共有取消・コピーで配達済みと推測しない。通話とミュート、人のID・詳細は保つ。

保存APIと画面を別単位にする。APIの成立後、同じ人の詳細・設定へ共有操作と復帰を接続し、両モードのUIと文書を揃える。後者までこのstory全体を完了とは扱わない。

## 同じ受け取り画面から共有を続ける

`0f40f4e`の保存APIへOSのShareLinkと専用URL入口を接続した。登録後は同じacceptingのシートを保存済みの人の詳細へ更新する。その場で返信共有、またはDoneで一覧へ戻る。共有取消・コピーで詳細を閉じず、共有操作だけで配達済みを保存しない。手動返信を受けた作者はreceivedBySharingを同じcommitで保持し、この場合だけStandardに到着確認を案内する。通常の自動交換ではこの追加操作を出さない。Advancedは保存値と処理条件をそのまま示す。

UIテストは既知の合成署名者を相手役とし、実際のOS共有でコピーされたリンクを、隔離した検証アプリの未保存の名前入力で明示Pasteして観測し、必ずCancelで破棄する。これはテストの観測用であり、利用者の手順ではない。iOSがテストランナーの直接Clipboard読取を拒否した先行実行はcontact-reply-ui-core／contact-reply-ui-copyに保持した。通常Appへ鍵・URL表示用の検証経路は追加していない。

XCTestのURL入口では、再表示後の保存状態と同じ相手を照合する。起動中のpresentation識別の保持はVMの実操作でも別途確認した。ローカルでの手動共有と登録後の続行は完了。Internet不在の2実機でのAirDrop・共有先アプリ往復、物理無線・実サービス通知は未受入であり、この結果で招待全体の受入完了とはしない。CallKit・VoIP Push・Apple PushToTalkは使わない。
