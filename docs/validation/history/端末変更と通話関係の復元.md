## 再起動後に自動保存を再開する

2026-11-22。共有mainの `69af50fa` を展開し、[自動保存の照合](../../spec/App/通信仕様.md#アプリの操作を起点に復元候補を自動保存する)を検証した。macOSとiPhone Simulatorで各38件が成功した。対象は `CallRelationshipAutomaticBackupTests`、`CloudKitCallRelationshipBackupStoreTests`、`BackgroundCallStorageTests`、`AccountDeletionTests`、`ReplacementDeviceRestoreTests`。

| 試した条件 | 結果 |
|---|---|
| 自動保存を止めて編集し、通話モデルを作り直す | 同じ端末内のKeychainと保管先から再開し、保管先に変更がなければ新しい編集を保存した |
| 保管先に届いたが応答が途切れ、再開前にさらに編集 | 再起動後の照合で前の送信結果を確認し、新しい編集を保存した |
| 別端末が先に編集、または確認済みの保管記録を削除 | 再起動しても別端末の編集を維持し、削除した保管記録は作り直さなかった |
| 別のiCloudアカウントまたは別の端末鍵 | 以前のハッシュ値を使わなかった。読込中にiCloudアカウントが切り替わった場合も送信しなかった |
| Keychainの保護、アカウントの端末内データの消去 | iOS用の保護属性を選ぶことと、同じ名前空間のハッシュ値も消去することを確認した |

模擬Keychain、CloudKit SDKの記録型、模擬保管先を使い、再起動は同じ保存先から通話モデルを作り直して試した。実iCloudの有効化、競合した編集と削除の統合、復元前の参加資格の照合は[残作業](../../backlog/未実装課題.md#icloud自動保存と招待をやり直さない端末復元)に含める。

## 端末内の保存と前面復帰から候補を自動保存する

2026-11-22。共有mainの `9d4ad430` を展開し、[自動保存の仕様](../../spec/App/通信仕様.md#アプリの操作を起点に復元候補を自動保存する)を試した。macOSとiPhone Simulatorの両方で21件が成功した。対象は `CallRelationshipAutomaticBackupTests`、`CloudKitCallRelationshipBackupStoreTests`、`ReplacementDeviceRestoreTests`、`GroupPersistenceTests`。

| 試した条件 | 結果 |
|---|---|
| グループの名前を変えて端末内に保存 | アプリの保存操作から候補を更新した。端末内の書込が失敗したときは送信を要求しなかった |
| 問い合わせ中にグループの名前を変更 | 最新の名前を1回だけ保存した。最後のグループを消した後は、空の候補で上書きしなかった |
| 保管先の別端末が同じグループを先に編集 | 既存の内容を上書きしなかった。自動保存を構成し直した後も、異なる記録を保った |
| 保管先との通信に失敗、アプリが前面復帰、次の読込中にアカウントを切替 | 前面復帰で再試行し保存した。切替後は新しい書込を始めなかった |

アプリ本体のグループ保存・前面復帰を使い、CloudKitの読込と書込はメモリ内の保管先で代替した。実iCloudの設定と接続、再起動をまたぐ編集や削除の統合、通話資格の照合は[残作業](../../backlog/未実装課題.md#icloud自動保存と招待をやり直さない端末復元)に含める。

## iCloudの保存・読込を模擬保管先で確かめる

2026-11-22。共有mainの `680d5828` を展開し、[iCloudのアプリデータ領域に候補を保存する処理](../../spec/App/通信仕様.md#復元候補をicloudのアプリデータ領域に保存する)を加えた。macOSとiPhone Simulatorの両方で19件が成功した。対象は `CloudKitCallRelationshipBackupStoreTests`、`CallRelationshipBackupTests`、`ReplacementDeviceRestoreTests`、`GroupPersistenceTests`。

| 試した条件 | 結果 |
|---|---|
| 旧端末が保存し、同じ本人の別端末が読む | 同じレコードの候補を読み込んだ。別人は別のレコードを参照し、混ざらなかった。別人の候補や、別人が読んだレコードを使う更新を拒否した |
| 暗号化と許可した項目 | CloudKit SDKが扱う `CKRecord` を使い、平文のフィールドを作らず、暗号化フィールドに候補の項目だけを入れた。平文や追加のフィールドがある記録は拒否した |
| 同時更新、保管先を読めない、候補が空 | 最新の変更との一致を求める書込条件を指定し、模擬保管先が競合を返した後も前の内容を保った。未作成と読込失敗を区別し、空の候補の書込は拒否した |

CloudKit SDKの記録形式を使い、読込と書込の相手はメモリ内に作り直した。実iCloudのスキーマ・権限、アカウント切替時の自動保存、機種変更後の現行参加資格の照合は[残作業](../../backlog/未実装課題.md#icloud自動保存と招待をやり直さない端末復元)で扱う。

## 本人の保存データから通話関係の復元候補を取り出す

2026-11-22。共有mainの `5d86e381` に候補の作成と読込を加え、macOSとiPhone Simulatorで復元候補・端末復元・保存の各16件が成功した。試験では架空の2アカウントと異なる端末鍵を使った。

保存データに、本人との対応が記録されたグループ、対応の記録がないグループ、別人との対応が記録されたグループを用意した。新端末は同じ本人の有効な端末証明で読み込み、本人と結び付くグループと個別通話の相手だけを得た。保存したJSONの項目を調べ、端末や招待の資格が含まれないことを確認した。別人の証明、期限切れ、対応していない形式番号は拒否した。同じ保存を別の処理が変更した場合は、再読込が必要になることを確認した。

[復元候補の仕様](../../spec/App/通信仕様.md#保存データから通話関係の復元候補を作る)の範囲を試験した。iCloudへの書き込み、本人との対応を記録していない関係の移行、現在の参加資格の照合は[残作業](../../backlog/未実装課題.md#icloud自動保存と招待をやり直さない端末復元)に含める。

## 招待時に記録した旧端末の公開鍵を新端末で再利用すると拒否する

2026-11-22。旧端末のアカウントとの対応が通常グループに残らず、招待時の公開鍵だけが残る場合を、試験用の本人と鍵で再現した。修正前は、旧端末と同じ公開鍵を持つ別の端末IDで復元でき、通話先と通話鍵が保存された。

[新端末への保存仕様](../../spec/App/通信仕様.md#新端末に確認済みの通話関係を保存する)に従い、修正後は同じ鍵での復元を拒否し、保存済みの内容と鍵の保管状態を維持した。異なる鍵では保存と再読込に成功し、グループに残る相手の招待時の公開鍵と、新端末のアカウントに対応する公開鍵を確認した。

共有mainの `949f3985` にこの変更を加え、macOSで復元・通常グループ・永続化の31件、iPhone Simulatorで復元・永続化の14件が成功した。Simulatorでは通常グループと個別通話の試験音声パケットの送受信も再確認した。この試験は確認済みの入力を作って端末内の保存処理から始める。iCloudから読み出す処理と、最新の参加資格を確認する処理の検証は引き続き[バックログ](../../backlog/未実装課題.md#icloud自動保存と招待をやり直さない端末復元)で追う。

## 確認済みの関係を保存する処理を共有mainで検証する

2026-11-22。共有mainの `d1f699ab` を空の作業場所へ展開し、端末内の保存処理と回帰試験を加えて検証した。各試験は架空の本人、元の端末と異なる署名鍵、有効な試験用の端末証明から作り直した。試験の入力や鍵材料はリポジトリへ保存しなかった。

| 環境 | 入口と結果 |
|---|---|
| macOS | `ReplacementDeviceRestoreTests`、`RegularGroupRepresentativeTests`、`GroupPersistenceTests` の30件が成功 |
| iPhone Simulator | `ReplacementDeviceRestoreTests` と `GroupPersistenceTests` の13件が成功 |

旧端末の参加情報を直接読み込むと拒否する。同じ本人の新端末では個別通話と通常グループを保存して開始でき、iPhone Simulatorでは双方が試験用の音声パケットを受信した。除外された本人は古いデータから参加できず、保存失敗後も一覧を保持した。

旧設定だけが戻った場合は、通話・招待の開始を拒否し、近距離で招待を送受信する資格を生成せず、元の保存を維持した。

保存処理は確認済みの入力を受け取る。[iCloud復元の残作業](../../backlog/未実装課題.md#icloud自動保存と招待をやり直さない端末復元)では、iCloudへの自動保存と、本人・現在の参加資格を確認してから保存処理を呼ぶ部分を扱う。

## 2026-11-22の先行検証

[端末変更時の復元要求](../../requirements/製品要求.md#icloud自動保存と端末変更時の復元)に沿って、旧端末の署名用秘密鍵と端末資格を使えない機種変更を再現した。相手側には旧端末を登録した状態を残した。通常グループと個別通話に必要な試験用データだけを別の保存先へ渡し、新端末には別の端末ID・署名鍵と同じRideComアカウントの試験用証明を用意した。

| 確認 | 結果 |
|---|---|
| 旧端末の参加情報のまま保存を読込 | 通話用の鍵を用意した状態でも、現在の端末IDがグループにないため読込を拒否した。元の保存を維持した |
| 本人確認後の復元データを模した入力 | 本人の参加情報だけを新端末用に組み直すと、個別の相手IDと通常グループ・個別通話のIDおよび通話鍵を維持して、双方の通話開始と音声の許可まで進んだ。通常グループでは相手側の旧端末の枠を新端末へ引き継いだ |
| 別人・除外・再接続 | 個別通話では、未登録の端末が証明を出さない場合と、別アカウントの証明を出した場合に音声を許可しなかった。登録後は保存した鍵で再接続した。通常グループでは旧端末の持ち主を除外すると、古い保存を持つ新端末が同じアカウントの証明を出しても音声を許可しなかった |

macOSは標準の検証手順で47件成功。証跡は `.validation/icloud-replacement-device-20261122/macos-candidate/`。

```sh
scripts/validate.sh macos \
  --only-testing RideIntercomTests/ReplacementDeviceRestoreTests \
  --only-testing RideIntercomTests/RegularGroupRepresentativeTests \
  --only-testing RideIntercomTests/AccountDirectCallTests
```

iOS Simulatorは52件成功。復元を模した個別通話と通常グループで、2端末分の近距離接続に試験用のPCM音声パケットを流し、双方で受信した。証跡は `.validation/icloud-replacement-device-20261122/ios-candidate/`。

```sh
scripts/validate.sh ios \
  --only-testing RideIntercomTests/ReplacementDeviceRestoreTests \
  --only-testing RideIntercomTests/DirectCallTests \
  --only-testing RideIntercomTests/AccountDirectCallTests
```

復元の入力は試験内で作った。実機のiCloudバックアップ、Appleでの本人確認と端末登録、保存した通話鍵の安全な復元、削除・退出・失効後の古いバックアップの取込は受入前。通常グループでは通話鍵と端末署名を持つ相手が別の枠に入れる場合があるため、復元時に本人と最新の参加資格を確かめてから通話鍵を使える状態にする。[実装前の設計条件](../../backlog/機能拡張の実装前整理.md#icloudへの保存と自分の端末間同期)

## 確認済みの関係を保存して通話する

2026-11-22、Build 2070。先行検証で試験内に置いた参加情報の組み直しを、[端末内の保存処理](../../spec/App/通信仕様.md#新端末に確認済みの通話関係を保存する)へ移した。復元の呼出元が本人と現在の参加資格を確認済みであることを、試験用の入力で再現した。

| 条件 | 結果 |
|---|---|
| 同じ本人の新端末 | 通話鍵を新端末用の参照で保存した。起動時の通常読込と相手・グループを選ぶ操作から、双方が音声を受け入れた。iOS Simulatorでは個別・グループとも双方が試験用PCMパケットを受信した |
| 別アカウントの所有者・証明の期限切れ・本人の除外記録 | 保存処理が拒否した。相手・通話先の一覧と端末内の鍵は変わらなかった |
| 通話鍵を保存した後で一覧の確定に失敗 | 確定済みの一覧は変わらなかった。再読込で参照されない鍵を回収し、再試行で相手・通話先と鍵を保存できた。復元済みの保存先に同じ入力を渡しても上書きしなかった |

macOSは復元・グループの認証・保存の29件、iOS Simulatorは復元・保存・背景操作の18件が成功。いずれも標準の検証手順で、指定した試験がすべて実行されたことを照合した。証跡は `.validation/icloud-restore-store-20261122/`。

```sh
scripts/validate.sh macos \
  --only-testing RideIntercomTests/ReplacementDeviceRestoreTests \
  --only-testing RideIntercomTests/RegularGroupRepresentativeTests \
  --only-testing RideIntercomTests/GroupPersistenceTests
scripts/validate.sh ios \
  --only-testing RideIntercomTests/ReplacementDeviceRestoreTests \
  --only-testing RideIntercomTests/GroupPersistenceTests \
  --only-testing RideIntercomTests/BackgroundCallStorageTests
```

保存処理は、呼出元が本人と参加資格を確認した結果を受け取り、通常の更新経路で鍵と一覧を確定する。今後は呼出元で照合する処理を実装し、実機でiCloudへの自動保存から復元後の通話までを確認する。[残作業](../../backlog/未実装課題.md#icloud自動保存と招待をやり直さない端末復元)
