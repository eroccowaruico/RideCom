# 実機確認待ち

## 対象と確認を減らす進め方

2026-11-02、バックログと未確認事項のうち、記録済みの実装・ローカル検証に対して物理端末・周辺機器・実無線での確認だけが残る範囲を分離した。各行に記した受入範囲だけを扱い、機能全体や最新ソースの全体検証が完了したことは意味しない。未着手・未解決の作業は[バックログ](../backlog/README.md)、自動テスト・Mac／Simulator・実サービス・署名／配布も残る項目は[未確認事項](未確認事項.md)で管理する。

実機の前に、変更の影響がある単体・結合・UI・音声E2Eを自動化で閉じ、既存証跡と対象ソースを照合する。同じ端末・同じ操作で重なる確認はまとめ、物理端末でしか観測できない無線・機器・OS動作・聴感に絞る。後続変更で自動検証不足や不具合が判明した範囲は未確認事項／バックログへ戻す。現在の音声E2Eの環境阻害は[Mac音声](未確認事項.md#mac音声サービスの応答待ち)・[Simulator音声](未確認事項.md#simulatorのnative入力開始)を参照し、過去の成功で置き換えない。

## ネットワーク設備のない場所での近距離通話

[圏外開始の製品App回帰](../backlog/未実装課題.md#apもセルラーもない場所からの近距離通話を実証する)を通したソースで実無線を確認する。前提は[現行の近距離経路](../spec/App/通信仕様.md)と[QUIC移行後の再調査](history/近距離オフライン通信.md#quic移行後の再調査)を参照する。実装の確認やSimulator内の音声試験の結果と、設備を外した実無線の結果は区別して記録する。

| 単位 | 試験条件 | 合格条件 |
|---|---|---|
| 最小の設備なし実無線試験 | 上の自動回帰を閉じたソースをiPhone 2台へ導入し、AP未接続・セルラーOFF・テザリングなしでAppを終了した状態から開始する。Wi-Fi機能・ローカルネットワーク／マイク権限・保存済み準備を事前照合し、通知を受けずに同じ通話先へ入る | 探索・相互認証・実UDP受信・復号・両端の音声出力までの時刻と経路を記録する。単なる接続表示・send成功・同一Mac／Simulatorでの成功は合格の代用にしない。失敗時はこの最小条件を修復して再試験してから台数を増やす |
| 継続・移動・隊列 | 2台の相互発話、1〜3秒の無音と相槌、画面ロック・バックグラウンド、AP離脱と復帰を確認する。次に3台以上で先頭と最後尾が直接届かず中間だけを介する条件を作り、中間の離脱・再合流を測る。最後に8台へ広げる | 実際の直接リンクと中継経路を記録し、届く範囲の会話を維持する。遮断解除後は手動の繋ぎ直しなしで新しい音声が届き、重複・古い音声を再生しない。手動終了・自動切断後は復活せず、期限も延長しない |
| 品質と製品受入 | 既定設定の双方向音声、距離・障害物・移動・台数による遅延分布・欠落・電池消費を同じ条件で記録する。Internet復帰・遠隔参加者との混在は別条件で確認する | [音声の途切れと遅延](../backlog/未実装課題.md#音声の途切れと遅延)と[背景切断](../backlog/未実装課題.md#バックグラウンドでの予期しない切断後に再接続できない)の残件を照合する。接続成立、継続成立、約125 msを含む品質合格を別々に判定し、品質基準を緩めず未達を修復課題として残す |

最初の実無線試験は2台・1条件・接続待ち60秒上限・発話2分・同じ条件の試行は最大2回を調査枠とする。この値は製品の待機時間・通話時間の仕様ではない。失敗した段階のログ・波形を保存して切り分け、同じ失敗を繰り返す前に仮説を更新する。対象外の開発用ネットワークは変更しない。必要な物理端末・無線条件・導入権限を確保できる時点で実行する。

対象commit・設定・OS・機種・保存済み前提、AP／セルラー／テザリングの状態、両端の認証と経路、受信・native出力・発話波形、距離・遮蔽物・移動、開始／復旧時間、遅延・欠落・電池測定の条件を[近距離オフライン通信の履歴](history/近距離オフライン通信.md)へ記録する。端末IDは必要な範囲でハッシュ化し、鍵・招待token・音声内容は通常ログから除く。検証用の発話波形は検証成果物として保管する。

## iPadの実機表示と入力

iPadは同じiOS版のfamily 1,2に含め、専用Simulatorで英日・縦横・sheet・主要操作を検証した。実機の複数window、Stage Manager、外部入力機器、VoiceOverは未確認であり、[統合検証](history/外部通話操作と低帯域設定の統合.md)の成功とは分ける。

実機では複数window／Stage Manager・外部入力機器・VoiceOverの差分を確認する。サイズ・英日・回転・sheet操作の既存自動試験と重複する全組合せの手動再試験は増やさず、端末固有の差と主要操作の到達性を記録する。
