# Widget・Control・Macメニューと通話状態表示

## 確定したWidgetの範囲

2026-11-01の利用者指定により、Widgetは**配置・設定時に指定した登録済みユーザーまたはグループへの通話専用リモコン**とする。Widgetからの通話先の新規登録・グループ作成・メンバー追加は提供しない。配置したWidgetの開始操作で、その設定先へ通話を開始できることを必須とし、毎回iPhoneで先に通話を開始することを求めない。

| 項目 | 契約 |
|---|---|
| 通話先 | Widgetの配置・設定時に保存済みユーザー／グループを選ぶ。通常操作で直近の別通話先へ自動変更しない |
| 操作 | 設定した相手への開始・終了・ミュート。別の通話先のリモコンへ自動的に変化しない |
| 未設定・削除済み | 設定先が必要であることを示す。別の相手・直近先で代用しない |
| Watchとの差 | [開発・検証用Watch](Watch操作.md)では保存済み一覧から個人を選べる。Widgetは配置時に選んだ1件を使う |

実装済み。Widgetは設定先だけを開始し、現在通話の終了・ミュートは同じ設定先の通話であることを確認して表示する。未設定・削除済み・投影欠落・別ログインでは別通話の操作を出さない。直近再開はWidgetから除き、iOS ControlとSiri／Shortcutsの独立した入口に残す。

## 表示の構成

選択通話Widgetは`systemSmall`を使う。背景は共通のbackgroundTop（ダークはdeepNavy）からbackgroundBaseへ変わるグラデーションとする。上段左に設定先の種別を記号と「ユーザー」または「グループ」で示す。設定先があるときは上段右にアプリアイコンの画像`ridecom.appicon.small`を22ptで置く。外観に応じてライト／ダークを使い、色付きの外観でも元の色を保つ。名前、現在状態、操作を表示する。名前は1行に収まる大きさ（縮めて切らない）。未設定では、上段左にアプリアイコンと「RideCom」を置く。案内は「長押しして接続先を設定」、操作は「接続先を選ぶ」。待機中は接続先の名前と全幅の「接続」だけを表示し、「未接続」という状態の語は出さない。Widget・Controlを追加したときは、Appが共有データに書いた前回の接続先を既定値にする（`WidgetCallDestinationQuery.defaultResult()`）。保存場所は`WidgetDestinationSnapshot`の`recentDestinationID`で、この値を持たない古いデータも読める。前回の接続先がない場合や、すでに削除された場合は未設定で始まる。通話中の名前は、同じ投影で設定先IDと現在通話先IDが一致した場合だけ表示し、名前を`privacySensitive`として扱う。状態は文字と記号を併用し、「Apple Watchで操作中」は文字を縮めて1行に収める。色付き・クリア外観やOSによる秘匿はWidgetKitに従う。

Live ActivityはRideCom、状態の記号と状態の語（会話中・接続中・音声停止中など。理由の補足は出さない）だけを表示し、ミュート中は通話のアクセサリと同じ「会話中・ミュート中」にする。「マイクオン／オフ」の文は置かない。Dynamic Islandの展開とcompactのtrailingではマイク状態を記号で示す。ロック画面とDynamic Islandではマイクや切断を操作せず、本体タップで通話画面を開く。ロック画面はdeepNavyの標準background tintと白文字、状態記号だけを意味色にする。Dynamic Islandでは展開のleading・center・trailingとcompact／minimalを使う。compactの接続中はwarningの静止した`progress.indicator`記号を使う。WidgetKit・Live Activityは静止画で、回転する`ProgressView`を表示できないためである。ミュートはdangerの記号、keylineはaccentを使う。WidgetとActivityの表示はOSホストと同じSwiftUI Viewを共用する。アプリの識別には共有Asset Catalogのアプリアイコンの画像`ridecom.appicon.small`（`RideComAppMark`）を使う。背景が暗いロック画面とDynamic IslandはDarkの画像に固定する。ロック画面と展開leadingは「RideCom」の文字と並べ、compact leading・minimalは画像だけにする。

Widgetの「接続」は`borderedProminent`、「接続先を選ぶ」は`bordered`を使う。WidgetKitのOSホストでglass系スタイルのラベルが表示されないため、操作可能な標準スタイルを使用し、独自のぼかしでガラスを再現しない。開始・補助の意味と44pt以上の操作範囲は維持する。

### 表示状態と操作

| 状態 | 選択通話Widget | Live Activity／Island |
|---|---|---|
| Ideal | 同じ設定先の通話状態と名前。ミュートToggleと、離して置いた切断 | 名前なしの状態文。Islandではマイク状態も記号で表示。本体をタップするとAppへ |
| Empty | 設定先なし／投影から消失した場合は、長押し設定の案内とChoose a call。別の宛先を代用しない | 通話がなければOS表示を開始しない |
| Loading | connectingはwarningの`progress.indicator`記号と文字、切断だけを残す | 接続中の文言と進行表示。破壊操作なし |
| Partial | 音声停止はwarningの記号と文字。Watch所有中はマイク操作を表示せず「Apple Watchで操作中」と切断 | 音声停止／Watchのマイク所有を文字と記号で示す |
| Error | 音声利用不能はdangerの記号と文字、現在通話を終了できる。保存先消失は設定し直す案内へ戻る | 音声利用不能を記号と文字で示し、Appを開いて確認できる |

操作は同じIntentへ表示中の参照と明示Boolを渡し、開始・終了・再接続のライフサイクルをUIへ増設しない。未設定から設定後の待機、開始から接続待ち／成立／音声停止、終了後の待機へ既存投影で戻る。Controlは、追加するときに接続先を選ぶ宛先Control（`RideIntercom.DestinationCall`、`SelectControlCallDestination`）と直近再開の2つ。未設定の宛先Controlは「接続先を設定」（`plus`）を表示し、Appを開く。待機中は接続先の名前と「接続」（`phone.fill`）を表示する。`OpenCallControlIntent(destinationID:)`は端末認証の後でAppを開いて接続を始め、別の通話を切り替えない。同じ宛先に有効な通話があれば、名前と投影された状態を表示する。接続中は `progress.indicator`（warning）、会話中は `waveform`（success）、音声停止中は `headphones`（warning）、音声の利用不能は `exclamationmark.triangle.fill`（danger）を使う。状態にかかわらず、タップでその通話を開く。接続先が削除されたら「接続先を設定し直してください」を示す。状態はAppが公開する宛先と現在通話の投影（`CallControlState`）から決め、Controlから切断しない（コントロールセンターはロック中も開けるため）。systemMediumはこの単位に含めない。

## 操作の所有者

Widget extensionは通話やアカウントのモデルを生成しない。選択通話Widgetの操作には`BackgroundCallControlIntent`を使い、`.background`と`allowedExecutionTargets = .main`でApp本体へ実行を渡す。Intentは追加の端末認証を要求しない`.alwaysAllowed`を指定する。施錠中のWidgetKitのボタン／ToggleはOSの認証と解除に従い、AppのAppleログイン・保存関係・利用条件も適用する。Controlは前面実行と端末認証を要求する`OpenCallControlIntent`を使う。Appが登録した`CallSurfaceActions`は同じ`AppCallOwner`であり、保存先・ログイン・共通の利用権条件を実行時に再確認する。OS経由の受入は[未確認事項](../../validation/未確認事項.md)で管理する。

WidgetとControlからの開始をAppが拒否したときは、開始処理の理由を `CallIntentError` としてIntentへ返す。App所有者は、開始処理が返した通話参照と現在の通話が一致する場合に、画面表示を更新して成功を返す。マイクが許可済みで、登録を待てる相手への発信を受け付けた場合も、通話準備画面に操作を引き継ぐ。別の宛先を指定したときは待機中の発信を保つ。Siri／ショートカットもこの照合を使う。[マイク許可の条件](音声処理仕様.md#マイク許可と音声準備)・[端末登録を待つ発信](通信仕様.md#通常サインインからインターネット通話の端末を登録する)

端末登録の本人確認が必要な場合は、既存のIntentのエラー表示で、RideComで同じ相手を選び「Appleで続ける」を使うよう案内する。本人確認に進める条件は[端末登録の仕様](通信仕様.md#通常サインインからインターネット通話の端末を登録する)に従う。

WidgetとControlで保存先への開始を求めたときは、同じAppの開始処理に保存先IDを渡す。開始操作にIDが欠けていた場合、Appは現在のログインを照合し、保存先の選び直しを案内する。Siri／ショートカットで保存先を指定した場合も、Appが同じ手順で現在の保存先を探す。

Siri／ショートカット、Widget、Controlの開始・直近再開は、[通話先の共通判定](通信仕様.md#通話先と操作対象の共通境界)に従う。別の通話が接続待ちまたは進行中なら現在の通話を保つ。その通話を理由に開始を拒否した場合は、現在の通話を終了してからやり直すよう案内する。

| 入口 | 現行動作 | 対象の境界 |
|---|---|---|
| 特定通話先Widget | Widgetの編集で保存ユーザー／通常groupを選び、Start callでAppの共通操作で開始 | 現在の選択用投影を読み直し、削除・破損・未選択ならAppの通話画面へ戻る。古いconfiguration内の名前や対象をfallbackとして使わない |
| 特定通話先Widgetの通話中操作 | Widget編集で選んだ保存ユーザー／通常groupの終了・ミュートを表示する | 現在通話の宛先IDが設定先IDと一致し、現在の投影にも設定先がある場合だけ終了・ミュートを表示する。別通話・未設定・削除・別ログインでは表示しない |
| iOS Control | 宛先Control（設定した接続先へ接続、接続中は通話を開く）／直近再開の独立したボタン | 同じ共有IntentとApp所有者を使用。直近再開はSiri／ショートカットと同じ[開始処理](通信仕様.md#直近の成立済み通話先)を使う。切断は置かない |
| Live Activity | ロック画面・Islandの本体タップから`rideintercom://call`で通話を開く（iPhoneはシート） | マイク切替・切断は選択通話Widgetなどの操作入口で行う。URLは通話の表示だけを行う |

WidgetはiOS/macOS、ControlとLive ActivityはiOS targetに含む。すべての製品targetの最低OSは27.0。開始は[通話先と操作対象の共通境界](通信仕様.md#通話先と操作対象の共通境界)に従う。終了・ミュートは表示した[`CallSurfaceReference`](../packages/CallControl.md)を現在の通話と照合し、古い表示や待機中の参照では実行しない。重複を受け取っても同じ値を保つよう、ミュートには明示Boolを渡す。

### CarPlayのボタン操作

| 条件 | 現行の扱い |
|---|---|
| 27.0以降・タッチ対応CarPlay | 小型Widgetの開始・終了・ミュート／解除を背景Intentへ渡す。対応OS共通の経路を使う |
| 表示幅と読み上げ | 各操作を44pt以上とし、ミュートは記号と短い語（caption・semibold、収まらなければ縮める）を横並びのカプセルに収める。ミュートと切断の間は12pt離す（[デザインシステム](../../design/デザインシステム.md#端末ごとの補足)の下限で、ミュートの語の幅を優先する）。ミュートはネイティブToggle（`.button`）の同一`mic.slash`記号とMute／Mutedの状態文で、ミュート中だけdangerの塗りに白い文字、解除中は中立の`.fill.tertiary`のカプセルとする。切断はdestructiveのButtonで、赤い記号を中立の塗りに置き、縁をdanger 45%の細線にする（ミュートがあるときは44ptの円、接続中・Watch所有中は文字付きのカプセル）。ミュート中の赤い塗りと並べても見分けられる。大きさと塗りを見本どおりに固定するため、どちらも`.plain`のボタンに標準の形（`Capsule`）の背景を付ける。見本のガラスは画面外の描画（試験の画像）に出ないため、中立の塗りで代える。読み上げ名・ミュート値と宛先の一致を保持する |
| 未設定・削除済み | Choose a callはHome画面・Mac向けの前面導線。専用CarPlay Appのない車載で機能する背景操作とは扱わない。CarPlayでの利用前にiPhoneのWidget編集で保存先を選ぶ |
| 非タッチCarPlay | WidgetのButton／Toggle操作はOS非対応。表示できることを操作可能とは扱わない |
| CallKit・専用CarPlay App | 採用しない。電話型の発着信UI・VoIP Push・communication entitlementを追加せず、既存インカムを操作する |
| マイクと実行時間 | `.main`は実行先の指定であり、背景マイク開始や接続成立までの実行時間を付与するAPIではない。新規開始、停止後の解除、cold launchは実車／実機の別受入。失敗時に電話型の経路へ切り替えない |

[AppleのCarPlay Widget条件](https://developer.apple.com/documentation/widgetkit/adding-standby-and-carplay-support-to-your-widget)と[App Intentの実行先](https://developer.apple.com/documentation/appintents/intentexecutiontargets/main)を適用する。Live ActivityのCarPlay表示は非対話であり、Widgetボタンの代替にしない。

### 画面を開かないアカウント確認

Apple credential失効通知の購読と、ログイン世代変更時のVM停止・置換は`AppCallOwner`が所有する。ContentViewの生成を前提にしない。背景での開始・ミュート解除前に保存状態の再読込とApple credentialを確認し、await前後で本人・access ID・同じVMと通話参照が一致することを確認する。確認待ちの間に終話・切替があれば古い開始要求を拒否する。終了・ミュートは外部のcredential確認を待たず、既存の現在ログインと通話参照の検査から共通停止操作へ渡す。サインアウト・削除・別ログインへ遅れた旧操作を渡さない。Appleの確認通信が失敗した場合の、以前成立したログインをオフラインで使える方針は維持する。

iOSの通話用Keychain資格は初回解除後に利用できる`AfterFirstUnlockThisDeviceOnly`とし、既存itemは読込成功時に属性だけを揃える。MacのKeychain保護は変更しない。group manifest・lock・Widget投影は初回解除後のファイル保護を使う。初回解除前や読込不可は失敗として戻し、鍵の再生成・空データへの置換で回復した扱いにしない。

## 通話状態の投影

| 項目 | 現行仕様 |
|---|---|
| 初期値と保存 | `liveActivityEnabled=false`。アカウント別UserDefaultsの`RideIntercom.settings.liveActivityEnabled`へ保存し、音声設定保存・Reset All Settingsでは維持する。アカウントデータ消去では消す |
| 表示内容 | 現在通話中のgroupに対する共通`callStatus(for:)`とミュート値だけ。閲覧中の別groupの状態へ切り替えず、本人・相手・groupの名前を出さない |
| 開始 | 設定ONかつApp前面で有効な通話投影がある場合、ActivityKitへ要求する。背景では新規要求しない |
| 更新 | 同じ投影の再送を抑止。状態変更時は背景でも更新し、Appの通話状態を正とする |
| 停止 | OFF、サインアウト、対象通話消失で表示を終了。表示側から媒体処理を停止しない |
| OSによる終了 | 利用者による消去・OSの終了（Live Activityの8時間上限を含む）では同じ通話の表示を自動再生成しない。次の通話または明示OFF→ONで再試行する |
| 失敗・再起動 | 表示要求失敗はSettingsで案内し、通話を継続。次回プロセスは前回の表示を先に終了し、それを通話復旧の証拠にしない |
| 非表示の意味 | OFFはAppが追加するLive Activityだけを対象とし、OSのマイク利用表示などを隠さない |

Appの`CallLiveActivityPresenter`が表示更新を直列化する。延滞した旧開始が完了しても、旧表示を終了してから次の通話へ更新する。`CallSurfaceReference`は対象照合のUUIDだけで、Apple識別子・秘密鍵・group鍵・通知資格を含めない。

Appleの[Widget操作](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities)、[Control](https://developer.apple.com/documentation/widgetkit/creating-controls-to-perform-actions-across-the-system)、[Live Activity](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)の契約を適用する。

## 特定通話先の選択用共有

| 境界 | 現行仕様 |
|---|---|
| App Group | `group.com.yowamushi-inc.RideIntercom.CallWidgets`をAppとWidgetのentitlementへ指定。`containerURL(forSecurityApplicationGroupIdentifier:)`配下の`call-destinations.json`を使用。実profile・Developer portalの登録は[受入条件](../../validation/未確認事項.md)で別管理 |
| 書込所有者 | Appの`WidgetDestinationPublisher`だけ。Appはログイン中の既存`callTargets`から保存ユーザー／通常group、現在通話の宛先・状態と直近の宛先を1つの値に組み立てる。Publisherはその値でアトミックに書き込む。iOSではUntilFirstUserAuthenticationのファイル保護を指定する。extension targetにはwriter実装を含めない |
| 共有する内容 | schema version、宛先ID・表示名・user/group種別、現在通話の宛先ID・参照・状態・ミュート値と自動切断時刻。既存の宛先IDが持つ端末の本人識別子でアカウント境界を保つ。現在通話に名前を付けず、Appleの生識別子、署名鍵、group鍵、購入状態、通知capabilityを共有しない |
| group内だけの参加者 | Usersへ登録せず、Widget候補にも出さない。通常group自体は候補に含める |
| 候補と表示 | `WidgetConfigurationIntent`と`EntityStringQuery`で現在の投影を読む。Widgetと宛先Controlは、表示時に共通の処理で設定先のIDを照合し、現在の名前と期限内の同じ宛先への通話を得る。選択済み宛先名は`privacySensitive()`を付ける |
| 再読込 | 通話終了・宛先の改名や削除・サインアウトなどで投影が変わったとき、選択通話先Widgetのタイムラインと、iOSの宛先Controlにそれぞれ再読込を要求する。要求する時点は保存または失敗時の削除試行の後とする。OSが再読込して表示を切り替えるまでの時間は実機で確認する |
| 自動切断時刻 | WidgetとControlはAppが通話開始時に決めた時刻まで、同じ宛先の通話中状態を表示対象とする。時刻に達した場合や時刻のない投影では、保存された宛先の接続操作を表示対象とする。Widgetはタイムラインに切替時刻を含め、Controlは状態を読み直す際に現在時刻と照合する |
| 実行時 | 共有JSONや過去のWidget表示を認可の根拠にせず、App所有者が[共通の開始操作](通信仕様.md#通話先と操作対象の共通境界)で現在のログインと宛先を照合する |
| 読込失敗 | 共有container不在、ファイル破損、未知version、重複ID、1MiB超は空一覧。端末で管理する元データを削除せず、Appへ戻る操作を残す |
| 書込失敗・復旧 | 過去投影の削除を試み、次の前面復帰／一覧変更で再公開する。成功した投影とファイルが一致していれば、WidgetとControlへの再読込要求を省く。同じ投影でもファイルが破損・欠落していれば修復して再読込を要求する。通話は維持する |

Appleの[設定可能なWidget](https://developer.apple.com/documentation/widgetkit/making-a-configurable-widget)、[タイムライン](https://developer.apple.com/documentation/widgetkit/timeline)と[App Group設定](https://developer.apple.com/documentation/xcode/configuring-app-groups)を使用する。OS27専用のquery実行先指定には依存しない。

## iPadとMacへの表示

iOS AppとWidgetの対応familyはiPhone・iPad。iPadでは対応するロック画面など、OSが提供する場所へ表示し、Dynamic Islandの有無で通話動作を変えない。Widgetはnative macOS targetにも含む。

27.2 SDKのActivityKitはmacOSからのActivity開始をunavailableとする。iPhoneで開始したLive Activityは、[Appleの共有条件](https://support.apple.com/en-ca/120684)を満たすMacのメニューバーへOSが表示する。この表示が表すのはiPhone側の通話であり、Macアプリの通話状態ではない。Mac自身の状態表示には、同じApp所有者に接続した標準`MenuBarExtra`を使用する。これはplatform APIの差であり、OS最低対応バージョンを分ける理由にはしない。

## Macメニューバー

| 境界 | 現行仕様 |
|---|---|
| 設定 | `menuBarEnabled=false`。アカウント別UserDefaultsの`RideIntercom.settings.menuBarEnabled`へ保存。Settingsの共通Call status display sectionにMac用の1スイッチを表示し、音声設定リセットでは保持、アカウントデータ消去では消す |
| 表示 | ログイン中かつ設定ONの間、標準`MenuBarExtra`のmenu styleで表示。アイコンはAppのカスタムシンボル`ridecom.glyph`を`.hierarchical`で描き（吹き出しの層が半透明になり下の道が見える）、ミュート中だけ`mic.slash`（label「RideCom」）。通話がない場合もAppへ戻れる。氏名・group名・資格は出さない |
| 状態 | `AppCallOwner.currentLivePresentation`から現在の通話の`callStatus(for:)`とmuteを取得する。つながっていない状態（`ready`）は通話がないときと同じ「通話していません」で、ミュート・切断を出さない。接続待ち・成立済み・音声停止を同じ状態で区別し、閲覧中の別groupへ追従しない |
| ミュート | メニューに表示した通話参照と明示Boolを共通`setCallMuted`へ渡す。重複操作で反転せず、古いログイン／接続の操作は拒否 |
| 終話 | 表示した`CallSurfaceReference`を既存の共通終了操作へ渡す。古いメニューの操作で、新しい通話を終了しない |
| Appへ戻る | Open RideComで既存のmain WindowGroupと通話を表示。別のVM・通話セッションを生成しない |
| OFF・サインアウト | 表示を外すだけ。OFFで通話を終了しない。サインアウト時の通話終了は既存のアカウントlifecycleが所有する |
| 更新 | SwiftUIの既存Observationで現在状態を読む。ネットワーク照会、周期timer、別の通話状態保存は追加しない |

Appleの[MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)と[Menus HIG](https://developer.apple.com/design/human-interface-guidelines/menus)を使用する。ActivityKitをMacで起動せず、iPhoneから共有されたLive Activityとは別にMac自身の通話を示す。iPhoneのLive Activityが対応Macのメニューバーへ共有される。[Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities)、[Macへの共有条件](https://support.apple.com/en-ca/120684)。この共有は、Mac自身の通話を表示する仕組みや最低OSを引き上げる理由として扱わない。通常のDock／main windowを維持し、メニューだけのアプリには変えない。OSの実メニュー操作とVoiceOverの受入は[未確認事項](../../validation/未確認事項.md)へ分ける。

## 検証構成の隔離

システム表示は生成Infoの `StorageNamespace` が通常版の `RideIntercom` と完全一致する場合だけ許可する。欠落、未展開、検証用保存先ではApp Groupを解決する前に拒否する。この判定をWidgetの読取・書込・reload、Live Activityの開始・更新・終了一覧へのアクセス、OS通知に使う。Release構成の音声E2Eにも同じ判定を適用する。Watch連携はこの通常版の判定に加え、[録音確認専用の試験経路](Watch操作.md#録音確認だけを行う試験構成)を持つ。
