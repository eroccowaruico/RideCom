# 開発方針に反映した個別要求

## 設計と検証の要求

- 2026-11-06に、StandardとAdvancedの目的に応じた設計原則をすべての画面に適用するよう指定された。11月15日には同じ部品の片側だけが変更される不整合を防ぐため、表示・語・配置・操作がすべて同じ場合に共通化する条件が加わった。[現在の設計原則](../../policies/開発方針.md#standardとadvancedの設計の絶対ルール)
- 11月20日に、対象・要求・影響範囲・所要時間で試験を選べる構成と、製品の実装後に利用者が行う外部設定の引き継ぎが求められた。試験の分類にCI新設・有料実行は含まれていなかった。[試験の残作業](../../backlog/未実装課題.md#テストを対象要求影響と所要時間で選択実行できるようにする)、[外部設定の引き継ぎ](../../backlog/未実装課題.md#appサーバー実装を揃えてapplecloudflareの設定手順を引き継ぐ)
- 11月21日に、コード、仕様、コードの再整理、デザイン・ユースケース、テストという全体整理の順序と各回の独立した受入が指定された。初回の着手対象はバックログのコード全体の簡素化だった。テスト点検の追加時には対象と受入条件を記録し、構成の変更、全試験の実行、CIの新設は依頼の範囲外とした。同日、既存の画面・文書で短縮により失われた意味の修復も最重要課題の1つに指定された。[全体整理の周期](../../policies/開発方針.md#全体整理のサイクル)、[表現の修復とレビューの残作業](../../backlog/未実装課題.md#画面と文書全体の意味が痩せた表現を修復する)

## 署名付きArchiveをOrganizerで利用する

2026-11-21の依頼では、実行中の変更を安全に閉じた後、普段のコマンドで作る署名付きArchiveをOrganizerに登録する対応を最優先とした。iOS Build 1830とMac Build 1832は一覧への表示を利用者が確認した。選択後の詳細照合は[検証待ちの対象と条件](../../validation/未確認事項.md#organizerで署名付きarchiveを選んだ後の詳細を照合する)で追う。

## 開発環境の異常終了

2026-11-21に、PCの通常利用を妨げる異常終了が報告された。原文の「postr board」「spring board」はプロセスを特定する手掛かりだった。PosterBoardやSpringBoardを含め、アプリ本体と利用中のツールも調査対象とした。発生時の正式名称・環境・原因は実際の記録で確かめる。[未解決の発生条件と再発防止](../../backlog/未実装課題.md#異常終了を継続監視しpc利用を阻害する再発を抑える)
