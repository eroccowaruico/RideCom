# RideCom 招待と登録の設計

## 指示と背景

[バックログ](../backlog/README.md)の2026-11-04の課題で、個人招待の修復が最優先になり、招待・削除の同期と呼び出せる相手の制限がデザイン課題として渡された。本書はStandardのUX（[UXの定義](一般向け/画面構成とレイアウト.md#uxの定義)の「仲間に入れたい」「招待がつながらない」「やめたい」「相手にやめられた」）の設計案である。Advancedは同じ記録（`ContactInvitationRecord`、削除の同期の記録）を[実装との対応表](詳細画面/診断と詳細画面の構成.md#実装との対応表)のとおり実装の値で表す。

## 共通の原則

| 原則 | 内容 | 根拠 |
|---|---|---|
| 成立したものだけを普通の行にする | ユーザー・メンバーの通常の行（青い人物アイコン、タップで接続）は、相互の登録が成立した相手だけ。成立前も同じ相手の行で、破線の人物アイコンと「未登録」を示す | 同期待ちを成立済みに見せない（バックログの受入条件） |
| 経路を語らない | 「インターネット」「近距離」「サーバー」など配送の経路を状態の語に使わない。「届けています」「届きました」だけで表す。経路と期限はAdvancedが実装の値として出す | 一般向けUIの理解に内部の経路を前提にしない（同上） |
| 一覧は短く、意味は詳細で | 一覧の補足は状態の語1つ。誰に対する何の操作かは、行をタップして開く「招待の詳細」で1文ずつ説明する | 未連携メンバーの識別・招待UIの要求 |
| 自動で届けることを基本にする | 返信・削除・グループの追加は、接続できる経路があれば自動で届ける。利用者の操作（「もう一度送る」）は、届いていない状態が続くときの手段 | 招待・削除同期の機能要求 |
| 古い操作を実行させない | 表示中に削除が届いたら、その相手・グループに対する操作をすぐ無効にし、画面を閉じるか状態を置き換える。送信直前にも共通処理で確認する | 削除同期の受入条件 |
| 削除で通知を出さない | 相手に削除された・グループから外されたことを通知で知らせない。次に一覧を見たときに反映されている | 不要な通知を発生させない（同上） |

## 個人の招待

### 仮名と名前

| 名前 | 意味 | 編集 | 表示する場所 |
|---|---|---|---|
| 仮名 | 招待を作るときに、相手の名前をまだ決められない人のための候補。「青いキツネ」のような自然な語の組み合わせ（[仮名の作り方](#仮名の作り方)）。名前の欄のプレースホルダーとして見せ、空のまま保存したときだけ使う | 招待の作成時と招待の詳細でいつでも編集できる。編集した名前は「呼び名」になる | 招待中の行、招待の詳細、「もう一度送る」で共有する文面 |
| 呼び名 | この端末の表示に使う相手の名前（現行の別名）。明示的に共有する招待の文面にも含む。相手のアプリの表示名は変えない | 相手の設定・招待の詳細 | 一覧・通話・通知 |
| 本人の名前 | 相手が自分で設定した名前。成立した時点で届く | 編集できない | 相手の設定・招待の詳細に「本人の名前」として補足で出す |

### 仮名から本人名への選択

2026-11-18。入力を空欄のまま保存して候補を採用したことを、`SavedUser.usesProvisionalName=true`で記録する。文字列が仮名の形式に一致するかで推測しない。手入力・名前の編集・本人名へ戻す操作は自動生成と区別する。旧データの由来が不明な場合は既存の呼び名を保ち、設定から変更できるようにする。

| 状態・操作 | 表示と結果 |
|---|---|
| 未登録／本人名未取得 | 確認を出さず、保存した仮名を保つ |
| 自動生成した仮名で登録済み、本人名と異なる | 同じ人の詳細・設定内で「「青いキツネ」を「マキ」に変更しますか？」。「本人の名前を使う」「この呼び名を使う」の2択。新しい画面を自動で開かない |
| 一覧で待機中 | 同じ相手の行の補足に本人名を添え、対応を見分けられる。登録済みの行のタップは従来どおり接続し、名前の確認で通話開始を止めない。確認は相手の設定からも行える |
| 本人の名前を使う | `localName=nil`として本人名へ追従し、確認済みを保存。同じID・詳細を保ち、後でSaveしても旧仮名へ戻さない |
| この呼び名を使う | 現在の仮名をそのまま保存し、同じ確認を繰り返さない |
| 選ばず閉じる／アプリ終了 | 仮名と未確認を保存し、次に同じ人の詳細・設定を開くと続けられる。通話・ミュート・招待・本人の識別子は変えない |
| 明示編集済み／本人名と同じ／既に選択済み | 自動の確認を出さず、保存した選択を保つ。再招待でも上書きしない |
| 保存失敗／確認中に名前が変わった | 元の名前と未確認を保持。表示した旧名・本人名の一致を保存直前に確認し、変わっていれば再確認する |

どちらの選択もその場で保存し、詳細・設定を勝手に閉じない。設定では保存済みの選択後は「完了」だけにし、新しい文字入力を編集した場合に「キャンセル」「保存」へ戻す。未保存の編集がある間は2択を出さず、別の名前を上書きしない。本人名への追従は入力を空欄にして本人名をプレースホルダーにする。

Advancedは`usesProvisionalName`と派生値`needsNameConfirmation`を実装どおりに表示し、`Use Shared Name`／`Keep Local Name`を同じ保存操作へ接続する。Standardは利用者が選ぶ2つの名前と結果だけを示す。既存の手編集名は自動で上書きしない。上の設計に対する保存とUIの検証は各実装単位の記録で区別する。

### 仮名の作り方

2026-11-06の利用者指示により、招待を作るときは最初に相手の名前を入れてもらう（[招待の作成](#招待の作成)）。仮名はその場で名前を決められない人のための候補で、記号や英数字の符号ではなく自然な語の組み合わせにする。色の語と生き物の語を1つずつ組み合わせる。

| 条件 | 内容 | 理由 |
|---|---|---|
| 形 | 「{色}{生き物}」。日本語は「青いキツネ」「白いカモメ」、英語は「Blue Fox」「White Gull」 | 読んで・聞いて自然で、覚えやすい。OSの通知の読み上げ（[通知の設計](通知の設計.md#受け取る側の表示)）でも聞き取れる |
| 人の名前に見せない | 人名・あだ名に使われる語を使わない | 成立後に届く本人の名前と取り違えない |
| 意味 | 否定的・失礼な意味、体型や見た目を言う語、食べ物、季節に偏る語を使わない | 相手に共有の文面で見えるため。バイクとスキーのどちらの季節にも合う |
| 重ならない | 今の招待中の仮名・保存ユーザーの呼び名と同じ組み合わせを選ばない。すべて使っている場合だけ末尾に数字を付ける（「青いキツネ 2」） | 一覧で見分けられる |
| 言語 | 招待を作った端末の言語で作り、その文字列を呼び名として保存する。後から言語を変えても書き換えない | 呼び名は利用者の端末の文字列として扱う（翻訳しない名前の規則） |

| 色（日本語／English） | 生き物（日本語／English） |
|---|---|
| 青い／Blue、白い／White、緑の／Green、黄色い／Yellow、銀色の／Silver、金色の／Golden、茶色の／Brown、空色の／Sky | キツネ／Fox、カモメ／Gull、ウサギ／Rabbit、リス／Squirrel、ツバメ／Swallow、クジラ／Whale、ライチョウ／Ptarmigan、シカ／Deer、イルカ／Dolphin、フクロウ／Owl、ペンギン／Penguin、カワセミ／Kingfisher、ハヤブサ／Falcon、ヤマネ／Dormouse |

8色×14種で112通り。語の追加・削除は上の条件で確かめてから行う。

### 招待の作成

2026-11-17の利用者指示を反映する。名前の保存と招待の共有を分け、共有画面を閉じただけで送信・登録の成功を表示しない。以下を保存・画面の実装に適用し、検証範囲は[保存と共有の分離](../validation/history/名前の保存と招待共有の分離.md)へ記録する。

| 利用者の意図 | 見えるもの・すること | アプリが引き受けること | 見せないもの |
|---|---|---|---|
| 相手を覚えておきたい | ＋で「相手を追加」。名前と候補、下端の「保存」。取消は「キャンセル」 | 保存まで無書込。空欄なら表示中の候補で保存。成功後、同じシートを保存済み詳細に切り替える | 名前の暗黙保存、共有の強制、保存前の招待発行 |
| 招待したい | 保存済みの名前、「未登録」、「招待を共有」 | OS共有画面を開く。共有画面を閉じても同じ詳細へ戻す | 「送信済み」や到着・受諾の推測 |
| いったん終えたい | 保存済み詳細の「完了」 | 詳細だけを閉じ、同じ相手を一覧に1行で残す | 保存済みなのに「キャンセル」しかない状態 |
| あとで招待したい | 一覧の未登録の相手をタップ | 同じ相手の詳細と「招待を共有」を開く。通話は開始しない | 再入力・重複する招待行 |
| 相手が登録したか知りたい | 同じ相手の行・詳細の「登録済み」 | 検証済みの受諾を保存した時だけ更新。詳細は閉じない | 返信用の技術記録を別の相手のように表示すること |
| 招待を受け取った | 相手の本人名、「登録」「拒否」 | 登録は初めて保存し、同じシートを登録済み詳細へ更新して返信を開始。「返信を共有」または「完了」で続ける。拒否は保存せず閉じる。元のリンクは有効期限まで再利用できる | 拒否記録、相手への拒否通知 |

### 招待の状態

相手の正本は保存した人1件とする。招待の配送記録はその人に紐づけ、一般向けの一覧へ別行として足さない。別々の相手を名前だけで統合しない。相手の識別がまだない保存は通話・グループ追加・通知許可の対象にしない。

| 状態 | 表示 | 可能な操作・次の状態 | 閉じる・再開 |
|---|---|---|---|
| 入力中（未保存） | 名前の入力欄、候補、保存 | 保存成功で未登録。失敗は入力を保って同じ画面に理由 | キャンセルで無書込。画面外タップ・スワイプでは閉じない |
| 保存済み・未登録 | 確定した名前、「未登録」、「相手が登録すると通話できます。」 | 招待を共有。共有開始・取消・コピー・共有先アプリへの引渡しはいずれも未登録のまま | 完了で一覧へ。同じ行から詳細を開ける。再起動しても名前と同じ人のIDを保持 |
| OS共有画面が開いている | OSの共有先選択 | 取消でも共有操作後でも、同じ保存済み詳細へ戻る。名前は編集状態へ戻さない | 親の詳細は閉じない。共有操作を保存や登録の条件にしない |
| 相手の受諾を確認・保存できた | 同じ人の「登録済み」、本人の名前 | 招待の共有を外す。手動の返信を受領した場合は同じ詳細・設定から到着確認を共有できる。本人名への選択は[仮名の確認](#仮名から本人名への選択)に従う | 開いている詳細を保ち、完了で一覧へ。行のタップは通話開始へ切り替わる |
| 受け手の登録後、返信が未配送 | 保存済み相手の詳細内に「返信が届いていません」または配送中 | 現在の通話を維持して返信を再試行するか、OSの共有先へ「返信を共有」。共有だけでは配達待ちを保ち、検証済みの到着確認で補足を外す | 相手を重複表示しない。返信記録は再起動後も保持 |
| リンク期限切れ | 人は未登録のまま。古いリンクの共有をしない | 次の「招待を共有」で新しいリンクを同じ人へ紐づける | 保存した名前・人のIDを保つ |
| 保存・署名・共有用リンクの準備失敗 | 対象の詳細に理由 | 同じ相手に対して再試行 | 人や名前を消さず、別画面へ進めない |

「未登録」は、まだ相手の受諾をこの端末で確認できていない意味である。共有先の選択・コピー・OSの完了通知から相手の到着や登録を推測しない。名前は「保存」を押したときだけ確定し、focus移動・Return・シートの終了では保存しない。保存・共有の主要操作はキーボードの上を含む下端の操作領域に置く。

### 通信を使わずに返信する

2026-11-18。登録した受け手は同じシートの保存済み詳細に留まり、そのまま「返信を共有」を選べる。通信がつながらなくても待たずにOS共有を開ける。「完了」で終えても同じ人の設定から続けられる。Internet資格・通知登録・通常通話を返信共有の条件にしない。

| 利用者の意図・状態 | 見えるもの・すること | 保存と復帰 |
|---|---|---|
| 登録して返信したい（Partial） | 登録済みの同じ相手の詳細に返信状況、「返信を共有」、相手の名前。OSの共有先を選ぶ | 登録と返信は保存済み。同じシートを保ち、共有取消・コピーでは配達済みにしない |
| 通話中に返信したい | 自動配送は通話終了待ち。「返信を共有」は利用可能 | 通話・音量・ミュートを維持して共有し、同じ詳細へ戻る |
| 元の作者が返信を受け取った（Ideal） | 元の同じ人が登録済みへ更新。「返信を受け取りました」「到着確認を共有」 | 署名と元の招待を検証して保存する。共有経由の受領をreceivedBySharingで保持し、この場合だけStandardに到着確認を出す |
| 受け手の返信待ちを終えたい | 作者が到着確認を共有。受け手はそのリンクを開く | 開いた端末で検証・保存後に返信状況を外す。コピーや共有先への引渡しだけでは解消しない。開いている詳細・設定は保つ |
| 選ばず閉じる・再起動（Partial） | 同じ相手の設定で返信／到着確認を共有できる | 元のIDと署名済みの保存を使い、新しい人や招待を作らない |
| 期限・取消・削除（Empty） | 共有対象を出さない。有効な新しい招待から登録し直す | 古い返信で登録を戻さない。削除・取消前に開いた共有からも書き出さず、重複応答用の内部記録とは区別する |
| 準備・保存・検証失敗（Error） | 同じ画面に案内。保存状態を保って再確認・再読込後に再試行 | 未確認の相手を登録せず、失敗時に成功や配達を表示しない |
| Loading | OS共有と実際の有限な自動配送だけ | URL準備のための独自待機画面・timerを作らない |

通常の近距離交換ではACKを自動で返すため、手動の到着確認は追加しない。手動共有は同じreceiptとACKを使う回復経路で、新たな拒否通知や通話開始を行わない。Advancedは方向・状態・receivedBySharing・canResumeをそのまま示し、Share Accepted Receipt／Share Acknowledgementを条件に対応付ける。

### 一連の操作の確認

実装前に、以下の操作列で途中の目的と復帰先が変わらないことを確認する。HTMLは入力中・保存済み詳細を同じ順で示す。HTMLの静的見本だけをOS共有画面や実アプリの動作確認と扱わず、実装後は同じ列をnative UIで実行する。

| 操作列 | 各段階で確かめる結果 |
|---|---|
| ＋ → 名前入力 → キャンセル | 保存も招待発行もされず、一覧へ戻る |
| ＋ → 名前入力 → 保存 → 完了 → 同じ行 | 保存直後に確定した名前が見える。共有せず終えられ、再表示しても同じ人 |
| 保存 → 招待を共有 → 何もせず取消 → 招待を共有 | 親の詳細・名前・人のIDが変わらず、続けて共有できる |
| 保存 → 招待を共有 → コピー → 完了 → 再起動 | コピーを「送信成功」にせず、未登録の同じ1行と名前を保持 |
| 詳細を表示中 → 他アプリ → 復帰 → 相手の受諾確認 | 画面を勝手に閉じず、同じ詳細が登録済みになる。通常通話・ミュートは維持 |
| リンクを開く → 拒否 → 同じリンクを開く → 登録 → 返信を共有 → 完了 | 拒否時は無書込。登録後は同じシートが詳細になり、共有取消・コピーで閉じない。相手への拒否通知はない |
| 保存失敗 → 修正・再試行／期限切れ → 再共有 | 入力・保存済みの名前と人のIDを保持し、その場で回復できる |

### 招待の詳細

Standardは名前・状態・目的に必要な操作だけを表示する。Advancedも人の正本を同じにし、`SavedUser`の`id`・`memberIDs`・`principal`と、その人に対応する`ContactInvitationRecord`の`id`・`direction`・`state`・`expiresAt`・`session`を詳細内で表す。共通にするのは保存・共有・登録の操作と、表示・語・配置が完全に同じ部品だけとする。

Idealは登録済み、Emptyは保存前、Partialは未登録または返信未配送、Errorは保存・検証失敗とする。ローカル保存は同期処理なので独立したLoading画面を作らない。返信中だけ共通の実際の接続状態から進捗を出し、未登録の相手を無期限のスピナーにしない。通知は通常のAPNsとUserNotificationsを使い、CallKit・VoIP Push・Apple PushToTalkは使わない。

## グループへの招待

[操作の語の意味](デザインシステム.md#操作の語の意味)により、グループに仲間を入れる意図は1つの入口「メンバーを招待」にまとめる。相手が個人で登録済みか、まだ新しい人かで利用者の操作を変えず、届け方の違いはアプリが引き受ける。

### メンバーを招待のシート

| 要素 | 内容 |
|---|---|
| 入口 | 通話のシートのメンバー一覧の下の「メンバーを招待」、グループの設定のメンバー一覧の「メンバーを招待」、新しいグループの作成。どの入口でも同じシート・同じ動き |
| 見出し | メンバーを招待（新しいグループの作成では「新しいグループ」） |
| 自分のユーザー | 見出し「あなたのユーザー」。まだメンバーでない保存ユーザーを並べ、選ぶだけ（行は[接続先のアバター](デザインシステム.md#共通コンポーネント設計案)・名前・選択の印）。行ごとの補足・鉛筆・削除を置かない |
| 新しい人 | 同じ一覧の最後に「新しい人を招待」の行。押すと名前の入力欄（プレースホルダーは仮名の候補。[招待の作成](#招待の作成)）が一覧に1行増え、選んだ人として数える。何人でも増やせる |
| 人数 | 一覧の下に「自分を含めて{n}/8人」（選んだ新しい人を含む） |
| 主要操作 | 「招待を送る」（既存グループへ招待するときは1人以上選ぶまで押せない）。新しいグループは生成名を編集でき、有効な名前と人数上限を満たせばメンバー未選択でも「作成して接続」、別の接続中は「グループを作成」 |

「招待を送る」を押した後の動き:

| 相手 | アプリがすること | 利用者に見えること |
|---|---|---|
| 保存ユーザー | 相手の一覧にグループを自動で届ける（[グループへの招待の配達](通知の設計.md#グループへの招待の配達)） | メンバー一覧に「招待中」で入り、補足「届けています」。届いたら通常のメンバー（未接続なら「接続していません」と「呼び出す」） |
| 新しい人 | 名前を付けた招待を作る。この招待は個人の登録とグループへの参加を兼ねる（受け入れると、お互いのユーザーにも入り、後から呼び出せる） | 新しい人がいるときだけ、続けて共有画面が開き、送り先を選ぶ。メンバー一覧に招待中として入り、ユーザーは同じ相手の「未登録」の行に対応付ける。受け入れられたら通常のメンバー |

招待だけでは呼び出さない。今すぐ来てほしい人は、メンバーの行の「呼び出す」で呼ぶ。シートの中に「リンクで招待」など手段の違いを見せる操作は置かない。宛先を持たないグループのリンク（開いた人が誰でも参加できる）はStandardに置かず、Advancedの`Share Call Invite`だけに残す。

保存ユーザーで相手の端末へまだ届かない人も、表示は「届けています」のまま（[招待・削除同期](../backlog/未実装課題.md#招待と削除の同期)で接続できたときに届ける）。

## 呼び出せる相手

グループの会話中に呼び出せるのは、送る人が個人で登録している人だけ。通知は直接の知り合いの間だけで届ける親切な知らせなので、それ以外の人には「呼び出す」を出さず、理由も代わりの操作も並べない。

| メンバーの状態 | 行の補足 | 行末 |
|---|---|---|
| 会話中 | 話しています等 | — |
| 未接続・個人で登録済み | 接続していません | 「呼び出す」 |
| 未接続・それ以外（グループでだけ会った、登録を解除した／された） | 接続していません | なし |

説明のfooter、行ごとの理由、長押しメニューの無効の「呼び出す」、グループからの「個人で招待」は置かない。グループの中から個人の招待を送れると、通知を直接の知り合いに限る意味がなくなるため。

表示中に相手の登録や許可が変わったら、行末の「呼び出す」をすぐ外す。押した時点で変わっていた場合は送らず、行の補足に理由の1文を出す。

## 削除と相手側への反映

### 削除の種類

| 削除 | 入口 | 確認のタイトル | 確認の本文 | 実行後の自分の表示 |
|---|---|---|---|---|
| ユーザーを削除 | ユーザーの行のスワイプ、相手の設定の最後のボタン | {呼び名}を削除しますか？ | {呼び名}の一覧からもあなたが削除され、お互いに呼び出せなくなります。同じグループのメンバーのままです。 | すぐに一覧から消す。反映待ちはStandardでは出さない |
| メンバーを外す | グループの設定のメンバーの行のスワイプ、メンバーの画面の最後のボタン | {名前}をグループから外しますか？ | {名前}の一覧から{グループ}が消えます。 | すぐにメンバー一覧から消す |
| グループを削除 | グループの行のスワイプと、グループの設定の最後のボタン（編集可能なオーナーだけ） | {グループ}を削除しますか？ | メンバー全員の一覧から{グループ}が消えます。 | すぐに一覧から消す |
| グループから抜ける | グループの設定の最後のボタン（オーナー以外） | {グループ}から抜けますか？ | ほかのメンバーの一覧からあなたが外れます。 | すぐに一覧から消す |

確認のボタンは「削除」（「メンバーを外す」は「外す」、「グループから抜ける」は「抜ける」、`role: .destructive`）と「キャンセル」。

#### 接続中の相手・グループを削除するとき

2026-11-06の利用者指示により、削除で今の接続が切れる場合は、切れることを確認の中で示してから実行する。

| 場面 | 確認の本文に加える文 | 確定のボタン | 確定後 |
|---|---|---|---|
| 1対1で接続中の相手を削除 | 今の接続は切断されます。 | 切断して削除 | 接続を切断してから削除する。相手側も接続が終わる（[相手側に届いたとき](#相手側に届いたとき)） |
| 接続中のグループを削除・グループから抜ける | 今の接続は切断されます。 | 切断して削除／切断して抜ける | 自分の接続を切断してから実行する |
| 会話に参加しているメンバーを外す | {名前}は今の会話からも外れます。 | 外す | 外したメンバーの接続はその人の端末で終わる。自分と残りの人の会話は続く |

キャンセルでは何も変えず、接続も維持する。確認を出している間に接続の状態が変わった場合は、確定の時点の状態で文を出し直さず、古い確認を取り消して閉じる。

#### 削除できる人

2026-11-11の利用者指示により、グループの削除はオーナー（グループを作った人）だけができ、オーナー以外はグループから抜けることだけができる。2026-11-17の利用者報告により、削除は編集可能なオーナーの一覧のスワイプにも置き、設定画面と同じ確認・取消・結果にする。抜ける操作はグループの設定から行う。メンバーの追加（招待）と外す操作は、有料の購入と同じ扱いの利用権を持つ人だけができる。判定はグループの作成と同じ共通判定（有料購入・有効な試用・無料チケット・TestFlightのいずれか。[グループ作成権](../backlog/未実装課題.md#購入と利用権の公開準備)、[通話利用権仕様](../spec/App/通話利用権仕様.md)）を使う（2026-11-06の「利用権を持つ人がグループを削除できる」を改める）。グループの会話中に呼び出せるのは、個人で登録している人だけ（[呼び出せる相手](#呼び出せる相手)）。

| 操作 | できる人 | できない人の表示 |
|---|---|---|
| グループを削除 | オーナー（グループを作った人） | 「グループを削除」を出さない |
| グループから抜ける | オーナー以外のメンバー | オーナーには出さない（オーナーはグループを削除する） |
| メンバーを招待 | 利用権を持つメンバー | 「メンバーを招待」を出さない |
| メンバーを外す | 利用権を持つメンバー | メンバーの行のスワイプとメンバーの画面に「外す」を出さない |

出せない操作の理由や説明のfooterは置かない。
| ユーザーを削除 | 全員（自分と相手の関係） | — |

利用権は操作の時点で確かめる。設定画面を開いている間に利用権が切れた場合は、押した時点で実行せず、footerの1文を出す。受け取った側の端末でも、削除・外す操作を送った人がその時点で利用権を持っていたかを機能側で確かめる（第三者による削除を防ぐ）。

### 相手側に届いたとき

| 届いた削除 | 一覧 | 開いている詳細・設定 | 開いている通話 |
|---|---|---|---|
| 相手が自分を削除した | 行が消える（アニメーションのみ。通知・バナーなし） | 内容を`ContentUnavailableView`「この相手は削除されました」と「閉じる」に置き換える | 1対1で会話中なら接続が終わる。状態ヒーローを「接続が終了しました」、補足を「{呼び名}との登録が解除されました」にし、主要操作を「閉じる」にする。触覚は接続の終了と同じstop。「呼び出す」は出さない |
| 自分がグループから外された | グループの行が消える | 同上「このグループから外されました」 | 接続が終わる。状態ヒーローを「接続が終了しました」、補足を「グループから外されました」にし、主要操作を「閉じる」にする |
| グループが削除された | グループの行が消える | 同上「このグループは削除されました」 | 同上。補足は「グループは削除されました」 |
| 同じグループの別の人が抜けた | メンバー数が変わる | メンバーの行が消える | メンバーの行が消える。会話は続く |
| 同じグループの別の人が外された | メンバー数が変わる | メンバーの行が消える | メンバーの行が消える。会話は続く |

### 反映待ちと期限

反映待ちは表示しない（削除した側ではすぐ消え、届けるのはアプリが引き受ける）。Advancedは、削除の同期を実装したときの保留の記録（種類・対象・作成時刻・期限・確認の有無）を、その型のフィールド名と値のまま[詳細表示のUsersとGroups](詳細画面/診断と詳細画面の構成.md#詳細表示のusersとgroups)に出す。表示の語は実装の型を先に決めてから合わせる。

## 現行との差と依存

| 項目 | 現行 | 本書の設計 | 依存 |
|---|---|---|---|
| 招待中の行 | directoryUsersで未登録も1行、personIDで配送記録を内包 | 保存前の入力から登録後まで同じ相手を1行で表示し、配送記録は詳細内へ | [個人招待の修復](../backlog/未実装課題.md#個人招待の仕上げ) |
| 名前・仮名 | 明示保存後、同じシートを保存済み詳細へ更新 | 明示的な保存後、共有せず完了できる。共有取消で入力へ戻さない | 同上（仮名の編集・保存・再表示後の対応） |
| 返信の送り直し | 「Retry」の明示操作。最大60秒で一時停止 | 自動で届け、届かない状態が続くときだけ「もう一度送る」 | [招待・削除同期](../backlog/未実装課題.md#招待と削除の同期) |
| グループへの招待 | 追加後に招待URLの共有を求める | 「メンバーを招待」の1つの入口で、登録済みの人へは自動で届け、新しい人へは名前付きのリンク（個人の登録を兼ねる）を送る | 同上と[group鍵の配達](../backlog/未実装課題.md#通知の残り)（暗号化方式は未決） |
| 呼び出せる相手 | グループ内の呼び出しは未実装 | 個人登録済み・許可ありの人だけに「呼び出す」 | [通知・呼出しの制約](../backlog/未実装課題.md#通知の残り) |
| 削除の同期 | 端末内だけの削除。相手側へ反映しない | 3種類の削除を区別し、相手側の一覧・詳細・通話を変える | [招待・削除同期](../backlog/未実装課題.md#招待と削除の同期) |

## 未決事項

| 事項 | 選択肢 | 決める場所 |
|---|---|---|

2026-11-06に利用者が決めた事項（グループの削除・抜ける・追加・外すの権限は2026-11-11に[削除できる人](#削除できる人)のとおり改めた）:1対1で接続中の相手を削除すると接続を切り、削除する側に切れることを確認する（[接続中の相手・グループを削除するとき](#接続中の相手グループを削除するとき)）。招待を作るときは最初に相手の名前を入れてもらい、仮名は決められない人のための自然な語の候補にする。候補は名前の欄のプレースホルダーとして見せ、空のまま保存するとその値になる（[招待の作成](#招待の作成)、[仮名の作り方](#仮名の作り方)）。自分の端末で1対1の接続を切り、相手のダイレクトグループも一緒に消す点は2026-11-15に実装した（[通信仕様](../spec/App/通信仕様.md)のユーザー更新、[Call画面仕様](../spec/App/UI/Call.md)）。通常グループには相手が残る。相手側の接続が終わることと相手の端末への削除の反映は[招待・削除同期](../backlog/未実装課題.md#招待と削除の同期)で扱う。
