## 共通の原則

| 原則 | 内容 | 根拠 |
|---|---|---|
| 成立したものだけを普通の行にする | ユーザー・メンバーの通常の行（青い人物アイコン、タップで接続）は、相互の登録が成立した相手だけ。成立前も同じ相手の行で、破線の人物アイコンと「未登録」を示す | 同期待ちを成立済みに見せない（バックログの受入条件） |
| 経路を語らない | 「インターネット」「近距離」「サーバー」など配送の経路を状態の語に使わない。「届けています」「届きました」だけで表す。経路と期限はAdvancedが実装の値として出す | 一般向けUIの理解に内部の経路を前提にしない（同上） |
| 一覧は短く、意味は詳細で | 一覧の補足は状態の語1つ。誰に対する何の操作かは、行をタップして開く「招待の詳細」で1文ずつ説明する | 未連携メンバーの識別・招待UIの要求 |
| 自動で届けることを基本にする | 返信・削除・グループの追加は、接続できる経路があれば自動で届ける。利用者の操作（「もう一度送る」）は、届いていない状態が続くときの手段 | 招待・削除同期の機能要求 |
| 古い操作を実行させない | 表示中に削除が届いたら、その相手・グループに対する操作をすぐ無効にし、画面を閉じるか状態を置き換える。送信直前にも共通処理で確認する | 削除同期の受入条件 |
| 削除で通知を出さない | 相手に削除された・グループから外されたことを通知で知らせない。次に一覧を見たときに反映されている | 不要な通知を発生させない（同上） |

## 個人の招待

### 仮名と名前

| 名前 | 意味 | 編集 | 表示する場所 |
|---|---|---|---|
| 仮名 | 招待を作るときに、相手の名前をまだ決められない人のための候補。「青いキツネ」のような自然な語の組み合わせ（[仮名の作り方](#仮名の作り方)）。名前の欄のプレースホルダーとして見せ、空のまま保存したときだけ使う | 招待の作成時と招待の詳細でいつでも編集できる。編集した名前は「呼び名」になる | 招待中の行、招待の詳細、「もう一度送る」で共有する文面 |
| 呼び名 | この端末の表示に使う相手の名前（現行の別名）。明示的に共有する招待の文面にも含む。相手のアプリの表示名は変えない | 相手の設定・招待の詳細 | 一覧・通話・通知 |
| 本人の名前 | 相手が自分で設定した名前。成立した時点で届く | 編集できない | 相手の設定・招待の詳細に「本人の名前」として補足で出す |

### 仮名から本人名への選択

2026-11-18。入力を空欄のまま保存して候補を採用したことを、`SavedUser.usesProvisionalName=true`で記録する。文字列が仮名の形式に一致するかで推測しない。手入力・名前の編集・本人名へ戻す操作は自動生成と区別する。旧データの由来が不明な場合は既存の呼び名を保ち、設定から変更できるようにする。

| 状態・操作 | 表示と結果 |
|---|---|
| 未登録／本人名未取得 | 確認を出さず、保存した仮名を保つ |
| 自動生成した仮名で登録済み、本人名と異なる | 同じ人の詳細・設定内で「「青いキツネ」を「マキ」に変更しますか？」。「本人の名前を使う」「この呼び名を使う」の2択。新しい画面を自動で開かない |
| 一覧で待機中 | 同じ相手の行の補足に本人名を添え、対応を見分けられる。登録済みの行のタップは従来どおり接続し、名前の確認で通話開始を止めない。確認は相手の設定からも行える |
| 本人の名前を使う | `localName=nil`として本人名へ追従し、確認済みを保存。同じID・詳細を保ち、後でSaveしても旧仮名へ戻さない |
| この呼び名を使う | 現在の仮名をそのまま保存し、同じ確認を繰り返さない |
| 選ばず閉じる／アプリ終了 | 仮名と未確認を保存し、次に同じ人の詳細・設定を開くと続けられる。通話・ミュート・招待・本人の識別子は変えない |
| 明示編集済み／本人名と同じ／既に選択済み | 自動の確認を出さず、保存した選択を保つ。再招待でも上書きしない |
| 保存失敗／確認中に名前が変わった | 元の名前と未確認を保持。表示した旧名・本人名の一致を保存直前に確認し、変わっていれば再確認する |

どちらの選択もその場で保存し、詳細・設定を勝手に閉じない。設定では保存済みの選択後は「完了」だけにし、新しい文字入力を編集した場合に「キャンセル」「保存」へ戻す。未保存の編集がある間は2択を出さず、別の名前を上書きしない。本人名への追従は入力を空欄にして本人名をプレースホルダーにする。

Advancedは`usesProvisionalName`と派生値`needsNameConfirmation`を実装どおりに表示し、`Use Shared Name`／`Keep Local Name`を同じ保存操作へ接続する。Standardは利用者が選ぶ2つの名前と結果だけを示す。既存の手編集名は自動で上書きしない。上の設計に対する保存とUIの検証は各実装単位の記録で区別する。

### 仮名の作り方

2026-11-06の利用者指示により、招待を作るときは最初に相手の名前を入れてもらう（[招待の作成](#招待の作成)）。仮名はその場で名前を決められない人のための候補で、記号や英数字の符号ではなく自然な語の組み合わせにする。色の語と生き物の語を1つずつ組み合わせる。

| 条件 | 内容 | 理由 |
|---|---|---|
| 形 | 「{色}{生き物}」。日本語は「青いキツネ」「白いカモメ」、英語は「Blue Fox」「White Gull」 | 読んで・聞いて自然で、覚えやすい。OSの通知の読み上げ（[通知の設計](通知の設計.md#受け取る側の表示)）でも聞き取れる |
| 人の名前に見せない | 人名・あだ名に使われる語を使わない | 成立後に届く本人の名前と取り違えない |
| 意味 | 否定的・失礼な意味、体型や見た目を言う語、食べ物、季節に偏る語を使わない | 相手に共有の文面で見えるため。バイクとスキーのどちらの季節にも合う |
| 重ならない | 今の招待中の仮名・保存ユーザーの呼び名と同じ組み合わせを選ばない。すべて使っている場合だけ末尾に数字を付ける（「青いキツネ 2」） | 一覧で見分けられる |
| 言語 | 招待を作った端末の言語で作り、その文字列を呼び名として保存する。後から言語を変えても書き換えない | 呼び名は利用者の端末の文字列として扱う（翻訳しない名前の規則） |

| 色（日本語／English） | 生き物（日本語／English） |
|---|---|
| 青い／Blue、白い／White、緑の／Green、黄色い／Yellow、銀色の／Silver、金色の／Golden、茶色の／Brown、空色の／Sky | キツネ／Fox、カモメ／Gull、ウサギ／Rabbit、リス／Squirrel、ツバメ／Swallow、クジラ／Whale、ライチョウ／Ptarmigan、シカ／Deer、イルカ／Dolphin、フクロウ／Owl、ペンギン／Penguin、カワセミ／Kingfisher、ハヤブサ／Falcon、ヤマネ／Dormouse |

8色×14種で112通り。語の追加・削除は上の条件で確かめてから行う。

### 招待の作成

2026-11-17の利用者指示を反映する。名前の保存と招待の共有を分け、共有画面を閉じただけで送信・登録の成功を表示しない。以下を保存・画面の実装に適用し、検証範囲は[保存と共有の分離](../validation/history/名前の保存と招待共有の分離.md)へ記録する。

| 利用者の意図 | 見えるもの・すること | アプリが引き受けること | 見せないもの |
|---|---|---|---|
| 相手を覚えておきたい | ＋で「相手を追加」。名前と候補、下端の「保存」。取消は「キャンセル」 | 保存まで無書込。空欄なら表示中の候補で保存。成功後、同じシートを保存済み詳細に切り替える | 名前の暗黙保存、共有の強制、保存前の招待発行 |
| 招待したい | 保存済みの名前、「未登録」、「招待を共有」 | OS共有画面を開く。共有画面を閉じても同じ詳細へ戻す | 「送信済み」や到着・受諾の推測 |
| いったん終えたい | 保存済み詳細の「完了」 | 詳細だけを閉じ、同じ相手を一覧に1行で残す | 保存済みなのに「キャンセル」しかない状態 |
| あとで招待したい | 一覧の未登録の相手をタップ | 同じ相手の詳細と「招待を共有」を開く。通話は開始しない | 再入力・重複する招待行 |
| 相手が登録したか知りたい | 同じ相手の行・詳細の「登録済み」 | 検証済みの受諾を保存した時だけ更新。詳細は閉じない | 返信用の技術記録を別の相手のように表示すること |
| 招待を受け取った | 相手の本人名、「登録」「拒否」 | 登録は初めて保存し、同じシートを登録済み詳細へ更新して返信を開始。「返信を共有」または「完了」で続ける。拒否は保存せず閉じる。元のリンクは有効期限まで再利用できる | 拒否記録、相手への拒否通知 |

### 招待の状態

相手の正本は保存した人1件とする。招待の配送記録はその人に紐づけ、一般向けの一覧へ別行として足さない。別々の相手を名前だけで統合しない。相手の識別がまだない保存は通話・グループ追加・通知許可の対象にしない。

| 状態 | 表示 | 可能な操作・次の状態 | 閉じる・再開 |
|---|---|---|---|
| 入力中（未保存） | 名前の入力欄、候補、保存 | 保存成功で未登録。失敗は入力を保って同じ画面に理由 | キャンセルで無書込。画面外タップ・スワイプでは閉じない |
| 保存済み・未登録 | 確定した名前、「未登録」、「相手が登録すると通話できます。」 | 招待を共有。共有開始・取消・コピー・共有先アプリへの引渡しはいずれも未登録のまま | 完了で一覧へ。同じ行から詳細を開ける。再起動しても名前と同じ人のIDを保持 |
| OS共有画面が開いている | OSの共有先選択 | 取消でも共有操作後でも、同じ保存済み詳細へ戻る。名前は編集状態へ戻さない | 親の詳細は閉じない。共有操作を保存や登録の条件にしない |
| 相手の受諾を確認・保存できた | 同じ人の「登録済み」、本人の名前 | 招待の共有を外す。手動の返信を受領した場合は同じ詳細・設定から到着確認を共有できる。本人名への選択は[仮名の確認](#仮名から本人名への選択)に従う | 開いている詳細を保ち、完了で一覧へ。行のタップは通話開始へ切り替わる |
| 受け手の登録後、返信が未配送 | 保存済み相手の詳細内に「返信が届いていません」または配送中 | 現在の通話を維持して返信を再試行するか、OSの共有先へ「返信を共有」。共有だけでは配達待ちを保ち、検証済みの到着確認で補足を外す | 相手を重複表示しない。返信記録は再起動後も保持 |
| リンク期限切れ | 人は未登録のまま。古いリンクの共有をしない | 次の「招待を共有」で新しいリンクを同じ人へ紐づける | 保存した名前・人のIDを保つ |
| 保存・署名・共有用リンクの準備失敗 | 対象の詳細に理由 | 同じ相手に対して再試行 | 人や名前を消さず、別画面へ進めない |

「未登録」は、まだ相手の受諾をこの端末で確認できていない意味である。共有先の選択・コピー・OSの完了通知から相手の到着や登録を推測しない。名前は「保存」を押したときだけ確定し、focus移動・Return・シートの終了では保存しない。保存・共有の主要操作はキーボードの上を含む下端の操作領域に置く。

### 人に紐づかない旧形式の送信招待

Usersの「招待」から同じ詳細を開く。「閉じる」で一覧へ戻り、同じ招待と呼び名を保つ。「招待を取り消す」は招待自体を取り消す別の操作で、確認を出す。

| 状態 | 詳細の操作と変化 |
|---|---|
| まだ送っていません | 「招待を共有」でOS共有を開く。プレビュー・取消で同じ詳細と状態へ戻る |
| 共有操作・コピーが完了 | OSの完了に合わせて共有結果を保存し、その詳細で「受け取り待ち」に更新する。「再共有」で同じリンクを使う。登録は相手の署名付き返信で確かめる |

Advancedは同じOS共有を使い、詳細の `ContactInvitationRecord.sent` を記録どおりに表示する。`nil` は共有結果を記録していない旧データの値。見本は[Standardの旧形式の招待](一般向け/デザイン見本.html#legacy-contact-invitation)と[AdvancedのUsers](詳細画面/詳細画面見本.html#advanced-users)に対応する。

### 通信を使わずに返信する

2026-11-18。登録した受け手は同じシートの保存済み詳細に留まり、そのまま「返信を共有」を選べる。通信がつながらなくても待たずにOS共有を開ける。「完了」で終えても同じ人の設定から続けられる。Internet資格・通知登録・通常通話を返信共有の条件にしない。

| 利用者の意図・状態 | 見えるもの・すること | 保存と復帰 |
|---|---|---|
| 登録して返信したい（Partial） | 登録済みの同じ相手の詳細に返信状況、「返信を共有」、相手の名前。OSの共有先を選ぶ | 登録と返信は保存済み。同じシートを保ち、共有取消・コピーでは配達済みにしない |
| iOSで登録または再試行してすぐロック・他のアプリへ移る（Partial） | 条件が揃ったInternetの受諾はiOSへ預ける。近距離の返信と到着確認はアプリが実行できる間に試す | 受諾の受付だけで表示を進めず、署名付きの到着確認を保存したら返信待ちを外す。時間切れなら同じ相手と保留中の返信を保つ |
| 通話中に返信したい | 近距離または本人確認済みのInternet経路で返信を試し、試行中だけ「返信を届けています」。どちらも使えない場合は通話の終了を待つ案内を出す。「返信を共有」は利用可能 | 通話・音量・ミュートを維持し、同じ詳細で状態を更新する |
| 自動返信の試行が止まった（Partial） | 有効な返信を再試行できる場合に「もう一度送る」。OSの共有先を選ぶ場合は「返信を共有」 | どちらも同じ人と保存済みの返信を使う。再試行中も有効な返信を共有でき、署名付きの到着確認を保存すると返信待ちを外す |
| 元の作者が返信を受け取った（Ideal） | 元の同じ人が登録済みへ更新。「返信を受け取りました」「到着確認を共有」 | 署名と元の招待を検証して保存する。共有経由の受領をreceivedBySharingで保持し、この場合だけStandardに到着確認を出す |
| 受け手の返信待ちを終えたい | 作者が到着確認を共有。受け手はそのリンクを開く | 開いた端末で検証・保存後に返信状況を外す。コピーや共有先への引渡しだけでは解消しない。開いている詳細・設定は保つ |
| 選ばず閉じる・再起動（Partial） | 同じ相手の設定で返信／到着確認を共有できる | 元のIDと署名済みの保存を使い、新しい人や招待を作らない |
| 保存された未配送の返信が期限切れ（Partial） | 同じ人の詳細・設定に「返信の有効期限が切れました」「新しい招待を送ってもらってください。」。再試行・共有を出さない | 相手・呼び名・通話は保つ。再表示と実行時に期限を再確認し、起動中の古い再試行を押した場合も理由を出す |
| 期限・取消・削除（Empty） | 共有対象を出さない。有効な新しい招待から登録し直す | 相手の削除と同時にその人の招待を取り消す。相手が残っていない旧データも再読込で取り消す。削除・取消前の返信や共有は受け付けず、再登録は新しい招待から行う |
| Advancedで返信の再試行を停止（Partial） | 同じ人の詳細・設定でStop Retrying Notificationを確認。「この端末での再試行を停止しました。」。再試行・返信共有を外す | 相手と名前は保ち、勝手に閉じない。停止はcancelledとして保存し再起動後も維持。届いたこと・相手の削除を意味しない |
| 準備・保存・検証失敗（Error） | 同じ画面に案内。保存状態を保って再確認・再読込後に再試行 | 未確認の相手を登録せず、失敗時に成功や配達を表示しない |
| Loading | OS共有と実際の有限な自動配送だけ | URL準備のための独自待機画面・timerを作らない |

期限の判定は保存記録のhasExpired(at:)を使い、期限ちょうどから無効とする。独立の画面用timerは増やさず、再表示・既存の状態更新・操作時に確認する。Advancedでは保存値canResumeとは別にhasExpiredを表示し、期限切れの再試行・取消操作を出さない。登録直後・人物詳細・相手の設定は同じ記録部品と人物別の共通操作を使い、実行時にも相手と招待の対応を確認する。停止済みなのに再送を促す表示へ戻さない。

通常の近距離交換では通話を開始せず、登録した相手へACKを自動で返す。手動共有では同じreceiptとACKを使って再開する。Advancedは方向・状態・receivedBySharing・canResumeをそのまま示し、Share Accepted Receipt／Share Acknowledgementを条件に対応付ける。[返信の通信仕様](../spec/App/通信仕様.md#新規相手招待の通知処理)

### 一連の操作の確認

実装前に、以下の操作列で途中の目的と復帰先が変わらないことを確認する。HTMLは入力中・保存済み詳細を同じ順で示す。HTMLの静的見本だけをOS共有画面や実アプリの動作確認と扱わず、実装後は同じ列をnative UIで実行する。

| 操作列 | 各段階で確かめる結果 |
|---|---|
| ＋ → 名前入力 → キャンセル | 保存も招待発行もされず、一覧へ戻る |
| ＋ → 名前入力 → 保存 → 完了 → 同じ行 | 保存直後に確定した名前が見える。共有せず終えられ、再表示しても同じ人 |
| 保存 → 招待を共有 → 何もせず取消 → 招待を共有 | 親の詳細・名前・人のIDが変わらず、続けて共有できる |
| 保存 → 招待を共有 → コピー → 完了 → 再起動 | コピーを「送信成功」にせず、未登録の同じ1行と名前を保持 |
| 詳細を表示中 → 他アプリ → 復帰 → 相手の受諾確認 | 画面を勝手に閉じず、同じ詳細が登録済みになる。通常通話・ミュートは維持 |
| リンクを開く → 拒否 → 同じリンクを開く → 登録 → 返信を共有 → 完了 | 拒否時は無書込。登録後は同じシートが詳細になり、共有取消・コピーで閉じない。相手への拒否通知はない |
| 保存失敗 → 修正・再試行／期限切れ → 再共有 | 入力・保存済みの名前と人のIDを保持し、その場で回復できる |

### 招待の詳細

Standardは名前・状態・目的に必要な操作だけを表示する。Advancedも人の正本を同じにし、`SavedUser`の`id`・`memberIDs`・`principal`と、その人に対応する`ContactInvitationRecord`の`id`・`direction`・`state`・`expiresAt`・`session`を詳細内で表す。共通にするのは保存・共有・登録の操作と、表示・語・配置が完全に同じ部品だけとする。

Idealは登録済み、Emptyは保存前、Partialは未登録または返信未配送、Errorは保存・検証失敗とする。ローカル保存は同期処理なので独立したLoading画面を作らない。返信中だけ共通の実際の接続状態から進捗を出し、未登録の相手を無期限のスピナーにしない。通知は通常のAPNsとUserNotificationsを使い、CallKit・VoIP Push・Apple PushToTalkは使わない。

## グループへの招待

[操作の語の意味](デザインシステム.md#操作の語の意味)により、グループに仲間を入れる意図は1つの入口「メンバーを招待」にまとめる。相手が個人で登録済みか、まだ新しい人かで利用者の操作を変えず、届け方の違いはアプリが引き受ける。

### メンバーを招待のシート

| 要素 | 内容 |
|---|---|
| 入口 | Standardは通話・グループ設定のメンバー一覧の先頭の「メンバーを招待」。Advancedは通話のメニュー・Group Settingsの追加、新しいグループの作成。どの入口でも同じシート・同じ動き |
| 見出し | メンバーを招待（新しいグループの作成では「新しいグループ」） |
| 自分のユーザー | 見出し「あなたのユーザー」。まだメンバーでない保存ユーザーを並べ、選ぶだけ（行は[接続先のアバター](デザインシステム.md#共通コンポーネント設計案)・名前・選択の印）。行ごとの補足・鉛筆・削除を置かない |
| 新しい人 | 選択画面の上に「新しい人を招待」。押すと同じ画面に名前の入力欄が増え、その欄へfocusする。空欄なら仮名の候補を使う。自分を含め8枠まで追加でき、未保存の行はRemoveで外せる。Standardは「あなたのユーザー」、Advancedは未保存のNew Peopleと保存済みのSaved Usersを分ける |
| 人数 | 一覧の下に「自分を含めて{n}/8人」（選んだ新しい人を含む） |
| 主要操作 | 既存グループは「招待を保存」（AdvancedはAdd Users）。登録済みの選択・新しい人が1人もいなければ押せない。新しいグループは生成名を編集でき、有効な名前と人数上限を満たせばメンバー未選択でも「作成して接続」、別の接続中は「グループを作成」 |

保存後の状態と共有（2026-11-18の実装）:

| 相手 | アプリがすること | 利用者に見えること |
|---|---|---|
| 保存ユーザー | 既知のアカウントと確認済み端末鍵を持つ登録済みの相手には、保存と同時に配送待ちを作り、自動配送する。未交換の許可は次の接続で交換し、手動共有も任意に使える | 同じ画面に名前と「招待中」。相手の受取確定で「受け取り済み」。必要なら共有し、完了で閉じる |
| 新しい人 | 名前・未登録の人・対象groupの招待枠・署名済み招待を一度に保存する。1つの招待で個人の登録とgroup参加を兼ねる | Invitation（招待）の同じ画面で相手を開き、参加先を確認して「招待を共有」。OS共有を取り消しても同じ詳細へ戻る。完了後もUsersの同じ人か、Standardの通話・グループ設定の未完了の相手の行から続けられる。検証済み返信で同じ人を登録済みにし、対応する枠だけを参加者へ更新する |

招待だけでは呼び出さない。今すぐ来てほしい人は、メンバーの行の「呼び出す」で呼ぶ。シートの中に「リンクで招待」など手段の違いを見せる操作は置かない。宛先を持たないグループのリンク（開いた人が誰でも参加できる）はAdvancedの`Invite`で共有する。

個人登録を兼ねるグループ招待で、双方が同じ二端末宛ての個別通話鍵を一件ずつ保存した場合は、相手の別端末が登録されていても、その二端末でUsersの相手の行から個別通話を始められる。[初回の鍵の条件](../spec/App/通信仕様.md#保存ユーザーを指定する個別通話)

実際の到着は[自動配送の実環境受入](../validation/未確認事項.md#登録済み相手へのグループ自動配送の実環境受入)で追う。新しい人のリンク共有の完了から、配達・登録の完了を推測しない。

### 宛先を持たないグループ招待の返信

リンクを受諾した側で近距離の試行がいったん終わっても、前面に戻ったときや実行中の通話で近距離が利用可能になったときに、進行中の通話を保ったまま各グループの返信を自動で試す。複数の返信待ちがあっても追加操作は要らず、到着確認で該当する招待だけが完了する。[通常グループの返信](../spec/App/通信仕様.md#通常グループの受諾を通話とは別に近距離で届ける)

Internetの条件が揃っていれば、招待発行と受諾の保存から同じ返信を自動で試す。最初の同期より後に届いた返信も、実行できる時間内は画面を開き直さずに受け取る。アプリが動作している間に通話のInternet経路が復旧したときも、保存済みの返信から続ける。発行側では受諾の照合と登録保存、受諾側では到着確認の照合と保存が状態を進める。進行中の通話を保つ。[遠距離の返信と再開](../spec/App/通信仕様.md#通常グループの受諾を遠距離で届ける)

アカウント証明を使わない新規の二端末では、互いに通常グループ招待を受けた場合も、同じ相手から複数の通常グループに招待された場合も、Usersの同じ相手から一つの個別通話を開ける。招待者がいずれかの受諾を確認すれば、受諾者が到着確認を待っていても同じ個別通話を使える。各グループの返信はそれぞれの到着確認で完了する。返信の処理中も進行中の通話は続く。[端末宛て個別通話の準備](../spec/App/通信仕様.md#通常グループの招待返信で端末宛て個別通話を準備する)

招待者が複数のリンクを共有した場合も、アプリを開き直したときに、利用可能な近距離またはInternetから有効な各招待の受諾を確認する。発行上限に達した場合は、これまでのリンクと通話を保ち、既存リンクの期限後に共有を試せることをエラー欄に表示する。[近距離の待受](../spec/App/通信仕様.md#通常グループの受諾を通話とは別に近距離で届ける)、[遠距離の同期](../spec/App/通信仕様.md#通常グループの受諾を遠距離で届ける)

アカウントを確認済みの二人も、それぞれ確認済みの相手端末が一台で、通常グループの招待で相互登録が済んだ条件では、初回からUsersの相手の行で同じ個別通話を開ける。[保存ユーザーを指定する個別通話](../spec/App/通信仕様.md#保存ユーザーを指定する個別通話)

### 新しい相手のグループ招待の状態遷移

| 状態 | 見えるもの・操作 | 保存と復帰 |
|---|---|---|
| 入力中（Empty） | 名前の入力と仮名の候補、人数、保存。追加・削除はこの画面だけ | 保存前の取消で人・招待・鍵・枠を書かない。入力中に利用権が切れたときは名前と選択を保ち、保存を無効にして設定の「利用権」を案内する。画面外タップ／スワイプでは閉じず、明示Cancelを使う |
| 保存済み（Partial） | 参加先と相手の一覧。Standardで相手を開くと、確定した名前・未登録・「まだ送っていません」・参加先・共有 | Doneで共有せず閉じ、通話・グループ設定で同じ人の行から続けられる |
| OS共有中（Partial） | OSの共有先を選ぶ | 取消・コピーで同じ詳細へ戻る。共有を閉じただけなら「まだ送っていません」を保つ。OSが共有操作またはコピーの完了を返すと「受け取り待ち」。相手への到着・登録は返信で確認する |
| 受け手の確認 | 作者名と、登録すると保存されるgroup名 | 拒否は無保存。Registerで個人登録・独立した個人通話鍵・groupと鍵・返信を同じcommitで保存し、同じ詳細に留まる。現在の通話は切り替えない |
| 返信を確認（Ideal） | 送信側の同じ人が登録済み、groupの対応枠が参加者へ変わる | 登録済みの別IDが既にあれば重複を作らず、開いている詳細の識別を保つ。手動返信なら同じ詳細から到着確認を共有できる |
| 保存・読込失敗（Error） | 入力・確定済みの値と理由、既存の再読込 | 全体を旧保存のまま保つ。再読込後の再実行は同じdraft IDを使い、既に保存されていれば二重に追加しない |
| 期限切れ（Partial） | 有効期限に達し、対応する予約枠がある間はStandardの人物詳細に「期限切れ」。次の共有で同じ人と参加先の新しい招待を用意 | 旧枠を新しい招待枠へ置き換え、人数と名前を保つ。OS共有を取り消した場合も新しい招待は「まだ送っていません」の状態で残る |
| 期限切れの枠・グループを外した | グループ招待の行と参加先が消える。Usersの同じ人から個人招待を共有できる | 保存した人と名前を保持する。旧招待は `cancelled` になり、グループへ招待し直すにはグループ側から改めて招待する |
| 受取後にgroupから抜ける | グループだけを外し、登録済みの相手と個人通話は残す | 未完了の返信を同じ保存で取消し、この端末の再試行と秘密の参照を外す。古い招待を開いてもgroup保存の成功扱いにせず、新しい招待を求める。使用済みの通常グループURLも退出後は新しい招待を求める。別の招待で参加し直した後も使用済みのURLで通話や鍵を変更しない。旧データの再読込でも同じ状態へ揃える |
| Loading | 独立の保存待機画面は置かない | 実際の有限な返信試行だけを表示。保存・OS共有を配達待ちのspinnerで覆わない |

新しい人の入力・削除・focusはNewGroupInvitees、選択データと保存はMemberSelectionを共通の正本とする。人の詳細はStandard／Advancedの部品を使い分け、受諾や名前の変更では現在の保存済みの人を読む。名前の編集は招待の呼び名とgroupの予約枠にも反映する。通知は通常のAPNs／UserNotificationsのみで、CallKit・VoIP Push・Apple PushToTalkを追加しない。

## 呼び出せる相手

グループの会話中に呼び出せるのは、送る人が個人で登録している人だけ。通知は直接の知り合いの間だけで届ける親切な知らせなので、それ以外の人には「呼び出す」を出さず、理由も代わりの操作も並べない。

| メンバーの状態 | 行の補足 | 行末 |
|---|---|---|
| 会話中 | 話しています等 | — |
| 未接続・個人で登録済み | 接続していません | 「呼び出す」 |
| 未接続・それ以外（グループでだけ会った、登録を解除した／された） | 接続していません | なし |

説明のfooter、行ごとの理由、長押しメニューの無効の「呼び出す」、グループからの「個人で招待」は置かない。グループの中から個人の招待を送れると、通知を直接の知り合いに限る意味がなくなるため。

表示中に相手の登録や許可が変わったら、行末の「呼び出す」をすぐ外す。押した時点で変わっていた場合は送らず、行の補足に理由の1文を出す。

## 削除と相手側への反映

### 削除の種類

| 削除 | 入口 | 確認のタイトル | 確認の本文 | 実行後の自分の表示 |
|---|---|---|---|---|
| ユーザーを削除 | 保存を編集できるとき、ユーザーの行のスワイプと相手の設定の最後のボタン | {呼び名}を削除しますか？ | {呼び名}の一覧からもあなたが削除され、お互いに呼び出せなくなります。同じグループのメンバーのままです。 | すぐに一覧から消す。反映待ちはStandardでは出さない |
| メンバーを外す | グループの設定のメンバーの行のスワイプ、メンバーの画面の最後のボタン | {名前}をグループから外しますか？ | 現行はタイトルと確認ボタン。相手側の削除同期に対応した時点で、その端末からも消えることを伝える | 保存後すぐにメンバー一覧から消し、その相手への未受領の自動配送を取り消す。この端末ではその相手が再接続しても一覧に戻らない。ユーザー一覧の登録は保つ |
| グループを削除 | グループの行のスワイプと、グループの設定の最後のボタン（編集可能なオーナーだけ） | {グループ}を削除しますか？ | メンバー全員の一覧から{グループ}が消えます。 | すぐに一覧から消す |
| グループから抜ける | グループの設定の最後のボタン（オーナー以外） | {グループ}から抜けますか？ | ほかのメンバーの一覧からあなたが外れます。 | すぐに一覧から消す |

個人削除の本文は、相手側の一覧にも反映する場合の案。現行は[個別通話鍵を持つ端末対の同期](../spec/App/通信仕様.md#個人削除の送信待ち)に対応している。鍵のない相手と同じ本人の別端末に届く範囲を確定した時点で、確認に出す本文を揃える。[画面の残課題](../backlog/画面実装とデザイン見本の差分.md#一覧の構成)

グループの削除・退出が保存されたら、一覧から外し、設定から操作した場合は設定を閉じる。保存に失敗したら、グループと通話を保ち、操作した画面に保存エラーを表示する。

確認のボタンは「削除」（「メンバーを外す」は「外す」、「グループから抜ける」は「抜ける」、`role: .destructive`）と「キャンセル」。メンバーを外す確認中に利用権が切れた場合、メンバーと開いていた画面を保ち、設定の「利用権」を確認する案内を表示する。

#### 接続中の相手・グループを削除するとき

2026-11-06の利用者指示により、削除で今の接続が切れる場合は、切れることを確認の中で示してから実行する。

| 場面 | 確認の本文に加える文 | 確定のボタン | 確定後 |
|---|---|---|---|
| 1対1で接続中の相手を削除 | 今の接続は切断されます。 | 切断して削除 | 接続を切断してから削除する。相手側も接続が終わる（[相手側に届いたとき](#相手側に届いたとき)） |
| 接続中のグループを削除・グループから抜ける | 今の接続は切断されます。 | 切断して削除／切断して抜ける | 保存できたら自分の接続を切断する。保存に失敗したら接続を保つ |
| 会話に参加しているメンバーを外す | {名前}は今の会話からも外れます。 | 外す | 自分の端末で外した人の音声を止め、残った人との会話を続ける。追加し直しても、外す前に保存した名前付き招待への返信では、現在の個別通話やメンバー情報を変更しない。その人の端末での切断と他端末への反映は削除同期の受入に含める |

キャンセルでは何も変えず、接続も維持する。確認を出している間に接続の状態が変わった場合は、確定の時点の状態で文を出し直さず、古い確認を取り消して閉じる。

#### 削除できる人

2026-11-11の利用者指示により、グループの削除はオーナー（グループを作った人）だけができ、オーナー以外はグループから抜けることだけができる。2026-11-17の利用者報告により、削除は編集可能なオーナーの一覧のスワイプにも置き、設定画面と同じ確認・取消・結果にする。抜ける操作はグループの設定から行う。メンバーの追加（招待）と外す操作は、有料の購入と同じ扱いの利用権を持つ人だけができる。判定はグループの作成と同じ共通判定（有料購入・有効な試用・無料チケット・TestFlightのいずれか。[グループ作成権](../backlog/未実装課題.md#購入と利用権の公開準備)、[通話利用権仕様](../spec/App/通話利用権仕様.md)）を使う（2026-11-06の「利用権を持つ人がグループを削除できる」を改める）。グループの会話中に呼び出せるのは、個人で登録している人だけ（[呼び出せる相手](#呼び出せる相手)）。

出せない操作の理由や説明のfooterは置かない。
| ユーザーを削除 | 全員（自分と相手の関係） | — |

利用権は操作の時点で確かめる。設定画面を開いている間に利用権が切れた場合は、押した時点で実行せず、footerの1文を出す。受け取った側の端末でも、削除・外す操作を送った人がその時点で利用権を持っていたかを機能側で確かめる（第三者による削除を防ぐ）。

反映待ちは表示しない（削除した側ではすぐ消え、届けるのはアプリが引き受ける）。Advancedは、削除の同期を実装したときの保留の記録（種類・対象・作成時刻・期限・確認の有無）を、その型のフィールド名と値のまま[詳細表示のUsersとGroups](詳細画面/診断と詳細画面の構成.md#詳細表示のusersとgroups)に出す。表示の語は実装の型を先に決めてから合わせる。

## 登録済みの相手の自動配送の状態遷移

| 状態 | 保存・通信 | Standard／Advanced |
|---|---|---|
| 入力中 | 取消は無保存 | 選択と名前入力 |
| pending | groupと配送待ちを一度に確定。許可未交換・通信不可も保持 | 招待中／pending |
| queued | 署名済み暗号文をserver受信箱へ保存。同じ暗号文で再試行 | 招待中／queued |
| received | 近距離では相手の保存後に署名付き受領を確認。Internetでは受信箱の受領を確定。どちらも一件として一覧に反映 | 受け取り済み／received |
| cancelled | group・相手・宛先鍵の削除、またはメンバーを外した保存で取消。Workerが未受領の暗号文を回収する | 招待画面に記録があれば「招待を停止しました」／cancelled。外したメンバーの行は両モードで消える |
| 受諾期限後 | 発行から7日で受諾できなくなる。未確認の結果は発行から28日まで次の同期機会に照会し、暗号文は回収する | 照会中は「招待中」と配送詳細を表示しない。確定した結果には同じ受領・取消の表示を使い、28日でその表示を外す |
| 宛先が旧形式 | principal／確認済み鍵がないので自動配送記録を作らない | 招待の共有が必要です／既存の共有 |

外した登録済みの人を同じグループへ招待し直すと、新しい招待の受取を待つ。Standardは「招待中」から始まり、Advancedの配送欄から前回の受領済み記録が消える。同じ招待で複数の端末へ届ける場合は、どれか1台の受領でその相手を「受け取り済み」と表示する。同じ相手が追加端末でログインすると、元の招待が有効な間はその端末にも同じグループを自動で届ける。元の送信端末と追加端末が同期できるときに進み、相手の個人登録は増やさない。Standardの受取表示は維持し、Advancedの配送欄に追加端末の記録を出す。期限切れ・取消・除外済みの招待からは配送を追加しない。

保存後は同じ画面で状態と任意の共有を確認し、完了で閉じる。OS共有の取消やコピーを受領として扱わない。受取側は確定するまで一覧とタブ案内に出さない。保存済みの鍵と食い違う自動招待や、そのグループで外した相手から届いた自動招待は破棄する。保存済みのグループと通話を保ち、同じ相手からの別グループへの招待も受け取れる。通信が戻りAppが実行できるときは、保存済みの未完了の招待を同じ配送で続ける。再起動後も同じ招待で確定を確認する。受信だけで通話は開始しない。実APNsと2実機の受入は未了である。

確認済みの相手には近距離でも自動配送する。一部の相手が近くにいない場合も、その相手の「招待中」を保ちながら他の相手への配送を順に試みる。iOSでは、条件が揃った未送信のInternet招待をWorker宛てに暗号化し、保存直後にOSへ預ける。ロックや別アプリへの移動後の送信時刻はOSが決める。近距離などApp自身が行う処理は、OSが与えた有限の実行時間で進める。OSに預けた段階では「招待中」を保ち、相手の受取確定で「受け取り済み」に変わる。続けて別の招待を保存したら、近距離の試行は新しい保存から時間を数える。OSの実行時間が先に切れたときも、未確定の分は起動・復帰時に同じ記録を使う。iOSでは保存済みのInternetの取消も同じ条件で暗号化し、OSへ預ける。未受領なら配送を止め、受領済みなら相手の受取を保つ。受け手も招待の通知を開いた後は同じように画面を閉じてよい。時間内に受取が確定しなければ、次にアプリを開いたときに同じ受取を続け、確定した招待を一覧に一度だけ出す。「外す」を確定した後は設定を閉じてよい。招待の送信が滞っていても、次の同期ではまず受信箱の取消を試みる。圏外や時間切れでは保存済みの取消を保ち、次に同期できる機会に続ける。先に取消が反映された招待は、送信が遅れて届いた場合や相手が取得を始めた場合も返さない。他の招待は引き続き届く。Internet経由では、相手がいったん取得していても、受信箱で受取確定に先立って取消が確定すれば一覧に追加しない。近距離の送信前にも取消を照合する。近距離で送出した招待の取消は、Internet側で完了したあとも確認に必要な記録を期限まで保持する。受取側は、先に近距離の取消を確認した招待を一覧に追加しない。先に受領したグループは、別の所属変更として扱う。相手が次に近距離で受け取れるときに、メンバーを外す操作で保存した取消が自動で届く。受取確定後のグループへの反映は削除同期の課題として扱う。

### 保存済みの招待の表示

保存後の見出しはInvitation（招待）。登録済みの相手だけの場合も対象グループ名を必ず表示する。Standardは名前・登録状態・配送状態と任意の共有、AdvancedはIntercomGroup.id／name、SavedUser.id／isRegistered、GroupDeliveryRecordを表示する。画面を分けても保存・配送の所有元は共通。配送中も共有でき、OS共有の取消やコピーは自動配送の状態を変えない。Advancedの`Invite`は配送記録の前に置く。親のDoneで保存済みのままsheetを閉じる。

自動配送は相手ごとに独立する。ある相手の許可拒否で別の相手の配送を止めず、拒否された相手は招待中のまま任意の共有を使える。一度に複数届いた招待は次の画面復帰を要求せず、その回でmailbox上限まで保存する。通信・認証・混雑の失敗や破棄失敗は次の同期機会まで待ち、裏で繰り返さない。

### 招待画面を完了した後の確認

グループ設定では、同じメンバー行に名前と状態を表示する。Standardは新しい相手に「まだ送っていません」「受け取り待ち」「期限切れ」、登録済みの相手に保存画面と同じ配送状態を表示する。Advancedは新しい相手の行に対象groupの `ContactInvitationRecord.direction`・`state`・`sent`・`expiresAt` を表示し、登録済み相手の `GroupDeliveryRecord` は専用Sectionに表示する。両モードで新しい相手の行から同じ人物詳細へ開き直せる。OS共有の完了で共有結果を更新し、署名付き返信で予約枠が通常メンバーになる。登録済み相手への配送の受領確認は既知端末のどれか1台でよい。配送記録がない場合は受領を推測しない。受信だけでは今の通話や画面を切り替えない。
