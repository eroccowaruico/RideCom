# RideCom 診断と詳細画面の構成

## 指示と背景

2026-11-01の利用者指示により、詳細表示（Advanced）の診断・通話・設定画面を、仕様を知らない人でもぱっと見でトラブルシューティングできる構成へ設計し直す。診断画面では、音声の流れ（パイプライン）・ミキサー・各処理が「何がどう流れ、今何が動いていて、どこで止まっているか」をすぐ読めることを最優先にする。一般向けではないため配色は一般向けほど作り込まないが、細かい情報を分かりやすく並べる。

同日の追加指示により、次を条件とする。

| 条件 | 内容 |
|---|---|
| 主な端末 | iPhone |
| 言語 | 英語だけ。日本語訳を持たない。正式な英語とし、画面の説明は現行の注記程度に留める |
| 語 | 現行コードの表示語をそのまま使う。例は`Live TX Pipeline`、`TX Bus`、`Peer Buses`、`Mix Down`、`RX Master`。操作の`Connect`、見出しの`Participants`、設定のSection名も同じ扱いとする |
| 多人数 | 相手ごとにばらばらな送信条件・自分側の設定が、1つのミックスへ合流する流れを入れ子で見せる。複数の経路を明示する |
| 一覧性・まとまり | 全体の構成・まとまり・順番が分かるようにする。設定はリセットまでの全体と、グループの構成を示す |
| 画面の入口 | Users・Groupsから通話を開く。通話には1対1でもグループの実体を表示する。[タブ構成](#タブ構成) |

現在の診断はOverview、TX、RX、Network、Appliedの5ページ。上部で全ページを選ぶ。Overviewで送受信の判定と流れを確認し、TX・RXで該当する段を開く。現行の項目・識別子・更新周期は[Diagnostics画面](../../spec/App/UI/Diagnostics.md)・[Call画面](../../spec/App/UI/Call.md)・[Settings画面](../../spec/App/UI/Settings.md)に従い、実装と同じ変更でそれらを更新する。音声経路の事実は[音声処理仕様](../../spec/App/音声処理仕様.md)、各packageの値は[packages](../../spec/packages/Overview.md)を正とする。一般向け画面は[一般向けの画面構成](../一般向け/画面構成とレイアウト.md)で扱い、本書と混ぜない。見た目は[詳細画面見本](詳細画面見本.html)で確認する。

## 設計方針

[絶対ルール](../../policies/開発方針.md#standardとadvancedの設計の絶対ルール): どの場合も、画面の各要素を実装と対応付ける。実装と実際の動作の状態を表示に反映する。設計の問題や実装の問題を、画面を見てすぐに見つけられることを満たす。画面の各要素は[実装との対応表](#実装との対応表)から決め、表にない要素を置かない。

| 方針 | 内容 |
|---|---|
| 結論を最初に | 先頭に、TX・RXそれぞれの判定（`Passing`／止まっている段と実装が返す理由／`Waiting`の理由）を出す。判定は各段の状態から機械的に導き、推測の文章を作らない |
| 流れを図として見せる | TXは段の縦の並びと経路への分岐、RXは相手ごとのブロックが`Mix Down`で1つに合流する入れ子の木として描く。止まっている段より先は`Idle`として灰色で示す |
| 今の値と累計を分ける | 各カウンタは毎秒値（今の流量）を主、累計を補助に置く。毎秒値が0なら今は流れていないと一目で分かる |
| 一覧性 | 5ページに分けて各ページの密度を保つ。同じ種類の値は同じ桁位置にそろえ、ラベル付きの短い行で並べる。Overviewの処理順と状態を見て、上部から詳しく読むページを選ぶ |
| packageの値だけを描く | 段・effect stageの順序は`AudioMixerSnapshot`・`MixerGraphSnapshot`・`AudioEffectChainSnapshot`から導く。固定の段名列・既定値をUIの判断基準にしない（[Diagnostics](../../spec/App/UI/Diagnostics.md)で定めた文字列の直接指定の禁止を維持）。effect stageの名前はpackageが返す名前のまま表示する |
| 共通の規則 | 色・背景・余白・寸法・コントロール・UI Stack・レイアウトは[デザインシステム](../デザインシステム.md)に従い、一般向けと同じ[カラーテーマ](../カラーテーマ.md)を使う。部品は[共通コンポーネント](../デザインシステム.md#共通コンポーネント設計案)の「Pipelineの流れ」「段の行」「合流する木」を使う。本書はAdvanced固有の内容だけを定める |

### 表記

| 対象 | 規則 |
|---|---|
| 言語 | 詳細画面（診断・詳細の通話・詳細の設定）は英語だけで表示し、String Catalogに日本語訳を持たない。現行の[Settings画面](../../spec/App/UI/Settings.md#利用者向け案内の言語)の「Advancedの診断文言の全訳は対象外」を維持する |
| 段・画面の語 | 現行コードの語を使う。TXは`Session`・`Input`・`VAD`・`TX Bus`（`TX Bus Effects`）・`Codec`・`RTC`。RXは`RTC RX`・`Decode`・`Peer Buses`・`Mix Down`・`RX Master`・`Master FX`・`Output`。見出しは`Live TX Pipeline`・`Live RX Pipeline`・`Network`・`Internet Service` |
| 状態の語 | 実装が返す語をそのまま使う（`connectionLabel`・`callPresenceLabel`・`routeLabel`、`CallConnectionState.label`、`PeerConnectionState.rawValue`、`PipelineStepState.statusText`など）。画面の側で言い換えない。たとえば、誰も参加していない正常な接続待ちで`Reconnecting / Offline`になることがある。実装が返す状態と実際の状況が食い違う場合は、表示を変えずに実装の問題として[画面実装とデザイン見本の差分](../../backlog/画面実装とデザイン見本の差分.md)へ記録する。VADは`Speech`／`Silence`（`VADGateState`）。機器の既定値は`Auto` |
| 略号 | 説明なしの略号を使わない。`RX`・`TX`は段の名前としてだけ使い、値には`packets/s`・`frames/s`・`ms`・`dBFS`・`B`／`KB`の単位を付ける。`JIT`は`Jitter buffer`、`F`は`frames`、`C`／`A`は`connected`／`authenticated`と書く |
| ID | snapshotのbus ID（`tx-bus`・`rx-master`・`rx-output`）を等幅の補助表記として併記する |
| 説明文 | 現行の注記と通知の文をそのまま使う。例は[経路に添える注記](#経路に添える注記)を参照する。新しい説明は1項目1文までとする |
| 利用者のデータ | 相手名・グループ名は保存されたまま表示し、翻訳しない |

### 状態の語彙

`PipelineStepState`の`statusText`をそのまま使う（`Passing`・`Waiting`・`Blocked`・`Muted`・`Idle`）。effect stageの状態は、`PipelineStepState(_:)`でまとめる前の`AudioEffectStageRuntimeState`の値（`active`・`waiting`・`unavailable`・`bypassed`・`idle`）をそのまま表示する。`PipelineStepState(_:)`は`waiting`と`unavailable`、`bypassed`と`idle`をそれぞれ同じ値にまとめる。記号の色はまとめた値、文字はまとめる前の値を表示し、違いが分かるようにする（2026-11-10に実装）。実装にない状態の語（`Running`・`Unsupported`など）を画面の側で作らない。非対応の設定は`unsupportedSettings`の値として表示する。

## 診断画面

### ページ

上部の標準`Picker(.segmented)`で5ページを選ぶ。iOSのアクセシビリティ文字サイズでは標準の一覧を開いて選ぶ。幅がある画面ではOverviewの判定と選んだページの詳しい値を並べて読める。1列と2列を切り替える幅・文字サイズ・ページの条件は[画面仕様](../../spec/App/UI/Diagnostics.md#画面構成)に従う。[Macでの確認条件](../../validation/未確認事項.md#画面デザインの実環境受入)

| 順序 | ページ（表示名） | 目的 | 主な内容 |
|---|---|---|---|
| 1 | Overview | 結論と全体の一覧 | TX・RXの判定、矢印でつないだ処理順と各段の状態記号、Participantsを1人1行、Networkを1経路1行 |
| 2 | TX | 自分の声がどこまで、どの経路へ出ているか | Live TX Pipelineの段、TX Bus Effects（入れ子）、RTCから経路ごとへの分岐（入れ子） |
| 3 | RX | 相手ごとの条件がどう1つのミックスになるか | 相手ごとのブロックがMix Downへ合流し、RX Master → Master FX → Outputへ続く木 |
| 4 | Network | 経路ごとの品質と中継 | Local・Internetのカード、相手ごとのPath、Event drops、更新からの経過 |
| 5 | Applied | 設定が効いているか | Requested → Applied、Call、Internet Service |

ページは上部から選ぶ。送受信の詳しい値はTX・RXの該当する行を開いて読み、現在の通話と招待はAppliedのCall・Inviteで読む。

### Overview

| 状態 | 判定の表示例 | 導出 |
|---|---|---|
| 両方向に流れている | `TX: Passing`／`RX: Passing` | 両方向の全段がpassing |
| TXが待機 | `TX: Waiting at VAD — Not speaking` | TXで最初にwaitingを示した段と、その段の理由 |
| セッションのエラー | `TX: Blocked at Session` ＋ `Error` | 最初にBlockedを示した段と、その段が報告した内容 |
| 入出力の準備後に相手待ち | `RX: Waiting at RTC RX` ＋ `Control Waiting` | RTC RXは制御接続の状態を表示する |
| 接続表示の後に受信の記録がない | `RX: Waiting at RTC RX` ＋ `Audio RX not measured` を含む経路と参加者の情報 | RTC RXは受信を観測した時刻で判定する。復号と出力は後の段で観測する |
| 出力がミュート | `RX: Muted at Output` | Output段が本人のミュートで止まっている（`speaker.slash`、Danger） |
| 通話の音声が一時停止 | `Connected / Audio Paused` または `Audio paused` ＋ 既存の理由 | 今の通話だけを対象とし、認証済みの相手がいる場合に `Connected` を付ける。送受信の判定と各段の記号は、その時点の観測を表示する |
| 未開始 | `TX: Idle`／`RX: Idle` ＋ `Media Idle` | 全段idle |

音声機器の消失・OSによる中断・再構成の失敗で音声が停止した場合は、Overviewの判定の上に一時停止の記号と理由を表示する。復帰の操作はCallで行う。iOSで同じ入出力先の構成変更から自動で戻った場合は、一時停止の行を外し、同じ通話の観測を表示する。再構成に必要なマイクの許可が得られなかった場合は、Callの再開操作のそばで設定での許可を案内する。

音声機器が切断されたときは、Callと同じ案内を表示する。

> Audio device disconnected. Your microphone and playback are paused; the group connection and relay continue. Check your audio device, then resume.

Pipelineは送信・受信ごとに段を処理順の矢印でつなぎ、各段に状態の記号と色を付ける。TXでは `Input → VAD → TX Bus` の順にたどる。送信エフェクトはTX Busに含め、待機や利用不能があればその段に反映する。幅が足りなければ段名と記号と直前の矢印をまとめて折り返す。Participantsは「名前・経路・RXの毎秒値・状態」、Networkは「経路名・相手数・RTT・状態」を1行ずつ出す。

通話の状態と段の記号を見て、上部でページを選ぶ。調べたい症状に応じて次の値を読む。

| 症状 | 確認するページと段 |
|---|---|
| 自分の声が相手に届かない | TXで最初に止まっている段を開く |
| 特定の相手の声が聞こえない | RXでその相手の行を開く |
| 相手の声が途切れる | RXで`RTC RX`の破棄、復号失敗、相手の行にある`Playout`の調整・リセットを順に読む。LossとEvent dropsはNetworkで確かめる |
| 相手の声が遅れて聞こえる | RXで相手の`Playout`とOutputの予約量を、NetworkでRTTを読む |

### TX（Live TX Pipeline）

段を縦に並べ、各段は「段名／状態／主な値／毎秒値」を1〜2行に収める。`TX Bus`と`RTC`は中身を入れ子で示す。

| 段（表示名） | 主な値 | 毎秒値 | Waiting・Blockedの理由の例 | 展開で出す値 |
|---|---|---|---|---|
| Session | `Burst mode`／`Stream mode`と有効状態 | — | `Configured`（未活性）、`Error` | 要求設定と実効設定（category・mode・options・echo cancellation・sample rate・IO buffer）、`unsupportedSettings` |
| Input | 機器名（`currentInput`）と実形式（例: `AirPods Pro · 48 kHz mono`）。Apple Watch選択中は`Apple Watch` | frames/s | `Starting`、機器の切断（ミュート中は状態を`Muted`にする） | 要求形式と実形式、処理frame累計、voice processingの要求と実効、`inputDeliveryMuted` |
| VAD | `Speech`／`Silence`、感度preset | — | `Not speaking` | `Microphone input before TX Bus Effects.`、入力・Noise floor・Threshold（dBFS）、gate gain。分析値がなければ`Input level: Not measured` |
| TX Bus | source数・effect数と、声の分離の設定・実状態（例 `Voice Isolation On · active`） | — | `Not available`、`Snapshot waiting`、effectの待機・利用不能の理由 | 入れ子の`TX Bus Effects`（下記） |
| Codec | 選択された形式と符号化の状態。観測済みなら実際の形式と最終時刻（例 `AAC-ELD / Encoding / Last encode AAC-ELD · 0s ago`）。fallback時は要求→選択と`Fallback`を併記する | — | `Encode idle`、`Encode not measured`、`Encode idle · Muted` | 要求設定と実効設定、sample rateとbitrate、`Encoded audio packets`（今の通話の累計。メディアを準備する前は未計測） |
| RTC | `routeLabel`（例: `Local + Internet / Relay`）と`Control Connected`。音声の受付状態と最後に渡した時刻を併記 | — | `Control Waiting`、`Media Idle`、`Audio TX idle` | `Last audio dispatch`の観測時刻と、入れ子の経路ごとの分岐（下表） |

`TX Bus Effects`は`tx-bus.effectChain`の登録順に、stage名と状態を並べる。現在の配線では `Isolation`（SoundIsolation）→ `Dynamics`（DynamicsProcessor）→ `Limiter`（PeakLimiter）の順になる。閉じたTX Busでは `isSoundIsolationEnabled` のOn／Offと `sound-isolation` の `AudioEffectStageRuntimeState` を併記する。stageが読めない場合は実状態を `Not measured` とする。待機・利用不能の理由がある場合も、分離の設定を併記する。VADはTX Busの直前の独立した段に置く。発話の有無にかかわらず、判定状態と分離の適用状態が別々に読める。[Diagnostics](../../spec/App/UI/Diagnostics.md#送信パイプライン)。

RTCを閉じた行でも、最後の音声を経路に渡した状態と経過秒が分かる。直近2秒に経路が受け付けた場合にPassingとし、音声が途絶えると `Audio TX idle` に戻す。制御接続は別の値として残す。RTCを開くと、最後の自端末音声について、LocalとInternetを矢印で分岐させる。経路の受付は閉じたRTC行と同じ `RTCOutboundAudioDispatch` から得る。状態は共通の記号と語で示す。

| 状態 | 表示 |
|---|---|
| 経路が受け付けた | Passingの記号と `Accepted by transport` |
| 経路が受け付けなかった | Waitingの記号と `Not accepted by transport` |
| 経路へ渡したが受付結果が得られない | Waitingの記号と `Acceptance not measured` |
| 近距離でカバーしてInternetを省略 | InternetにIdleの記号と `Covered by Local` |
| 最後の音声で使わなかった | Idleの記号と `Not used for last packet` |
| 記録がない・15秒を超えた | Idleと `No audio dispatch observed`／`Last dispatch is stale` |

Internetの行には `Send queue` を併記する。相手への到着は `Peer receipt: Not measured` と示す。観測した受信経路と中継先はNetworkのPathsで確認する。

### RX（Live RX Pipeline）

狭い幅では、`RTC RX`、`Decode`、`Peer Buses`の段名と状態記号の下に観測値を折り返して表示する。

`RTC RX`は経路、接続した相手と認証した相手の数を `n connected / n authenticated` で示す。`Received packets n` と `Dropped packets n` で、受信数と破棄数を分ける。最新の受信は `Last receipt` と経過秒を添える。直近2秒なら `Audio received`、2秒超なら `Audio RX idle`、時刻がなければ `Audio RX not measured` とする。

`Decode`は現在の受信グラフでPCMが得られたpacket数を `PCM n`、失敗数を `Decode errors n` として表示する。`Last PCM · Opus · 0s ago` は、実際の復号形式と最終観測からの経過秒を示す。失敗の経過秒は `Last error` に示す。未観測で失敗もなければ `No PCM observed`。直近2秒にPCMを得た場合はPassing。PCMが途絶え、直近2秒に失敗がある間はDecodeをBlockedの記号と語で示す。どちらも途絶えればWaiting。Overviewの判定・処理順にも同じ状態を使い、復号失敗だけならRTC RXの受信はPassingのまま示せる。再生予約と実出力は後の段を読む。

相手ごとの条件がばらばらなまま届き、相手ごとのPeer Busで自分側の設定が掛かり、`Mix Down`で1つに合流する流れを入れ子の木で描く。`rx-master`への経路がある相手から左の縦線へ枝を伸ばし、`Mix Down`で合流させる。合流点で線を終え、`3 routes → rx-master`のように実際の経路数を示す。経路がない相手は木の上に並べる。

相手ごとの開閉見出しに名前、経路の状態、自端末の相手別の分離設定と実状態を示す。設定は `remoteSoundIsolationEnabled` の相手の値を使い、保存値がなければAppの既定値を使う。経路とstageがあれば実状態を表示し、どちらかを取得できなければ `Not measured` とする。

経路がある相手は、その入力の最後のPCM再生予約から2秒以内なら`Passing`、未観測または2秒超なら`Waiting`。共通の状態記号と語を添え、`Waiting`の相手も経路がある間は同じ合流線につなぐ。開くと段名付きの内訳を表示する。別の相手を開くと前の内訳を閉じ、経路と見出しは見えるままとする。

| 行（表示名） | 内容 | 入力 |
|---|---|---|
| Sender | 相手が報告したマイクの状態（`Muted`／`Unmuted`）、実際のcodec識別子、bitrate（bps）、VAD、送信の音声分離。報告からの経過秒を示し、15秒を超えたら`Stale`を添える。相手の報告で取得できなかった値は`Not measured` | `receivePeerRuntimeStatuses`の`localMute`・`packageReports`（Codec・VADGate・SoundIsolation）、`generatedAt` |
| RTC RX | 接続と認証の状態をそれぞれの値で表示する。観測した経路は`Local direct`・`Local relayed`・`Internet`、未観測は`Path not measured` | `connectionState`、`authenticationState`、`RTCNetworkDiagnostics`の相手ごとの経路 |
| Decode | 相手ごとに、PCMを生成した最後の復号形式と経過秒（例 `Decode: Opus · 0s ago`）。相手ごとの`packets/s`は`Not measured`と表示する | その相手の最後の復号成功 |
| Playout | 復号したPCMの再生予約を`n ms queued / Adjustments: n / Resets: n`で示す。回数はそのsourceの累計。予約量が0なら0ms。未取得は`Not measured` | 経路のある`rx-peer-*`の`MixerSourceSnapshot.bufferedDuration`、`playoutAdjustmentCount`、`playbackResetCount` |
| Peer Bus | 自分側の設定。音量（%）、FXの要約 | peer volume、`receivePeerEffectChainSnapshot` |

経路がない相手の状態は接続状態に応じて`Offline`または`No mixer route`と示す。Offlineの相手は詳細も`Offline`と表示する。

合流後の段は縦1列とし、`Mix Down`の下に置く。アクセシビリティ文字サイズではRX Masterのメーターは集計の下に置く。Master FXは1列にする。

| 段（表示名） | 主な値 |
|---|---|
| Mix Down | 合流するroute数 → `rx-master`（`AudioMixerSnapshot.routes` の `rx-peer-*` → `rx-master`）。経路のある相手に直近2秒の再生予約があればPassing |
| RX Master | `rx-master`、入力数、OUT（%）と、受信全体の分離設定・実状態。設定は `receiveMixSoundIsolationEnabled`。実状態は `rx-master` の `sound-isolation` から読む。Passing／WaitingはMix Downと共通 |
| Master FX | 入れ子で、`rx-master.effectChain`＋`rx-output.effectChain`の順（現在は`SoundIsolation → Master fader → PeakLimiter`）。PeakLimiterは`rx-output`を併記 |
| Output | nativeは `Last audible PCM` と経過秒、未観測は `No audible PCM observed`。描画の観測は `Last render` と経過秒。別rendererでは再生予約と `Render not measured`。開くと機器名（`currentOutput`）、実形式、Buffered（`bufferedOutputDuration`）、Resets（`playbackResetCount`） |

OutputのPassingは直近2秒のnative有声PCMを示す。無音が続くとWaitingに戻り、`Last render` は更新される。描画も途絶えると両方の経過秒が進み、RX Masterのレベルとピークは最後の描画から2秒を超えると0になる。同じ通話で描画が戻るとメーターを更新し、有声PCMが出るとOutputはPassingに戻る。

上流が止まっている相手のブロックは、止まった行を強調し、それより下の行を`Idle`として薄くする。下流の0を故障として見せない。

### Network

Local・Internetのカードでは、`RTCNetworkDiagnostics`の値を経路ごとに表示する。

| 項目（表示名） | 内容 |
|---|---|
| Connection failure | Internetカードの先頭で、`internetFailureDetail` にある失敗を警告の記号と語で表示する。接続準備や入室の失敗では処理名を確認できる。Localの状態と計測は既存のカードで読める |
| RTT | ICE接続のRTT（ms）。取得できない場合は`Not measured` |
| Loss | その経路のpacket loss（%）。未取得は`Not measured` |
| Jitter | その経路のjitter（ms）。未取得は`Not measured` |
| Send queue | DataChannelの送信待ち（B）。未取得は`Not measured` |
| Event drops | session・route・engine・transportごとのoverflow・expired |
| Paths | 相手名、`Local`／`Internet`と`Direct group path`／`Relayed`、短縮IDの矢印、最終受信時刻を、相手別の縦1列に並べる |
| Updated | 経路レポートの生成からの経過秒を補助色で表示し、15秒を超えたら `Stale` を添える |

計測値と更新時刻は、横に収まるときは項目名の右に並べる。狭い幅や大きな文字で収まらないときは、カードの横幅を使って項目名の下へ移す。

失敗行にも同じ折り返しを使い、項目名と失敗理由をまとめて読み上げる。未計測や最初の接続中で失敗がなければ行は出ない。Internet経路の復帰、通話の終了、新しい開始で行を消す。

矢印は、認証されたデータの送信元から中継端末を通り、この端末へ届いた順序を保つ。相手名と矢印の列にはカードの横幅を使う。アクセシビリティ文字サイズでは1行に1つのIDを置き、下向きの矢印でつなぐ。`Last received n s ago`を独立して表示し、15秒を超えた観測値に`Stale`を付ける。

#### 経路に添える注記

カードの下に次の原文を表示する。

> RTT measures this device's ICE connection, not audio delay. Event drops occur inside this device. Paths show the last authenticated reception, not guaranteed reachability.

## 詳細表示の通話画面

Appleの本人確認が必要で回線を使える場合は、通話操作の次に標準の「Appleで続ける」を置く。確認後は同じ通話の接続を続ける。[通話の案内](../../spec/App/UI/Call.md#混在通話機器切断の表示)

保存済みの資格を読み取れない場合は発信先を保ち、回線が使える間は「インターネット通話の設定を読み込めませんでした。」と表示する。読み直せたら案内を外して接続を続ける。

登録が済むまで個人通話を作れないときは、Standardと同じ表示を使う。相手の名前と「接続中」を出し、閉じると準備中の発信を取り消す。

端末資格が拒否されたときは「インターネット通話でこの端末を確認できませんでした。」と表示する。本人確認が必要なら、回線が使えるときに同じ通話で「Appleで続ける」を出す。再登録後は案内を外す。利用できる近距離通話は続く。

端末宛て個別通話で招待を受け直す必要がある場合は、通話画面に「{相手の呼び名}さんに新しい招待を送ってもらってください。」と表示する。[表示条件](../../spec/App/UI/Call.md#グループ資格の案内)

[通常グループの返信で個別通話が準備されたとき](../../spec/App/通信仕様.md#通常グループの返信で初回の個別通話を準備する)は、Usersの短縮IDとGroupsの`Direct Groups`に保存結果を反映する。鍵を受け取った側では、鍵を含む受諾または到着確認の保存後に反映する。開いている画面と通話は維持する。
追加端末を登録しても相手は同じ行に表示する。個別通話の短縮IDを保ち、登録した端末数を表示する。
追加端末から通常グループの返信が届き、元の鍵を保った場合も、元の端末は同じ行と短縮IDを使う。

### 作成・追加のユーザー選択

`AdvancedSavedUsersSelection`は`Saved Users`の名前をタップして選び、選択中だけ行末に`checkmark`を出す（`selectUser-{UUID}`、VoiceOverは選択状態）。Toggle・行の編集・削除・説明のfooterは置かない。Formの別Sectionに「{n} of 8 members including you」とエラーを表示する。ツールバーには`Cancel`を置く。作成は`Create and Connect`（別通話中は`Create Group`）、追加は`Add Users`を置く。新規作成だけ生成名を入力済みの名前欄を出す。データと保存は共通の`MemberSelection`、追加後の共有も共通とし、Standardとの表示・語・配置の差は[現行Call仕様](../../spec/App/UI/Call.md#保存済みユーザーの操作)で対照する。

## グループ招待の保存後

新しい相手をグループへ招待するときは`AdvancedSavedUsersSelection`で選ぶ。New Peopleは`MemberSelection.newPeople`の入力欄、Saved Usersは`availableUsers`の選択欄とする。入力部品NewGroupInvitees・保存・共有は同じ契約を使う。保存後の人物詳細はSavedUserとContactInvitationRecordのinvitedGroupID・sent・state・canResumeに対応する。グループ設定の予約枠からも同じ人物詳細を開く。表示のためのtoken／鍵の読出しは行わない。登録済みの相手には`AdvancedRegisteredGroupInvitations`で`GroupDeliveryRecord`の実値を表示する。項目はid、recipientMemberID、state、expiresAt、credentialReference。項目名と値は横に並べ、長い値が収まらない場合は値を次の行に送り、IDの全体を読めるように折り返す。保存直後はpending、server受付はqueued、相手保存の確認はreceived。`Invite`は送受信の記録の前に置き、受取が確定する前も任意に共有できる。Doneまで同じ画面に留まる。

AdvancedGroupInvitationSavedViewの見出しはInvitation（招待）。IntercomGroupのid／nameを常に表示する。SavedUserは名前にisRegisteredとidを添え、同じ人物の詳細を開く。確認済み相手へのGroupDeliveryRecordは既存の記録表示を使い、旧形式で記録がなくても`Invite`で任意に共有できる。Standardの案内文を流用せず、Doneは親のsheet終了操作を呼ぶ。

Group SettingsのMembersで、新しい相手の名前に対象groupの `ContactInvitationRecord` の `direction`・`state`・`sent` とISO 8601の `expiresAt` を添える。その行から同じ人物詳細を開く。共有取消で同じ値を保ち、OSの共有完了で `sent` を更新する。署名付き返信で同じ枠が通常メンバーになり、招待の値は表示から外れる。[Group SettingsのHTML見本](詳細画面見本.html#group-settings)と対応する。

登録済み相手のoutgoing GroupDeliveryRecordはAdvancedGroupDeliveryRecordsで表示する。保存画面と同じ実フィールドを再利用し、宛先のないグループの共有は送受信の記録の前の`Invite`から開く。receivedは相手の受取が受信箱で確定した状態。同じグループに同じ人を招待し直すと、前回のreceivedは送受信状況の欄から消え、新しい転送がpendingから進む。受取側の一覧反映は確定後に行われる。保存済みのグループと鍵が食い違う招待や、そのグループで外した相手から届いた招待は破棄し、次の受信箱の項目へ進む。受領の応答を待つ間に競合や除外が起きても、受取側のグループと通話を保つ。表示用の送受信の状況は保存しない。
