# RideCom 診断と詳細画面の構成

## 指示と背景

2026-11-01の利用者指示により、詳細表示（Advanced）の診断・通話・設定画面を、仕様を知らない人でもぱっと見でトラブルシューティングできる構成へ設計し直す。診断画面では、音声の流れ（パイプライン）・ミキサー・各処理が「何がどう流れ、今何が動いていて、どこで止まっているか」をすぐ読めることを最優先にする。一般向けではないため配色は一般向けほど作り込まないが、細かい情報を分かりやすく並べる。

同日の追加指示により、次を条件とする。

| 条件 | 内容 |
|---|---|
| 主な端末 | iPhone |
| 言語 | 英語だけ。日本語訳を持たない。正式な英語とし、画面の説明は現行の注記程度に留める |
| 語 | 現行コードの表示語（`Live TX Pipeline`、`TX Bus`、`Peer Buses`、`Mix Down`、`RX Master`、`Connect`、`Participants`、設定のSection名など）をそのまま使う |
| 多人数 | 相手ごとにばらばらな送信条件・自分側の設定が、1つのミックスへ合流する流れを入れ子で見せる。複数の経路を明示する |
| 一覧性・まとまり | 全体の構成・まとまり・順番が分かるようにする。設定はリセットまでの全体と、グループの構成を示す |
| タブ | Call・Users・Groupsは一般向けと同じく分ける。通話は1対1でもグループの実体として見せる |

本書は実装前の設計案。現行の項目・識別子・更新周期は[Diagnostics画面](../../spec/App/UI/Diagnostics.md)・[Call画面](../../spec/App/UI/Call.md)・[Settings画面](../../spec/App/UI/Settings.md)を正本とし、実装と同じ変更でそれらを更新する。音声経路の事実は[音声処理仕様](../../spec/App/音声処理仕様.md)、各packageの値は[packages](../../spec/packages/Overview.md)を正とする。一般向け画面は[一般向けの画面構成](../一般向け/画面構成とレイアウト.md)で扱い、本書と混ぜない。見た目は[詳細画面見本](詳細画面見本.html)で確認する。

## 現行の診断画面で分からない理由

2026-11-01時点のコード（`DiagnosticsView`・`TransmitPipelinePresentation`・`ReceivePipelinePresentation`・`IntercomViewModel+Diagnostics`）を確認した結果。

| 現象 | 現行の実装 | 困ること |
|---|---|---|
| 結論がない | Live TX Pipeline 6段・Live RX Pipeline 7段の各行に状態色を付けるだけ | どこで止まっているかを、全行を読み比べて自分で推測する必要がある |
| 略号が説明なしで並ぶ | `C 2 / A 2 / RX 341`、`Run / 48k/1ch / F 12345`、`RX / JIT / PLAY`、`DEC` | 接続数・認証数・受信packet数・処理frame数・再生待ちの意味が分からない |
| 累計しかない | 送受信packet・frame数は通話開始からの累計 | 「今」流れているのか、さっき止まったのかが分からない |
| 概要カードが空疎 | Audio Pathは常に固定文と灰色。Callは`GROUP 1a2b3c4d / MEMBERS 4`。Inviteは招待可否だけ | 概要として役に立たない |
| Networkが1つの長文 | `networkDiagnosticsSummary`を改行区切りの1つのTextで表示 | 経路ごとのRTT・送信待ち・drop・中継経路を見比べられない |
| VADが行にない | 見出しの説明文には`VAD`とあるが、段の行がない。noise floor・threshold・gainはruntime snapshotにあるのに未表示 | 「話しているのに送られない」の原因（感度・騒音）を確認できない |
| 相手側の条件が見えない | 相手から届く`remoteRuntimeStatuses`（相手のマイク、codecの要求と実際・fallback、VAD、effect）を表示していない | 相手ごとに条件が違うときに、どこが原因か分からない |
| 要求値と実効値が見えない | Codecは要求→選択とFallbackの語だけ。SessionManagerの`resolvedConfiguration`・`unsupportedSettings`は未表示 | 設定が反映されたのか、OSに無視されたのかが分からない |
| 機器が見えない | `currentInput`・`currentOutput`の機器名、出力の`bufferedOutputDuration`・`playbackResetCount`は未表示 | Bluetooth・有線・内蔵のどれで鳴っているか、再生が途切れ直しているかが分からない |
| Apple Watch経路が見えない | `watchAudioLink`の有無を表示しない | 音声がWatchへ行っているのか、iPhoneで鳴っているのかが分からない |

## 設計方針

[絶対ルール](../../policies/開発方針.md#standardとadvancedの設計の絶対ルール): すべてのケースで、実装と対になるように表し、実装と動作の状態に連動したデザインにする。設計の問題や実装の問題を、画面を見てすぐに見つけられることを満たす。画面の各要素は[実装との対応表](#実装との対応表)から決め、表にない要素を置かない。

| 方針 | 内容 |
|---|---|
| 結論を最初に | 先頭に、TX・RXそれぞれの判定（`Passing`／止まっている段と実装が返す理由／`Waiting`の理由）を出す。判定は各段の状態から機械的に導き、推測の文章を作らない |
| 流れを図として見せる | TXは段の縦の並びと経路への分岐、RXは相手ごとのブロックが`Mix Down`で1つに合流する入れ子の木として描く。止まっている段より先は`Idle`として灰色で示す |
| 今の値と累計を分ける | 各カウンタは毎秒値（今の流量）を主、累計を補助に置く。毎秒値が0なら今は流れていないと一目で分かる |
| 一覧性 | 5ページに分けて各ページの密度を保つ。同じ種類の値は同じ桁位置にそろえ、ラベル付きの短い行で並べる。4症状から見るべき段へ直接移動できる |
| packageの値だけを描く | 段・effect stageの順序は`AudioMixerSnapshot`・`MixerGraphSnapshot`・`AudioEffectChainSnapshot`から導く。固定の段名列・既定値をUIの正本にしない（[Diagnostics](../../spec/App/UI/Diagnostics.md)の固定文字列禁止を維持）。effect stageの名前はpackageが返す名前のまま表示する |
| 共通の規則 | 色・背景・余白・寸法・コントロール・UI Stack・レイアウトは[デザインシステム](../デザインシステム.md)に従い、一般向けと同じ[カラーテーマ](../カラーテーマ.md)を使う。部品は[共通コンポーネント](../デザインシステム.md#共通コンポーネント設計案)の「Pipelineの流れ」「段の行」「合流する木」を使う。本書はAdvanced固有の内容だけを定める |

### 表記

| 対象 | 規則 |
|---|---|
| 言語 | 詳細画面（診断・詳細の通話・詳細の設定）は英語だけで表示し、String Catalogに日本語訳を持たない。現行の[Settings画面](../../spec/App/UI/Settings.md#利用者向け案内の言語)の「Advancedの診断文言の全訳は対象外」を維持する |
| 段・画面の語 | 現行コードの語を使う。TXは`Session`・`Input`・`VAD`・`TX Bus`（`TX Bus Effects`）・`Codec`・`RTC`、RXは`RTC RX`・`Decode`・`Peer Buses`・`Mix Down`・`RX Master`・`Master FX`・`Output`。見出しは`Live TX Pipeline`・`Live RX Pipeline`・`Network`・`Internet Service` |
| 状態の語 | 実装が返す語をそのまま使う（`connectionLabel`・`callPresenceLabel`・`routeLabel`、`CallConnectionState.label`、`PeerConnectionState.rawValue`、`PipelineStepState.statusText`など）。画面の側で言い換えない。実装の状態が実際の状況と食い違う場合（例: 誰も参加していない正常な接続待ちで`Reconnecting / Offline`になる）は、表示を変えずに実装の問題として[画面実装とデザイン見本の差分](../../backlog/画面実装とデザイン見本の差分.md)へ記録する。VADは`Speech`／`Silence`（`VADGateState`）。機器の既定値は`Auto` |
| 略号 | 説明なしの略号を使わない。`RX`・`TX`は段の名前としてだけ使い、値には`packets/s`・`frames/s`・`ms`・`dBFS`・`B`／`KB`の単位を付ける。`JIT`は`Jitter buffer`、`F`は`frames`、`C`／`A`は`connected`／`authenticated`と書く |
| ID | snapshotのbus ID（`tx-bus`・`rx-master`・`rx-output`）を等幅の補助表記として併記する |
| 説明文 | 現行の注記・通知の文をそのまま使う（例: `RTT measures this device's ICE connection, not audio delay. Event drops occur inside this device. Paths show the last authenticated reception, not guaranteed reachability.`）。新しい説明は1項目1文までとする |
| 利用者のデータ | 相手名・グループ名は保存されたまま表示し、翻訳しない |

### 状態の語彙

`PipelineStepState`の`statusText`をそのまま使う（`Passing`・`Waiting`・`Blocked`・`Muted`・`Idle`）。effect stageの状態は、`PipelineStepState(_:)`でまとめる前の`AudioEffectStageRuntimeState`の値（`active`・`waiting`・`unavailable`・`bypassed`・`idle`）をそのまま表示する。`PipelineStepState(_:)`は`waiting`と`unavailable`、`bypassed`と`idle`を同じ値にまとめるため、記号の色はまとめた値、文字はまとめる前の値を表示し、違いが分かるようにする（2026-11-10に実装）。実装にない状態の語（`Running`・`Unsupported`など）を画面の側で作らない。非対応の設定は`unsupportedSettings`の値として表示する。

## 診断画面

### ページ

上部の標準`Picker(.segmented)`で5ページに分ける。結論は`Overview`だけで分かるようにする。iPadとMacでは`Overview`と選択中のページを2列で並べる。

| 順序 | ページ（表示名） | 目的 | 主な内容 |
|---|---|---|---|
| 1 | Overview | 結論と全体の一覧 | TX・RXの判定、矢印でつないだ処理順と各段の状態記号、Participantsを1人1行、Networkを1経路1行、症状ボタン |
| 2 | TX | 自分の声がどこまで、どの経路へ出ているか | Live TX Pipelineの段、TX Bus Effects（入れ子）、RTCから経路ごとへの分岐（入れ子） |
| 3 | RX | 相手ごとの条件がどう1つのミックスになるか | 相手ごとのブロックがMix Downへ合流し、RX Master → Master FX → Outputへ続く木 |
| 4 | Network | 経路ごとの品質と中継 | Local・Internetのカード、相手ごとのPath、Event drops、更新からの経過 |
| 5 | Applied | 設定が効いているか | Requested → Applied、Call、Internet Service |

現行の`Current Overview`のカード（Audio Path／Call／Network Quality／Invite）は各ページへ分解する。固定文だけのAudio Pathカードは廃止する。Inviteの可否はAppliedのCallへ移す。

### Overview

| 状態 | 判定の表示例 | 導出 |
|---|---|---|
| 両方向に流れている | `TX: Passing`／`RX: Passing` | 両方向の全段がpassing |
| TXが待機 | `TX: Waiting at VAD — Not speaking` | TXで最初にwaitingになった段と、その段の理由 |
| TXが停止 | `TX: Blocked at Input` ＋ 現行の通知文（例: `Audio device disconnected. Your microphone and playback are paused; the group connection and relay continue. Check your audio device, then resume.`） | 最初にblockedになった段と、その原因の既存の通知文 |
| RXが待機 | `RX: Waiting — Not speaking` | RXの最初の非passing段 |
| 出力がミュート | `RX: Muted at Output` | Output段が本人のミュートで止まっている（`speaker.slash`、Danger） |
| 音声停止で未到達 | `RX: Idle` ＋ `Connected / Audio Paused` | 音声が止まり、RXの段へ到達していない。接続と中継の維持を`callPresenceLabel`で示す。iOSで同じ入出力先の構成変更から戻れた場合は、同じ通話の実動作を表示する。機器の消失、中断または再構成失敗では音声停止と再開の案内を示す。再構成に必要なマイクの許可が得られなかった場合は、再開操作のそばで設定での許可を案内する |
| 未開始 | `TX: Idle`／`RX: Idle` ＋ `Media Idle` | 全段idle |

Pipelineは送信・受信ごとに段を処理順の矢印でつなぎ、各段に状態の記号と色を付ける。TXでは `Input → VAD → TX Bus` の順にたどる。送信エフェクトはTX Busに含め、待機や利用不能があればその段に反映する。幅が足りなければ段名と記号と直前の矢印をまとめて折り返す。Participantsは「名前・経路・RXの毎秒値・状態」、Networkは「経路名・相手数・RTT・状態」を1行ずつ出す。

症状ボタンは該当ページの該当段へ移動して展開する。

| 症状ボタン | 移動先 |
|---|---|
| `Others can't hear me` | TXの最初の非passing段 |
| `I can't hear someone` | RXの対象の相手のブロック |
| `Audio drops out` | RXの`RTC RX`の破棄・`Decode`の復号失敗・`Jitter buffer`と、NetworkのLoss・Event drops |
| `Audio is delayed` | RXの`Jitter buffer`、Outputの予約量、NetworkのRTT |

### TX（Live TX Pipeline）

段を縦に並べ、各段は「段名／状態／主な値／毎秒値」を1〜2行に収める。`TX Bus`と`RTC`は中身を入れ子で示す。

| 段（表示名） | 主な値 | 毎秒値 | Waiting・Blockedの理由の例 | 展開で出す値 |
|---|---|---|---|---|
| Session | `Burst mode`／`Stream mode`と有効状態 | — | `Configured`（未活性）、`Error` | 要求設定と実効設定（category・mode・options・echo cancellation・sample rate・IO buffer）、`unsupportedSettings` |
| Input | 機器名（`currentInput`）と実形式（例: `AirPods Pro · 48 kHz mono`）。Apple Watch選択中は`Apple Watch` | frames/s | `Starting`、機器の切断（ミュート中は状態を`Muted`にする） | 要求形式と実形式、処理frame累計、voice processingの要求と実効、`inputDeliveryMuted` |
| VAD | `Speech`／`Silence`、感度preset | — | `Not speaking` | `Microphone input before TX Bus Effects.`、入力・Noise floor・Threshold（dBFS）、gate gain。分析値がなければ`Input level: Not measured` |
| TX Bus | `tx-bus`、source数・effect数 | — | `Snapshot waiting` | 入れ子の`TX Bus Effects`（下記） |
| Codec | 実際の形式（`CodecIdentifier.displayName`と値。例: `MPEG-4 AAC-ELD · 48 kHz · 48 kbps`）。fallbackなら要求→実際と`Fallback` | — | 発話待ち、`Fallback` | 要求設定と実効設定、利用可能なcodec一覧、`Encoded audio packets`（今の通話の累計。メディアを準備する前は未計測） |
| RTC | `routeLabel`（例: `Local + Internet / Relay`）と`Control Connected` | — | `Control Waiting`、`Media Idle` | `Last audio dispatch`の観測時刻と、入れ子の経路ごとの分岐（下表） |

`TX Bus Effects`は`tx-bus.effectChain`の登録順に、packageが返すstage名と状態をそのまま並べる。現在の実配線では`SoundIsolation → DynamicsProcessor → PeakLimiter`の順になるが、この順は表示の正本ではない。VADはミキサーの前段で動くため、effectではなく独立した段として描く（[Diagnostics](../../spec/App/UI/Diagnostics.md#診断と適用状態の区別)）。

RTCを開くと、最後の自端末音声について、LocalとInternetを矢印で分岐させる。経路の選択は `RTCNetworkDiagnostics.outboundAudioDispatch` から得る。状態は共通の記号と語で示す。

| 状態 | 表示 |
|---|---|
| 経路へ渡した | Passingの記号と `Offered to transport` |
| 近距離でカバーしてInternetを省略 | InternetにIdleの記号と `Covered by Local` |
| 最後の音声で使わなかった | Idleの記号と `Not used for last packet` |
| 記録がない・15秒を超えた | Idleと `No audio dispatch observed`／`Last dispatch is stale` |

Internetの行には `Send queue` を併記する。相手への到着は `Peer receipt: Not measured` と示す。観測した受信経路と中継先はNetworkのPathsで確認する。

### RX（Live RX Pipeline）

全体の段で、`RTC RX`は経路と受信・破棄数を示す。`Decode`は現在の受信グラフでPCMが得られたpacket数を `PCM n`、失敗数を `Decode errors n` として表示する。PCMも失敗も未観測なら `No PCM observed`。再生予約と実出力は後の段を読む。

相手ごとの条件がばらばらなまま届き、相手ごとのPeer Busで自分側の設定が掛かり、`Mix Down`で1つに合流する流れを入れ子の木で描く。`rx-master`への経路がある相手から左の縦線へ枝を伸ばし、`Mix Down`で合流させる。合流点で線を終え、`3 routes → rx-master`のように実際の経路数を示す。経路がない相手は木の上に並べる。

相手ごとの開閉見出しに名前と状態を示す。経路がある相手は、その入力でPCMの再生予約を観測すると`Passing`、それまでは`Waiting`とし、共通の状態記号と語を添える。開くと段名付きの内訳を表示する。

| 行（表示名） | 内容 | 入力 |
|---|---|---|
| Sender | 相手の端末で掛かっている送信条件。codecと形式・bitrate（fallbackなら要求→実際と`Fallback`、低帯域は`Lower Quality`）、相手のマイク（`Unmuted`／`Muted`）、相手のVAD（`Speech`／`Silence`）、相手のTXのSoundIsolation。15秒を超えた値は経過秒を付けて薄くする | `remoteRuntimeStatuses[peer]`の`localMute`・`audioPolicy`・`packageReports`（Codec・VADGate・SoundIsolation）、`generatedAt` |
| RTC RX | `Connected`／`Connecting`／`Offline`と`authenticated`。届いた経路（直接・中継・Internet）。別の経路が使えない場合はその旨（例: `Local unavailable`） | `connectionState`、`authenticationState`、`RTCNetworkDiagnostics`の相手ごとの経路 |
| Decode | 参加者の受信codec | `activeCodec` |
| Peer Bus | 自分側の設定。Volume（%）、SoundIsolation（`AudioEffectStageRuntimeState`の値。例: `active`／`bypassed`／`unavailable`）、Jitter buffer（ms）、レベルメーター | peer volume、`receivePeerEffectChainSnapshot`、`queuedAudioFrameCount`、`voiceLevel` |

経路がない相手の状態は接続状態に応じて`Offline`または`No mixer route`と示す。Offlineの相手は詳細も`Offline`と表示する。

合流後の段は、`Mix Down`の下に縦に並べる。アクセシビリティ文字サイズではRX Masterのメーターを集計の下に置き、Master FXを1列にする。

| 段（表示名） | 主な値 |
|---|---|
| Mix Down | 合流するroute数 → `rx-master`（`AudioMixerSnapshot.routes` の `rx-peer-*` → `rx-master`） |
| RX Master | `rx-master`、入力数、OUT（%）。100%超は`Boost`。frames/s |
| Master FX | 入れ子で、`rx-master.effectChain`＋`rx-output.effectChain`の順（現在は`SoundIsolation → Master fader → PeakLimiter`）。PeakLimiterは`rx-output`を併記 |
| Output | 機器名（`currentOutput`）と実形式、Buffered（`bufferedOutputDuration`）、resets（`playbackResetCount`）、出力レベル。Apple Watch選択中は`Apple Watch`とし、iPhoneの出力が消音であることを併記 |

上流が止まっている相手のブロックは、止まった行を強調し、それより下の行を`Idle`として薄くする。下流の0を故障として見せない。

### Network

経路（Local・Internet）ごとにカードを分け、`networkDiagnosticsSummary`の1つの長文を廃止する。

| 項目（表示名） | 内容 |
|---|---|
| RTT | ICE接続のRTT（ms）。取得できない場合は`Not available` |
| Loss | `RouteMetrics.packetLoss`・`jitter`。未取得は`Not available`とし、0%として扱わない |
| Send queue | DataChannelの送信待ち（B／KB） |
| Event drops | session・route・engine・transportごとのoverflow・expired |
| Paths | 相手ごとに`Direct group path`／`Relayed`と短縮IDの経路 |
| Updated | 生成からの経過秒。15秒を超えたら古い値として薄くする |

カードの下に現行の注記をそのまま置く（`RTT measures this device's ICE connection, not audio delay. Event drops occur inside this device. Paths show the last authenticated reception, not guaranteed reachability.`）。

### Applied

| 項目（表示名） | Requested → Applied | 入力 |
|---|---|---|
| Codec | 設定のcodec・sample rate・bitrate → 実際の符号化設定 | `CodecRuntimeReport.requestedConfiguration`／`activeConfiguration`、`isFallback` |
| Session | `Burst mode`／`Stream mode`、Use Speaker、Echo Cancellation → 実効のcategory・mode・options | `AudioSessionConfigurationReport.requestedConfiguration`／`resolvedConfiguration` |
| IO buffer・Sample rate | 要求値 → 実効値 | 同上 |
| `unsupportedSettings` | OSが適用しなかった設定の一覧 | `unsupportedSettings`、`unsupportedInputVoiceProcessingSettings` |
| Ducking | Duck Other Audioの設定 → 今作動しているか | `isDuckOthersEnabled`、`isOtherAudioDuckingActive` |
| Isolation | Transmit・Master・相手ごとの設定 → 実ノードの`AudioEffectStageRuntimeState`の値 | effect stage snapshot |
| VAD | VAD Sensitivity → 実際のThreshold・Noise floor | `VADGateRuntimeSnapshot` |
| Devices | 選択した機器（`Auto`など）→ 実際の機器 | `selectedInputPort`、`AudioSessionSnapshot.currentInput`／`currentOutput` |

RequestedとAppliedが異なる行だけ`exclamationmark.triangle`と`Differs`を付ける。非対応による差は`unsupportedSettings`に含まれる値として示し、故障として扱わない。

AppliedにはCall（State・Group・Members・Invite）と、現行の`Internet Service`（状態の文・`Check Internet Service`・現行の注記）も置く。

### Copy Diagnostics（追加候補）

画面の内容を、秘密を含まないテキストとして書き出す`Copy Diagnostics`を候補とする。group secret・招待token・端末資格・音声payload・Apple識別子は含めない（[ログ記録規約](../../policies/ログ記録規約.md)と同じ禁止情報）。採否は未決事項とする。

### 毎秒値と更新

| 項目 | 方針 |
|---|---|
| 更新周期 | 現行どおり表示中0.5秒、非表示5秒、開いた時点で即時 |
| 毎秒値の計算 | 直前のsnapshotとの差分÷経過時間。差分の保持は`DiagnosticsInput`を作る側（表示中のtick）に置き、Presentationは純粋関数のまま保つ |
| 表示の安定 | 等幅数字を使い、桁が変わっても列幅を揺らさない |
| 停止の検出 | 通話中に毎秒値が0の段は、累計が増えていても今は流れていないと表示する |

| 値 | 所有 | 状態 |

| `resolvedConfiguration`・`unsupportedSettings` | `AudioSessionConfigurationReport` | ViewModelにある（`lastAudioSessionConfigurationReport`） |
| `bufferedOutputDuration`・`playbackResetCount` | `AudioStreamSnapshot` | 出力のoperation reportにある |

## 詳細表示の通話画面

通話は相手が1人でも内部ではグループ（`IntercomGroup.kind == .direct`）である。詳細表示ではこの実体を隠さず、1対1でもグループ通話と同じ構成で表示する。操作の流れは[操作の流れ](../操作の流れ.md)に従う（StandardとAdvancedで共通）。Users・Groupsで選ぶと接続を始めてCallへ移り、グループ通話ではCallからそのまま人を追加できる。グループの一覧・作成と保存の復旧はGroupsタブに置き、Callには置かない。現行の通話画面（`callStatusHeader`・`call-primary-controls`・`call-participants-section`）の語を保ち、4つのまとまりを上から順に置く。

| 順序 | まとまり（表示名） | 内容 | 現行の語 |
|---|---|---|---|
| 1 | Call status | `callPresenceLabel`（例: `Connected`）、`routeLabel`、connected・authenticatedの人数。Group行に種類（`Group`／`Direct`）・メンバー数・短縮グループID。操作は`Disconnect`（切断後は`Connect`）。設定と招待の入口は通話ツールバーの`More`（…） | `Connect`、`Disconnect`、`More` |
| 2 | Input | `Unmuted`／`Muted`、VADの判定と感度、入力メーターにNoise floorとThresholdの目盛、ミュートの切替（`mic.slash`）、`Transmit Voice Isolation Effect` | `Input`、`Unmuted`、`Muted` |
| 3 | Output | `Output {n}%`のスライダー（100%に目盛、超過は`Boost`）、`Voice Isolation`（マスター）、出力ミュート、`Duck Other Audio`の作動状態 | `Output`、`Output Volume`、`Voice Isolation` |
| 4 | Participants | 自分（local member）を先頭に含め、`You + n`と数える。相手は1人1行で、名前、`Connected`／`Offline`と`authenticated`（文字）、codec、受信メーター（実装の`VoiceMeterView`に`voiceLevel`のバーと`voicePeakLevel`の印、値の文`LEVEL n  PEAK n`。相手がミュート中は`MUTED`。値の文を隠さない。接続していない相手には出さない）、個別音量、Voice Isolation。行からDiagnosticsのRXの該当ブロックへ移動。用途別の許可（`canNotify`）がある`Offline`のメンバーの行末に`Send Call Request`（押すと1回送る。グループの呼び出しの実装後）。送った後の取消・結果・期限は出さない（呼びっぱなし。[通知の設計](../通知の設計.md#通知は親切な知らせ2026-11-10の利用者判断)）。相手が来るまでの行は`Offline`のまま | `Participants`、`No remote riders`、`Send Call Request` |

Callに置かないもの:

| 操作 | 置き場所 |
|---|---|
| グループの一覧・作成（`New Group`）・保存の復旧（`Reload Saved Groups`等） | Groupsタブ |
| 保存ユーザーの一覧とグループを指定しない個人招待 | Usersタブ |

Call statusのGroup行には種類（`Group`／`Direct`）を表示し、メンバーの接続・認証には文字（例: `Connected · authenticated`）を添える。

| 通話の種類 | `More`（…、`callMoreMenu`）の項目 |
|---|---|
| Group | `Group Settings`、`Add Saved Users`、共有可能な場合は`Invite`。`Add Saved Users`から保存済みの相手の選択と新しい相手の名前入力を同じ画面で行う。利用権がない場合は通話とGroup Settingsの追加操作を出さない。メンバーが上限の場合は無効にする。入力中に利用権が切れたときは入力を保ち、利用権の確認を案内する |
| Direct | `User Settings`、共有可能な場合は`Share Call Invite`。相手が保存されていない場合は`User Settings`を無効にする |

保存・共有・返信の状態は[通話画面の仕様](../../spec/App/UI/Call.md#新しい相手へのグループ招待)と[招待の設計と状態遷移](../招待と登録の設計.md#新しい相手のグループ招待の状態遷移)に従う。

## 詳細表示のUsersとGroups

並びは実装のデータの構造に合わせる（Usersは未登録の名前も含む`directoryUsers`、対応する`ContactInvitationRecord`はその人の詳細内。Groupsは`IntercomGroup.kind`ごと）。一覧の並びと表示の部品は実装との対応を基に定める。Standardと表示・語・配置・操作が完全に同一の部品（行のスワイプ・削除確認）はCommonで共有し、違いのある部品は分ける。データと操作は共通のViewModel・共通操作を使い、画面ごとの台帳を持たない。

| 画面 | 行に出す内容 | その他 |
|---|---|---|
| Users | 行の左に`directoryUsers`の呼び名、行から開始する個別通話の短縮ID・端末数、識別済みの本人名を上から並べる。相手との個別通話が進行中の場合は行の右に状態を出す。解決先が未保存のときは`No direct group yet`。未登録は`memberIDs [] · principal nil` | 通話中は先頭のCurrent Callに今の相手名またはグループ名を表示する。未登録の行からSavedUserの`id`・`displayName`・`localName`・`memberIDs`・`principal`を開き、配送記録を内包する。登録時は同じ詳細を保つ。記録のreceivedBySharingと、hasExpired(at:)の派生値をそのまま表示し、canShareContactReply成立時にShare Accepted Receipt／Share Acknowledgementをexportへ接続する。相手の設定にも配送記録と同じ操作を出す。`Share Call Invite`は行の通話先が共有可能なときに出し、表示中の短縮IDと同じ通話を共有する。未紐付けの旧記録だけInvitationsへ残す。操作はShare Invitation、Retry Notification、Cancel Pending Invitation／Stop Retrying Notificationを実装の条件で表示。取消後も保存済みの人を保持する。詳細・設定の`SavedUser name state`には`usesProvisionalName`と`needsNameConfirmation`、条件成立時の`Use Shared Name`／`Keep Local Name`を表示する（[呼び名の確認](../../spec/App/UI/Call.md#登録後の呼び名の確認)）。選択後も同じ画面を保ち、設定の文字入力と保存済みの値を揃える |
| Groups | グループ名、メンバー数、鍵の状態（`key ready`／`key missing`）、短縮グループID、通話中 | `New Group`（利用権があるときに作成できる。グループ名は共通の`MemberSelection`が生成した`Group ABC123`を入力した状態で開く。日本語の共通操作では「グループ ABC123」。6文字コードの生成と保存済み名の一致回避、手入力・メンバー選択時の保持はStandardと同じ。空で確定するとその画面の生成名を使う）、`Reload Saved Groups`などの保存の復旧操作。1対1のための内部のdirectグループは別Section`Direct Groups`に、種類`Direct`・相手の名前・短縮グループIDで並べる。`Group Settings`ではメンバーを読み取り専用にし、`Add Saved Users`とメンバーの削除を出さない（[バックログ](../../backlog/未実装課題.md#個人招待の仕上げ)の個人通話の内部モデル）。通常グループ行のswipeは共通の`destinationRowActions`で`Group Settings`と、`canEditSavedGroups && groupRepository.ownsGroup(group.id)`のときだけ`Delete`を出す。`Group Settings`でメンバー一覧・名前・`Add Saved Users`・メンバーの削除と名前の編集・招待・削除を開く。メンバーの行の `Edit Name` は利用権にかかわらず出す。`Remove` は利用権があるときだけ出し、確定時も共通判定を使う。確認中に期限が切れたときはメンバーと設定画面を保ち、利用権の確認を案内する。保存成功後は受信箱に残る招待の取消を開始する。受取確定より先に取り消した招待は、相手が取得を始めていても一覧に追加されない。送信が遅れても、先に反映された取消を保つ。この端末では外した人の音声を停止し、再接続で一覧に戻さない。他端末への除外反映は削除同期の対象。退出前に使った通常グループURLを開くと、新しい招待を依頼するよう案内し、現在の通話を保つ。取り消し処理が残る間だけ配送欄で `cancelled` を確認でき、設定を閉じても処理は続く。最後の操作と確認は両モード共通の`GroupRemovalSection`で、オーナーは`Delete Group`、招待から入ったメンバーは`Leave Group`。いずれも記号なしの赤い文字。`groupRepository.ownsGroup`と`canEditSavedGroups`に対応し、確認のタイトルはグループ名を含む。接続中は`Disconnect and Delete`／`Disconnect and Leave`と切断の本文、未接続なら`Delete`／`Leave`を出し、取消で保存と通話を保つ（Callのツールバーの設定のボタンからも同じ画面。長押しのメニューは置かない）。行のタップは未接続なら接続を始めてCallへ、会話中は今の通話を開くだけ（切替も確認もしない） |

### 作成・追加のユーザー選択

`AdvancedSavedUsersSelection`は`Saved Users`の名前をタップして選び、選択中だけ行末に`checkmark`を出す（`selectUser-{UUID}`、VoiceOverは選択状態）。Toggle・行の編集・削除・説明のfooterは置かない。Formの別Sectionに「{n} of 8 members including you」とエラーを出し、ツールバーに`Cancel`と、作成は`Create and Connect`（別通話中は`Create Group`）、追加は`Add Users`を置く。新規作成だけ生成名を入力済みの名前欄を出す。データと保存は共通の`MemberSelection`、追加後の共有も共通とし、Standardとの表示・語・配置の差は[現行Call仕様](../../spec/App/UI/Call.md#保存済みユーザーの操作)で対照する。

## グループ招待の保存後

新しい相手へのgroup招待では、AdvancedSavedUsersSelectionのNew PeopleにMemberSelection.newPeopleの入力、Saved UsersにavailableUsersの選択を分ける。入力部品NewGroupInvitees・保存・共有は同じ契約を使う。保存後の人物詳細はSavedUserとContactInvitationRecordのinvitedGroupID・sent・state・canResumeに対応し、グループ設定の予約枠からも同じ人物詳細を開く。表示のためのtoken／鍵の読出しは行わない。登録済みの相手にはAdvancedRegisteredGroupInvitationsでGroupDeliveryRecordのid・recipientMemberID・state・expiresAt・credentialReferenceを実値で表示する。項目名と値は横に並べ、長い値が収まらない場合は値を次の行に送り、IDの全体を読めるように折り返す。保存直後はpending、server受付はqueued、相手保存の確認はreceived。`Invite`で任意に共有でき、Doneまで同じ画面に留まる。

AdvancedGroupInvitationSavedViewの見出しはInvitation（招待）。IntercomGroupのid／nameを常に表示する。SavedUserは名前にisRegisteredとidを添え、同じ人物の詳細を開く。確認済み相手へのGroupDeliveryRecordは既存の記録表示を使い、旧形式で記録がなくても`Invite`で任意に共有できる。Standardの案内文を流用せず、Doneは親のsheet終了操作を呼ぶ。

Group SettingsのMembersで、新しい相手の名前に対象groupの `ContactInvitationRecord` の `direction`・`state`・`sent` とISO 8601の `expiresAt` を添える。その行から同じ人物詳細を開く。共有取消で同じ値を保ち、OSの共有完了で `sent` を更新する。署名付き返信で同じ枠が通常メンバーになり、招待の値は表示から外れる。[Group SettingsのHTML見本](詳細画面見本.html#group-settings)と対応する。

登録済み相手のoutgoing GroupDeliveryRecordはAdvancedGroupDeliveryRecordsで表示する。保存画面と同じ実フィールドを再利用し、宛先のないグループの共有は設定の`Invite`から開く。receivedは相手の受取が受信箱で確定した状態。同じグループに同じ人を招待し直すと、前回のreceivedは配送欄から消え、新しい配送がpendingから進む。受取側の一覧反映は確定後に行われる。保存済みのグループと鍵が食い違う招待や、そのグループで外した相手から届いた招待は破棄し、次の受信箱の項目へ進む。受領の応答を待つ間に競合や除外が起きても、受取側のグループと通話を保つ。表示用の配送状態は保存しない。
